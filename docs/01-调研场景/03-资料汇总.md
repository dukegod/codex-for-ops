# 资料汇总

> 把散落在飞书文档、邮件、微信、本地文件夹的资料统一喂给 Codex，1 小时内生成周报/月报初稿。

## 🎬 场景故事

小赵是用户运营组的，每周五下午是他最痛苦的时间——**写周报**。

他的周报需要汇总这些来源：

- 飞书文档里的 3 个项目进展文档
- 邮件附件里的 2 份数据周报（Excel）
- 微信群里客户经理发的截图（用户反馈、活动数据）
- 本地文件夹里的 1 份上周活动复盘 PDF

以前他**周五下午 + 晚上**才能写完，总是被同事催。用了 Codex 后：**周五下午 2 小时搞定，周五晚上正常下班陪家人**。

这章教你怎么复制他的做法。

## 🎯 你将学到

- 把分散资料统一收进一个文件夹的「资料归集法」
- 用 Codex 按时间线 / 主题 / 项目三种维度生成汇总
- 让 Codex 自动套用周报/月报/项目复盘的固定模板

**预计耗时**：资料归集 30 分钟，Codex 跑 15-30 分钟，人工润色 30 分钟。

## 📋 前置准备

- Codex 桌面端已登录
- 一个本地文件夹，按「周/月/项目」命名，例如 `周报-2026W26`：

```
~/Desktop/周报-2026W26/
├── 本周项目进展/
│   ├── 新用户拉新项目.md
│   ├── 618活动执行.md
│   └── VIP用户召回.md
├── 数据周报/
│   ├── 2026-06-23-DAU数据.xlsx
│   ├── 2026-06-24-转化漏斗.xlsx
│   └── 2026-06-25-渠道投放.xlsx
├── 客户反馈/
│   ├── 微信-客户经理反馈合集.md
│   ├── 客服工单摘要.md
│   └── 小红书-用户讨论截取.md
├── 团队协作/
│   ├── 与产品组周会纪要.md
│   └── 与销售组对接邮件.eml
└── README.md  ← 写一句本周主题
```

> 💡 **小贴士**：在 `README.md` 里写一句本周核心主题，方便 Codex 判断重点。比如：

```
# 2026 W26 周报

本周重点：618 活动收尾 + 新用户拉新项目启动。
下周重点：618 数据复盘 + VIP 召回二次触达。
```

## 🚀 操作步骤

### Step 1：资料归集（最关键的一步）

把分散在各处的资料**统一导出/复制**到上面那个文件夹：

- **飞书文档** → 右上角「···」→「导出为 Markdown」，存到对应子文件夹
- **邮件附件** → 直接拖到文件夹（.xlsx、.docx、.pdf 都能处理）
- **微信聊天截图** → 长按图片→「保存到电脑」，再 OCR 成文字（macOS 自带预览工具或微信 PC 版的「提取文字」功能）
- **Excel** → 直接保存 .xlsx 进文件夹即可，Codex 能读

> 👀 **这里你会看到**：Codex 主界面顶部的文件夹图标 🗂️。点击它选中 `周报-2026W26/` 整个文件夹。

### Step 2：先跑资料清单盘点

不要急着让 Codex 写周报。先让它列出它读到了什么：

```
请列出你已经读到的所有文件（按子文件夹归类），并对每个文件用一句话说清「这份资料讲了什么」。
```

这一步有两个作用：
1. **确认 Codex 真的读到所有文件**（有时候权限或路径问题会漏）
2. **让你心里有数**：万一某个文件没读到，现在补还来得及

### Step 3：跑「分类汇总」

用模板 1 让 Codex 按主题把本周的事情归类汇总。

### Step 4：跑「套模板出周报」

把 Step 3 的输出复制给 Codex，用模板 2 让它套周报模板。

### Step 5：人工润色

Codex 出的初稿肯定要改，但**至少省了你「搭骨架 + 找数据」的时间**，把最累的活省下来。

## 📝 完整 Prompt 模板

### 模板 1：分类汇总（信息提取）

**适用场景**：所有资料归集后，先让 Codex 把零散信息按主题分类。

**完整 prompt**：

```
请阅读文件夹里的所有资料，输出一份「本周信息汇总」。

【分类维度】
按下面 5 个主题分类，每个主题下用 bullet 列要点：
1. 项目进展（本周完成了什么、在推进什么、卡在哪）
2. 数据表现（DAU、转化、留存、GMV 这类关键数字，标注同比环比）
3. 用户反馈（正面、负面、典型案例各 1-2 条）
4. 跨部门协作（与产品/销售/市场的对接进展）
5. 风险与问题（本周发现的问题、没解决的、需要领导协调的）

【每个 bullet 的格式】
- 一句话说清事件
- 数据/数字用括号附在后面
- 来源用【xxx.md】标注

【特别注意】
- 同一事件出现在多个文件里（比如邮件和飞书文档都提了），合并成一条
- 数据冲突时（比如 Excel 和 md 给的数字不一样），按 Excel 优先，并注明冲突
- 不要补充资料里没有的内容
```

**预期输出**：5 个主题分类，每类 3-8 条 bullet，可直接喂给模板 2。

**调优提示**：
- 信息太多 → 在 prompt 里加「每个主题最多保留 5 条最关键的」
- 信息太少 → 加「如果某个主题资料很少，至少列 1 条；如果完全没有，写『本周无相关内容』」

### 模板 2：周报模板生成

**适用场景**：用模板 1 的输出作为输入，让 Codex 套标准周报模板。

**完整 prompt**：

```
下面是本周信息汇总（我手动整理过）：

[粘贴模板 1 的输出]

请基于以上内容，按公司周报标准模板生成周报初稿。

【标准模板（严格按这个结构）】
# [姓名] 第 X 周周报
## 📊 本周核心数据（用数字说话，3-5 个关键指标 + 环比）
## ✅ 本周完成事项（3-5 条，按重要性排序）
## 🚀 下周计划（3-5 条，要具体到「做什么 + 预期产出」）
## ⚠️ 风险与需要支持（最多 3 条，每条说清「问题 + 影响 + 需要谁支持」）
## 💡 思考与建议（最多 2 条，给老板看的洞察，不要写套话）

【写作要求】
- 每个 bullet 用动词开头（完成了/推进了/发现/计划/需要）
- 数据要具体（「DAU 12.3 万，环比 +5%」别写「DAU 有所增长」）
- 不要写「赋能」「抓手」「闭环」
- 「下周计划」要可验证（「完成 X 上线」不要写「推进 X」）

【输出】
不要写前言、不要写总结，直接输出 5 个章节的标题和内容。
```

**预期输出**：可直接复制到飞书文档的周报初稿。

### 模板 3：月报 / 项目复盘

**适用场景**：月度总结、项目结项复盘。

**完整 prompt（月报版）**：

```
请基于文件夹里 4 周的周报内容（[本周]/[上周]/[上上周]/[上上上周] 4 个 md 文件），生成 5 月份的月报初稿。

【月报结构】
1. 月度核心数据（4 周趋势，最好用文字描述「逐周上升/先降后升」+ 关键节点）
2. 月度里程碑（完成了哪些重要事件，3-5 个）
3. 项目进展总览（每个进行中的项目当前状态、下月计划）
4. 数据表现分析（关键指标月度变化 + 解读）
5. 经验与教训（本月踩的坑、沉淀的方法论各 2 条）
6. 下月战略重点（3 条，每条说「做什么 + 为什么 + 预期结果」）

【特别注意】
- 月报比周报更看重「趋势」和「归因」，不要简单堆数据
- 「经验与教训」要具体到事件，别写「重视数据」「加强沟通」
```

**项目复盘版**只需把 prompt 中的「月报」替换为「项目」，加上：

```
- 项目目标回顾（原始目标 vs 实际达成）
- 关键决策点回顾（项目过程中 3 个重要决策，当时为什么这么选、现在看对不对）
- 资源投入（人/钱/时间 vs 实际需要）
- 可复用经验（这个项目做完，下个项目能直接抄的是什么）
```

## ⚠️ 常见坑

- **坑 1：资料重复**（同一事件在邮件和飞书文档里都说了一遍） → 解决：用模板 1 的「合并同类项」要求。Codex 会自动合并；如果没合并，在追问里说「请把 X 和 Y 合并成一条」。
- **坑 2：docx/pdf/md/txt 格式混着，Codex 读不到某些格式** → 解决：Codex 默认支持 PDF/MD/TXT/CSV/XLSX。`.docx` 也能读但偶发问题，遇到导出为 md 重新喂。
- **坑 3：截图全是图片读不到** → 解决：macOS 预览打开图片 → 选择文字区域复制；或者用 QQ/微信截图工具自带的「提取文字」。
- **坑 4：周报写得太抽象**（「推动了项目进展」「加强了沟通」） → 解决：模板 2 末尾加了「动词开头 + 具体可验证」要求。如果 Codex 还是抽象，在追问里贴一句「重写，所有 bullet 必须包含至少 1 个具体名词（项目名/数字/客户名）」。
- **坑 5：数据来源不可追溯**（周报里写了「DAU 12 万」但查不到出处） → 解决：模板 1 已经要求每个数据标注【来源：xxx】，模板 2 在追问时加一句「数据来源标注请保留」。
