# 会议纪要

> 把飞书妙记 / 腾讯会议 / 钉钉导出的转写稿丢给 Codex，5 分钟出结构化纪要 + 待办清单。

## 🎬 场景故事

阿芳是用户增长组的 PM（产品经理），每周至少 5 场会——产品评审、跨部门协作、用户访谈、复盘会。

以前每场会开完，她要做两件事：
1. 整理纪要发飞书群（1 小时）
2. 把会议里的 Action Item（待办事项）拆成飞书任务（30 分钟）

上周她把 Codex 用起来，**每场会只多花 5 分钟**，剩下的时间专心做产品。

她特别提到：「以前最痛苦的是散会两周后，没人记得当时谁承诺了什么。Codex 整理的纪要带『责任人 + 截止日期』，再发群时大家都不敢装没看见。」

这章教你怎么做。

## 🎯 你将学到

- 把转写稿导出（飞书妙记 / 腾讯会议 / 钉钉都支持）
- 让 Codex 输出结构化纪要（议题 / 讨论要点 / 决定 / 待办 / 责任人 / 截止时间）
- 让 Codex 自动识别「谁答应了什么 + 什么时候交」
- 把待办事项一键同步到飞书任务

**预计耗时**：导出转写稿 5 分钟，Codex 跑 5 分钟，人工核对 10 分钟。

## 📋 前置准备

- Codex 桌面端已登录
- 一场已结束会议的转写稿
- 三个常用会议工具的转写稿导出方法（任选其一）：

```
【飞书妙记】
妙记页面 → 右上角「···」→「导出」→ 选「文本(.txt)」或「Markdown(.md)」

【腾讯会议】
会议详情页 → 「会议纪要」→「导出」→ 选「带发言人」格式 → 下载到本地

【钉钉】
会议详情页 → 「智能会议」→「导出纪要」→ 下载 .txt
```

- 一个本地文件夹，结构建议：

```
~/Desktop/会议纪要-2026Q2/
├── 2026-06-20-产品评审会.md
├── 2026-06-22-跨部门协作会.md
├── 2026-06-25-用户访谈-3位.md
└── README.md
```

## 🚀 操作步骤

### Step 1：导出转写稿

按上面方法导出。**优先导出「带发言人」的格式**——Codex 需要知道谁说了什么，才能识别 Action Item 的责任人。

> 👀 **这里你会看到**：Codex 主界面顶部文件夹图标 🗂️。选中当天的会议转写稿文件即可。

### Step 2：跑模板 1 出纪要初稿

粘贴模板 1 的 prompt，让 Codex 输出结构化纪要。**5-10 分钟**得到初稿。

### Step 3：人工核对「责任人 + 截止时间」

Codex 识别 Action Item 的责任人通常很准，但**截止时间**容易猜错（很多会议里没明确说截止日）。一定要人工核对这两项。

### Step 4：（可选）把待办同步成飞书任务

如果你的飞书开放了 API（Application Programming Interface，理解为「让外部程序读写飞书数据的通道」）权限，可以用 Codex + 飞书工具自动把待办创建为飞书任务。详见 [进阶篇：自动化任务](../03-进阶技巧/02-自动化任务.md)。

### Step 5：把纪要发到群里

Codex 输出的 Markdown 纪要，可以直接粘贴到飞书消息框（飞书消息支持 Markdown 渲染），@相关责任人。

## 📝 完整 Prompt 模板

### 模板 1：结构化纪要生成

**适用场景**：单场会议的标准纪要输出。

**完整 prompt**：

```
请把下面这份会议转写稿整理成结构化纪要。

【会议基本信息】
- 会议主题：[产品评审会-2026-06-20]
- 参会人：[产品组 3 人 + 运营组 2 人 + 技术组 2 人]
- 会议时长：[1.5 小时]

【输出结构（严格按这个）】
# [会议主题]
**时间**：2026-06-20 14:00-15:30
**参会人**：姓名（角色）、姓名（角色）……
**记录人**：[谁]
**会议目标**：一句话说清这场会要解决什么问题

---

## 议题 1：[议题名]
### 讨论要点
- [要点 1，简明扼要，附原始发言关键句]
- [要点 2]
- [要点 3]

### 决定
- [最终结论，要明确，不要写「大家认为」「可能考虑」这种模糊话]

### 待办
- [ ] [责任人] [截止时间] [具体动作] [优先级 高/中/低]
- [ ] ……

---

## 议题 2：……（同上）

---

## 📋 全部待办汇总
| # | 待办内容 | 责任人 | 截止时间 | 优先级 |
|---|---------|--------|---------|--------|
| 1 | | | | |

---

## 📌 下次会议
- 时间：
- 议题：

【特别注意】
- 如果发言人说「我来」「我负责」「我下周交」，请把「我」识别为对应的人名（结合转写稿的发言人标记）
- 如果截止时间不明，写「待确认」，不要瞎猜
- 中英文混排时，保留原始术语，不要强行翻译
- 口语化严重（很多「嗯」「啊」「那个」），请直接删除这些填充词
- 转写稿里如果有错别字（语音识别错误），请根据上下文修正，并在末尾「转写稿勘误」里列出
```

**预期输出**：标准结构化会议纪要，可直接发飞书群。

**调优提示**：
- 输出太长 → 在 prompt 里加「每个议题的『讨论要点』控制在 5 条以内」
- 责任人识别错 → 加「如果转写稿标了『发言人 A』『发言人 B』，请按上下文判断谁是 A 谁是 B」
- 想再口语化一点 → 加「请把『决定』段落写成大家能直接读懂的话，不要用书面语」

### 模板 2：批量处理一周的会议

**适用场景**：周五把一周 5 场会议统一整理。

**完整 prompt**：

```
文件夹里有本周 5 场会议的转写稿：
- 2026-06-20-产品评审会.md
- 2026-06-22-跨部门协作会.md
- 2026-06-23-用户访谈.md
- 2026-06-24-数据复盘会.md
- 2026-06-25-周五全员同步会.md

请你按下面步骤处理：

【步骤 1】逐个生成结构化纪要（用模板 1 的结构）

【步骤 2】把 5 场会议的所有「待办」汇总成一张总表：
| # | 待办内容 | 责任人 | 截止时间 | 来源会议 | 优先级 |
|---|---------|--------|---------|---------|--------|

【步骤 3】识别跨会议的主题（同一件事在多个会议被讨论），比如「VIP 召回策略」在产品评审、跨部门协作、周五全员会都提到了，请单独成段总结

【步骤 4】生成本周会议洞察（200 字）：
- 本周讨论最集中的 3 个主题
- 出现最多的 Action Item 类型（比如很多都是「数据分析」类）
- 需要领导关注/协调的 1-2 件事
```

**预期输出**：5 份独立纪要 + 1 张待办总表 + 1 段洞察。

### 模板 3：口语清理（转写稿质量差时用）

**适用场景**：转写稿错字多、口语化严重、说话人混杂。

**完整 prompt**：

```
这份会议转写稿质量很差（语音识别问题 + 多人讨论混杂），请先做「清理」，再做纪要。

【清理任务】
1. 删除所有填充词：「嗯」「啊」「那个」「就是说」「然后」「对」之类的
2. 删除重复发言（同一件事被不同人说了 N 遍，只保留最完整的那段）
3. 合并同一说话人的连续发言（一段话说完了被打断又继续）
4. 修正明显的语音识别错误（根据上下文判断，比如「支付宝」→「支付宝」，「那个」→「那个」），不确定的保留原文
5. 中英文混排保持原样

【清理后再做】
按模板 1 的结构生成纪要。

【特别输出】
在纪要末尾加一段「转写稿勘误」，列出 10 个最严重的修正：
- 原文：「xxx」 → 修正：「xxx」（理由：xxx）
```

**预期输出**：清理后的纪要 + 勘误清单。

## ⚠️ 常见坑

- **坑 1：转写稿没标发言人** → 解决：导回飞书妙记或腾讯会议重新导出，**必须勾选「带发言人」**。没有发言人就没法识别 Action Item 责任人。
- **坑 2：Codex 把所有人说成「大家」**（失去了具体责任人） → 解决：prompt 里强调「如果发言人说『我来做』『我负责』，必须识别为具体人名」。
- **坑 3：截止时间瞎猜**（明明没说，Codex 写「本周内」） → 解决：prompt 里明确「截止时间不明写『待确认』，不要瞎填」。出稿后人工核对所有日期。
- **坑 4：多人发言混杂，口语化严重** → 解决：用模板 3 的清理步骤，先清后整理。
- **坑 5：中英文混排把人名翻乱了**（「Tony」变成「托尼」「张 sir」变成「张先生」） → 解决：prompt 里加「人名、专有名词保留原文，不要翻译」。
- **坑 6：纪要发出去后没人接 Action Item** → 解决：发飞书时 @每个责任人，并把待办同步成飞书任务（需要飞书 API 权限）。
