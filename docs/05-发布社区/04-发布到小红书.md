# 4. 发布到小红书：从本地 Skill 到小红书笔记

> 配置 xiaohongshu-mcp + 用 Codex 一键发布

## 🎬 场景故事

小陈把 Skill 做好了，本地测试 3 个同事都跑通了。**接下来要把 Skill 发布到小红书，让更多人能用上**。

她面临两个选择：

**A. 手动发布**（最简单）：
- 把 SKILL.md 内容复制到小红书笔记
- 配上图，写好文案
- 自己点发布
- ❌ 不能挂载 RED Skill 组件（用户没法一键装）

**B. 自动发布**（推荐）：
- 用 xiaohongshu-mcp 让 AI 帮你发布
- ✅ 可以挂载 RED Skill 组件
- ✅ 可以批量、可以定时
- ✅ 一次性配置，长期受益

**这章讲 B 方案**。

## 📋 xiaohongshu-mcp 是什么

**GitHub**：[xpzouying/xiaohongshu-mcp](https://github.com/xpzouying/xiaohongshu-mcp)（开源、1k+ stars）

**它干嘛的**：

通过 MCP 协议（Model Context Protocol），让 AI 助手（Codex / Claude / Cursor 等）能直接操作小红书：

| 功能 | 说明 |
|------|------|
| 📝 **发布图文** | 标题 + 正文 + 图片 + 标签 |
| 🎬 **发布视频** | 本地视频 + 标题 + 描述 |
| 🔍 **搜索内容** | 按关键词搜索笔记 |
| 📊 **数据获取** | 帖子详情、评论、互动数据 |
| 💬 **评论管理** | 发表评论、回复评论 |
| 👤 **用户主页** | 查粉丝、查关注 |

**对运营的价值**：

```
之前：手动写 → 手动配图 → 手动复制到小红书 → 手动点发布（30 分钟/篇）
现在：用 Codex 一句话让 AI 帮你发（30 秒/篇）
```

## ⚠️ 发布前必读：风险与合规

### 🚨 风险提示

**用 xiaohongshu-mcp 发布小红书存在一定风险**：

1. **账号封禁风险**
   - 小红书官方对自动化操作有检测机制
   - 高频发布、重复内容、IP 异常都可能触发风控
   - **建议**：初期每天最多 1-2 篇，控制频率

2. **数据安全风险**
   - MCP 需要保存你的小红书登录 Cookie
   - Cookie 等同于账号密码，泄露 = 账号被盗
   - **建议**：不要在公用电脑用；定期清理 Cookie 重新登录

3. **合规风险**
   - 自动发布的内容仍需遵守小红书社区规范
   - AI 生成内容要明确标注（小红书 2026 年起要求）
   - **建议**：保留人工审核环节，不要 100% 自动

### 📜 合规要求

按小红书 2026 年新规：

- [ ] AI 生成内容必须明确标注「AI 生成」或「AI 辅助」
- [ ] 不得伪造数据、伪造体验
- [ ] 不得使用极限词（「最佳」「第一」「唯一」）
- [ ] 不得诱导互动（「点赞过 1000 更新下一期」）
- [ ] 商业合作需走蒲公英平台报备

## 🚀 安装 xiaohongshu-mcp

### Step 1：环境准备

**macOS 用户**：

```bash
# 1. 装 Go（如果还没装）
brew install go

# 2. 装 Chrome（自动登录用）
brew install --cask google-chrome

# 3. 验证
go version
```

**Windows 用户**：

1. 下载安装 [Go](https://go.dev/dl/)（1.20+）
2. 安装 [Chrome 浏览器](https://www.google.com/chrome/)
3. 打开 PowerShell 验证：`go version`

**Linux 用户**：

```bash
# Ubuntu/Debian
sudo apt update
sudo apt install golang-go chromium-browser
```

### Step 2：下载 xiaohongshu-mcp

```bash
# 进入你想放工具的目录
cd ~/tools/

# 克隆仓库
git clone https://github.com/xpzouying/xiaohongshu-mcp.git

# 进入项目
cd xiaohongshu-mcp

# 编译
go build -o xiaohongshu-mcp .
```

**编译成功后**，当前目录会有一个可执行文件。

### Step 3：第一次登录

```bash
# 启动登录工具（会弹出二维码让你扫码）
./xiaohongshu-login
```

**操作步骤**：
1. 命令会启动一个 Chrome 浏览器
2. 自动打开小红书登录页
3. 用**手机小红书 App 扫码**登录
4. 登录成功后，关闭浏览器窗口
5. 工具会自动保存 Cookie 到本地

**Cookie 保存位置**：`~/.xiaohongshu-mcp/cookies.json`（**绝对不要分享给别人**）

### Step 4：启动 MCP 服务

```bash
# 默认端口 18060
./xiaohongshu-mcp

# 自定义端口（可选）
./xiaohongshu-mcp --port 8888
```

**成功标志**：终端显示类似这样的输出：

```
2026/06/30 15:00:00 Starting xiaohongshu-mcp server...
2026/06/30 15:00:00 MCP endpoint: http://localhost:18060/mcp
2026/06/30 15:00:00 Health check: http://localhost:18060/health
```

**保持这个终端窗口开着**（或后台运行）。

## ⚙️ 在 Codex 里配置 xiaohongshu-mcp

### Step 1：打开 Codex 配置

1. 打开 Codex 桌面端
2. 右上角 ⚙ → **MCP Servers**
3. 点 **Add MCP Server**

### Step 2：填写配置

```
┌─────────────────────────────────────────────────┐
│  Add MCP Server                                 │
├─────────────────────────────────────────────────┤
│                                                 │
│  Name:                                          │
│  [xiaohongshu                                ] │
│                                                 │
│  Type:  [HTTP ▼]                               │
│                                                 │
│  URL:                                           │
│  [http://localhost:18060/mcp                 ] │
│                                                 │
│                              [Save]  [Cancel]  │
└─────────────────────────────────────────────────┘
```

填完点 Save。

### Step 3：测试连接

在 Codex 输入框输入：

```
列出你所有可用的工具
```

**预期结果**：Codex 会列出 xiaohongshu-mcp 提供的工具，比如：
- `xiaohongshu_publish` （发布图文）
- `xiaohongshu_publish_video` （发布视频）
- `xiaohongshu_search_feeds` （搜索内容）
- 等等

看到这些工具 = 连接成功 ✅

## 🚀 3 种发布工作流

### 工作流 1：让 Codex 帮你写 + 自动发布（推荐）

```
完整 prompt：

读取这个文件夹里 ~/Desktop/技能发布素材/weekly-report-skill/ 里的 SKILL.md，
然后：

1. 根据 Skill 的内容，写一篇小红书笔记，包含：
   - 标题（15-20 字，带 emoji）
   - 正文（300-500 字，分段清晰）
   - 3-5 个标签（#运营 #AI工具 #周报生成 之类）
   - 封面建议（描述封面图应该长什么样）

2. 写完后，自动发布到我的小红书账号：
   - 调用 xiaohongshu_publish 工具
   - 标题和正文用你刚写的内容
   - 封面图：从这个文件夹选一张最合适的 ~/Desktop/技能发布素材/cover-candidates/
   - 标签：用你刚写的标签列表
   - 注意：必须标注「AI 辅助生成」

3. 发布成功后，给我返回笔记链接
```

**Codex 会做的事**：
1. 读你的 SKILL.md
2. 基于 Skill 内容生成小红书笔记
3. 自动调用 xiaohongshu-mcp 的 publish 工具
4. 发布成功，返回链接

### 工作流 2：批量发布（系列内容）

```
完整 prompt：

帮我在下周 7 天里，每天早上 9 点自动发布一篇小红书笔记。
内容是「30 分钟搞定竞品周报」Skill 的 7 个分步教程，每天发一步。

要求：
1. 7 篇笔记的大纲：
   - Day 1：标题「为什么我用 AI 重做了周报流程」，介绍背景
   - Day 2：标题「3 步准备资料」，讲输入要求
   - Day 3：标题「完整 Prompt 长这样」，讲核心 prompt
   - Day 4：标题「常见 3 个坑」，讲注意事项
   - Day 5：标题「如何 1 键安装 Skill」，讲安装
   - Day 6：标题「真实案例展示」，讲效果
   - Day 7：标题「免费领取这个 Skill」，引导关注

2. 每天早上 9 点调用 xiaohongshu_publish 发布一篇
3. 每篇都标注「AI 辅助生成」
4. 7 篇都发完后给我汇总报告
```

**这是用 Codex + 定时任务能力**实现的内容日历。

### 工作流 3：先审后发（保守策略）

```
完整 prompt：

读取 ~/Desktop/技能发布素材/weekly-report-skill/SKILL.md，
基于内容生成一篇小红书笔记。

但是！**不要自动发布**。
先在对话里给我看：
- 标题
- 正文
- 封面图建议
- 标签
- 我点 [批准发布] 后，你才调用 xiaohongshu_publish 工具

如果有任何不合适的措辞，自动改正后再给我看。
```

**适合第一次发布**，稳妥一点。

## 📊 发布后的运营

发布只是开始，**小红书的算法推荐 + 互动运营**决定流量。

### 发布后 1 小时内做的事

- [ ] **自己评论置顶**：写一条引导评论（问大家问题）
- [ ] **回复每一条评论**：算法看「作者回复率」
- [ ] **不要秒删**：发了就别删，删帖影响权重

### 发布后 24 小时做的事

- [ ] **看数据**：曝光、点击、点赞、收藏、评论
- [ ] **对照预期**：
  - 曝光 < 100 → 标题/封面问题
  - 点击率 < 5% → 封面问题
  - 点赞率 < 1% → 内容不够好
- [ ] **复盘**：用 Codex 帮你分析「这篇为什么火/没火」

### 长期运营

- **稳定更新**：每周 2-3 篇，比每天发然后断更好
- **互相导流**：评论别人的笔记（不是硬广），让算法认识你
- **Skill 不断迭代**：根据用户反馈改进 Skill，发布新版

## 🛠️ 故障排查

### ❌ MCP 连接失败

**症状**：Codex 找不到 xiaohongshu 工具

**排查**：
1. xiaohongshu-mcp 服务是否还在运行？（看那个终端窗口）
2. 端口是否正确？默认 18060
3. URL 写对了吗？`http://localhost:18060/mcp`
4. 重启 Codex 试试

### ❌ 发布失败

**症状**：MCP 调用 publish 报错

**排查**：
1. 小红书 Cookie 是否过期？（重新跑 `./xiaohongshu-login`）
2. 标题或正文是否包含违规词？
3. 图片是否存在且格式正确？
4. 当天发布次数是否超限？

### ❌ 账号被风控

**症状**：发布后笔记搜索不到 / 账号异常

**处理**：
1. **立即停止**所有自动化操作
2. 改用小红书 App 手动发几篇正常内容
3. 等 1-2 周观察账号是否恢复
4. 恢复后降低发布频率

## 🎯 小红书发布 Skill 的合规建议

发布 Skill 类内容时：

| ✅ 应该 | ❌ 不应该 |
|--------|--------|
| 明确说明 Skill 的用途和限制 | 吹嘘「最强」「最好」 |
| 提供具体的输入要求 | 只给概念不给操作步骤 |
| 标注「AI 辅助生成」 | 假装完全人工创作 |
| 引导用户理性使用 | 暗示 Skill 能「全自动赚钱」 |
| 给出反馈渠道 | 拒绝回应用户问题 |
