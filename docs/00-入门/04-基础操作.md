# 4. 基础操作：输入任务、查看结果

> 学会这套操作流程，你能搞定 Codex 80% 的工作

## 🎬 场景故事

小赵第一次用 Codex 时手忙脚乱——他点了「New Task」、输入了一段话、然后就盯着屏幕看 Codex 怎么跑，**结果错过了 Codex 的关键提问、也没看到 Codex 自动生成的文件在哪儿**。

**这篇是「操作流程的标准 SOP」**——按这个流程走，你不会漏掉任何重要信息。

## 🎯 你将学到

- 跟 Codex 沟通的 5 个核心动作
- 怎么看懂 Codex 的输出
- 怎么改 prompt 让结果更好
- 怎么追加指令、怎么重新生成

## 🚀 完整操作流程

Codex 任务的标准流程是这 5 步：

```
┌──────────────────────────────────────────────┐
│  Step 1: 准备资料 → Step 2: 描述任务 →       │
│  Step 3: 看 Codex 跑 → Step 4: 审结果 →      │
│  Step 5: 保存/导出                            │
└──────────────────────────────────────────────┘
```

下面逐步讲。

### Step 1：准备资料（任务开始前）

**关键原则：把这次任务相关的所有资料，集中放进一个文件夹**。

举例：
- 周报 → 「`周报-2026W26`」文件夹里放所有 Excel + 文档 + 截图
- 竞品分析 → 「`竞品分析-2026Q2`」文件夹里放所有竞品 PDF + 截图
- 会议纪要 → 「`会议-2026-06-30`」文件夹里放会议转写稿

文件夹命名建议：
- ✅ 带日期：`周报-2026W26`、`竞品分析-2026Q2`
- ✅ 带项目名：`618-复盘`、`新品发布-会议`
- ❌ 别用：`新建文件夹`、`资料`、`tmp`（你自己都记不清是啥）

### 💡 补充：截图/窗口直接扔给 Codex（2026 GA 新功能）

如果你要 Codex 处理的"资料"**就在当前屏幕上**（报错窗口、微信对话、设计稿、网页）——**不用先截图存盘**。

**最快的方式**：**双击 ⌘ 键**，当前窗口的内容自动扔进 Codex 对话。

**适合的场景**：

| 场景 | 做法 |
|-----|------|
| 客户在微信甩了张截图问"这是啥意思" | 焦点在微信 → 双 ⌘ → 问 Codex |
| IDE 报错看不太懂 | 焦点在 IDE → 双 ⌘ → 问 Codex 怎么修 |
| 想让 Codex 改你看到的某个网页 | 浏览器在前台 → 双 ⌘ → 让 Codex 改 |
| 看到飞书 / 钉钉 / 邮件里一段话 | 焦点切到对应窗口 → 双 ⌘ → 让 Codex 整理 |

**为什么不替代文件夹方式**：

- 截图/抓窗口**不是结构化数据**，Codex 读不准（OCR 错、漏字段、可能把"100"读成"10O"）
- **重要数据还是走文件夹 + 文件**
- 但**临时看图、轻量提问**，双 ⌘ 比"截图 → 存盘 → 拖进文件夹 → 让 Codex 读"快 100 倍

**改键位**：Settings → Shortcuts → 搜 "Appshots"，可改成其他快捷键（Win 是 `Win + Shift + S` 等价）

**这一招只占了 2026 桌面端 5 个新功能里的第 ① 个**，完整教程 + 演示剧本看 [10. 桌面端新功能速通](10-桌面端新功能速通.md)。

### Step 2：描述任务（创建任务时）

点 `+ New Task`，选好文件夹后，**关键是把「任务描述」写清楚**。

#### 好的描述 vs 不好的描述

| ❌ 不清楚的描述 | ✅ 清楚的描述 |
|------------|-----------|
| 「做个报告」 | 「读取这个文件夹的 3 个 Excel，生成一份周报。包含本周亮点、数据回顾、问题与风险、下周计划 4 个章节。Markdown 格式。」 |
| 「分析竞品」 | 「读取这个文件夹里 3 家竞品的官方介绍（PDF），提取：产品名、目标用户、核心功能、定价策略，生成对比表（markdown 格式）。」 |
| 「整理会议纪要」 | 「读取这个文件夹里的会议转写稿（txt），生成结构化纪要：议题、讨论要点、决定事项、Action Item（含负责人和截止日期）、风险。」 |

#### 描述任务的「4 要素」模板

写任务描述时，套这个模板：

```
读取这个文件夹里的 [资料类型：Excel/PDF/txt/md 等]，
帮我做 [具体任务：分析/整理/对比/总结]。

要求：
1. [要求 1：粒度、字段、范围]
2. [要求 2：分析角度、关注点]
3. 输出格式：[markdown / 表格 / JSON / 直接生成新文件]
```

#### 3 个真实可复制的 prompt

**Prompt 1：周报生成**

```
读取这个文件夹里所有的 Excel 和文档，生成本周周报。

要求：
1. 包含 4 个章节：本周亮点、数据回顾、问题与风险、下周计划
2. 数据回顾要包含核心指标（销售额、新增用户、活跃用户、转化率）
3. 问题与风险至少列 3 条
4. Markdown 格式，直接输出，不要让我再追问
5. 如果数据里有明显的异常或趋势，请在文末加一个「数据洞察」章节
```

**Prompt 2：竞品对比**

```
读取这个文件夹里 3 家竞品的官方介绍 PDF 和新闻稿截图，
生成竞品对比分析。

要求：
1. 提取每个竞品的：产品名、目标用户、核心功能、定价、近期动态
2. 用 markdown 表格做横向对比
3. 表格后写 3 段分析：
   - 我们跟他们的差异化机会
   - 他们的产品弱点（我们可以进攻的点）
   - 潜在的合作或并购可能性
```

**Prompt 3：会议纪要**

```
读取这个会议转写稿（txt/md 格式），生成结构化纪要。

要求：
1. 顶部会议元信息：会议名、时间、参会人（如果有）
2. 按议题分段，每个议题包含：
   - 讨论要点（要点式，不要长段落）
   - 决定事项（明确"决定了什么"）
   - 待办事项（含负责人、截止日期）
3. 文末汇总所有 Action Item 的清单
4. Markdown 格式
```

更多写法可以直接看后面的具体场景：比如 [竞品分析](../01-调研场景/01-竞品分析.md)、[Excel 清洗与转换](../02-数据处理场景/01-excel清洗.md)、[表格分析](../02-数据处理场景/03-表格分析.md)。

### Step 3：看 Codex 跑（任务执行中）

任务跑起来后，**不要傻等**。Codex 跑的时候会在主对话区实时显示它在做什么。

观察这几个东西：

#### 3.1 文件读取区（左侧）

```
📁 2026-W26周报/
├─ 📄 销售数据.xlsx        [✓ 已读]
├─ 📄 用户反馈.xlsx        [✓ 已读]
├─ 📄 活动数据.csv         [⏳ 读取中]
└─ 📄 会议纪要.md          [⏳ 等待]
```

Codex 会按顺序读它需要的文件。**如果 Codex 没有读某些文件**，可能是因为：
- 你 prompt 里没提到
- 文件格式 Codex 不支持
- 文件名太奇怪，Codex 找不到

**这时候你应该停下来，补充 prompt**：

```
等等，你还没读「会议纪要.md」，那个文件里也有本周的重要讨论。
请也读一下它，然后在「本周亮点」里加上会议里提到的内容。
```

#### 3.2 Codex 思考区（右侧）

```
💬 Codex：
我先读取了销售数据.xlsx，发现本周销售额比上周下降了 12%。
我准备在「数据回顾」章节重点分析这个下降的原因。
接下来我会读用户反馈.xlsx...
```

**这段是 Codex 在自言自语——告诉你它在做什么、它在想什么**。

你可以从这段话里学到：
- Codex 理解对了吗？（如果不对，停下来纠正）
- Codex 发现什么了吗？（可能漏掉的好点子）
- Codex 跑的方向对吗？

#### 3.3 暂停 / 继续 / 追加指令

任务进行中你可以：

- **追加指令**：底部输入框直接打字
  ```
  「等下，再加一个章节叫『客户反馈 Top 5』」
  ```
- **暂停**：点 [Stop] 按钮
  ```
  「停一下，你这个方向不对，我想让你先...」
  ```
- **问问题**：
  ```
  「你刚才说销售额下降了 12%，这个数据是怎么算的？」
  ```

### Step 4：审结果（任务完成后）

任务完成后，**最重要的事是人工审核**。

#### 4.1 检查清单

每次拿到 Codex 的输出，按这个清单过一遍：

- ✅ **关键数字对吗**？销售额、用户数、百分比——自己心算一遍
- ✅ **逻辑通顺吗**？有没有前后矛盾的描述
- ✅ **有没有遗漏**？该提到的没提到
- ✅ **格式对吗**？Markdown 表格是不是 Markdown、日期格式是不是统一
- ✅ **没有幻觉**？Codex 有时会编造「某某说」「数据显示」——溯源一下

#### 4.2 怎么发现 Codex 幻觉？

Codex 偶尔会**编造内容**——比如：
- 编造一个不存在的客户名字
- 编造一个不存在的会议讨论
- 编造数据来源（「根据 XX 报告」但报告里没有）

**怎么发现**：
- 关键引用 → 找原文核实
- 关键数字 → 自己算一遍
- 模糊措辞（「一般来说」「众所周知」）→ 这种往往是 Codex 在编

**怎么应对**：
```
你刚才提到「根据 Q1 财报，营收增长 25%」——这个数据是从哪个文件里读到的？请给出具体来源。
```

#### 4.3 怎么让 Codex 重做

如果结果不满意，可以：

- **点 🔄 重新生成**：让 Codex 完全重做（结果会不一样）
- **追加指令**：
  ```
  「重新做刚才的任务，但这次请只关注销售额和用户数，其他指标不用提」
  ```
- **明确要求**：
  ```
  「你刚才的输出太长了，请压缩到 500 字以内，重点说结论」
  ```

### Step 5：保存 / 导出（任务结束）

Codex 生成的文件**默认保存在你授权的文件夹里**，跟你的原始资料放在一起。

文件命名是 Codex 自动起的，比如：
- `week26-report.md`
- `competitor-analysis.md`
- `meeting-summary.md`

如果你想自己命名：

```
把刚才生成的报告保存为「2026-W26-市场部周报.md」，放到当前文件夹根目录。
```

或者：

```
把刚才的对比表保存为 Excel，文件名「竞品对比-2026Q2.xlsx」，包含 2 个 sheet：对比表 + 分析建议。
```

## 🎯 总结：完整操作流程

```
1. 准备资料（建文件夹、归类）
     ↓
2. 创建任务（+ New Task → 选文件夹 → 写 prompt）
     ↓
3. 看 Codex 跑（看文件读取、看思考过程、随时追加指令）
     ↓
4. 审结果（核对数字、查幻觉、改 prompt 重做）
     ↓
5. 保存/导出（确认文件名、位置、格式）
```

## ⚠️ 常见操作错误

### ❌ 错误 1：文件夹里塞太多不相关的资料
**症状**：Codex 读了一堆不相关的文件，输出混乱
**解决**：每次任务建独立文件夹，只放相关资料

### ❌ 错误 2：prompt 写得太抽象
**症状**：Codex 输出泛泛而谈，没有你想要的具体内容
**解决**：用「4 要素模板」——明确说读什么、做什么、要求、格式

### ❌ 错误 3：信任 Codex 的输出
**症状**：关键数字错了、引用编造了
**解决**：**永远人工审一遍**，尤其是关键数字和引用

### ❌ 错误 4：把敏感数据喂给 Codex
**症状**：合规风险
**解决**：见 [数据安全](../04-安全红线/01-数据安全.md)

### ❌ 错误 5：期待 Codex 100% 准确
**症状**：失望、否定 Codex
**解决**：Codex 是工具，是助手，不是替代品。**用好它能省 80% 时间，但要保留 20% 人工审核**。
