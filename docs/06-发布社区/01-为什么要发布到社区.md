# 1. 为什么要发布到社区

> 把你的方法变成 Skill 发布到小红书，能得到什么

## 🎬 场景故事

小陈在市场调研岗干了 3 年，积累了一套**「30 分钟搞定竞品周报」**的方法论：
- 用 Codex 读 5 家竞品的资料
- 自动生成对比表
- 输出 markdown 格式的周报

这套方法她用得很熟，但只在团队内部用。**她想到一个问题**：
> 「这套方法论如果能让更多运营同学用上，是不是价值更大？」

但她不知道怎么**「包装」**成可以分享出去的形式。写文档太死板、贴 prompt 又太零散。

**小红书 2026 年 6 月新出了「RED Skill」功能**——创作者可以在笔记里挂载 Skill 组件，用户一键复制就能用到自己的 Agent 里。

**这就是「发布社区」这个章节要解决的问题**。

## 💎 4 个核心价值

### 价值 1：个人影响力放大

**没发布前**：方法只在小陈自己 + 团队内用，影响 10-20 人。
**发布后**：一篇小红书笔记能被几千人看到，方法论被几百人用上。

小红书的 RED Skill 功能让分享变得**一键可用**——读者点 Skill 组件就能直接装到自己的 Codex / Claude / 任何 Agent 里，**不用复制粘贴 prompt**。

### 价值 2：粉丝精准增长

小红书的 RED Skill 创作者开通条件是 **粉丝 ≥ 1000**，但反过来 Skill 也能**帮你涨粉**：

- 你发的是「运营干货 + AI 工具」，精准吸引运营/产品/数据岗的人
- 这些人在小红书是高价值粉丝（容易被品牌方看上）
- Skill 组件自带传播性（用的人多了会推荐给别人）

### 价值 3：副业/职业机会

发布 Skill 之后，可能带来：

- 🏢 **企业咨询机会**：有公司看到你的 Skill 找你做内训
- 📝 **品牌合作**：小红书的「蒲公英」平台会主动推你给品牌方
- 💼 **职业加分**：作品集里有公开发布的 Skill，比简历写「会用 AI」强 100 倍

### 价值 4：方法论持续迭代

**闭门造车** vs **公开发布**：

| 维度 | 自己用 | 发布出去 |
|------|------|---------|
| 反馈 | 自己的体感 | 几百人的反馈 |
| 迭代速度 | 慢 | 快（用户会告诉你哪里不好用） |
| 灵感 | 单打独斗 | 看到同行新玩法 |
| 内容储备 | 用完就丢 | 沉淀成「作品集」 |

整个流程分 4 步：

```

│  Step 1: 资源整合                                           │
│  ┌──────────────┐                                          │

│  │ - 历史报告    │                                          │
│  │ - prompt 草稿 │                                          │
│  │ - 经验总结    │                                          │
│  └──────────────┘                                          │
├─────────────────────────────────────────────────────────────┤
│  Step 2: 创建 Skill                                         │
│  ┌──────────────┐                                          │
│  │ 结构化方法论   │  ─── Codex 帮你 ───>  SKILL.md 文件     │
│  │              │                                          │
│  └──────────────┘                                          │
├─────────────────────────────────────────────────────────────┤
│  Step 3: 配置发布工具（xiaohongshu-mcp）                     │
│  ┌──────────────┐                                          │
│  │ SKILL.md     │  ─── 安装 + 配置 ───>  能自动发布的工具    │
│  └──────────────┘                                          │
├─────────────────────────────────────────────────────────────┤
│  Step 4: 用 Codex + MCP 发布                                 │
```

**全流程时长**：
- 首次配置：1-2 小时（装 MCP、登录小红书、调通）
- 后续每篇：30-60 分钟（含素材整理 + 写文案 + 发布）

## 👥 谁适合做这件事

### ✅ 强烈推荐做

- **小红书博主**（已经在运营账号）：用 Skill 提升内容生产力
- **运营/调研/数据岗位**：把工作经验沉淀成可分享的资产
- **AI 工具早期用户**：比别人先发布，吃第一波流量红利
- **企业内部讲师**：把内训内容顺便发出来，扩大影响

### 🤔 看情况做

- **偶尔发发小红书**：建议先做前 3 章（不发布），等想清楚再做
- **公司有合规要求**：先跟法务/合规确认能不能发（特别是涉及公司内部数据）

### ❌ 不建议做

- **小红书账号还没到 1000 粉丝**：先把账号运营起来再说
- **没有可分享的方法论**：先积累 3-6 个月的工作经验
- **完全不会用 Codex**：先看 [入门篇](../00-入门/)

## ⚠️ 发布前要确认的事

### 账号要求

- [ ] 小红书账号注册满 6 个月
- [ ] 粉丝数 ≥ 1000（开通 RED Skill 的硬性要求）
- [ ] 已完成实名认证
- [ ] 账号无违规记录
- [ ] 最近 30 天有正常发帖（避免被判定为僵尸号）

### 内容要求

- [ ] 内容原创，不抄袭
- [ ] 不涉及政治、宗教、医疗、金融等专业领域（小红书审核严格）
- [ ] 不发未公开的产品信息、内部数据
- [ ] 不发违反广告法的内容（如「最好」「第一」等极限词）

### 技术准备

- [ ] 已装好 Codex 桌面端（[安装与登录](../00-入门/02-安装与登录.md)）
- [ ] Mac（推荐）/ Windows / Linux 任意
- [ ] 稳定的网络（发布时需要连小红书）
- [ ] 约 30-60 分钟首次配置时间

## 🎯 真实案例预期

参考其他小红书创作者 + AI 工具发布者的数据：

| 维度 | 平均水平 | 做得好 |
|------|--------|--------|
| **笔记曝光** | 1000-5000 | 1 万+ |
| **点赞收藏** | 50-200 | 500+ |
| **粉丝增长** | +50/篇 | +200/篇 |
| **Skill 被装次数** | 10-50 | 100+ |

**关键变量**：
- 标题和封面图（决定打开率）
- Skill 本身的实用性（决定收藏率）
- 互动运营（决定算法推荐）
