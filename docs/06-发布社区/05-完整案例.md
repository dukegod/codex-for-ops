# 5. 完整案例：把「30 分钟竞品周报」Skill 发布到小红书

> 端到端实战：跟着做一遍就懂

## 🎬 案例背景

**小陈**在一家电商公司做竞品分析岗。她有一套成熟方法：用 Codex 读竞品资料、生成结构化周报，每周能省 3-4 小时。

她想把方法分享到小红书，让更多运营同学用上。**这是她从 0 到发布的完整过程**。

## 🎯 你将学到

- 完整的 4 阶段流程（每阶段多少时间）
- 真实的 prompt 模板（直接抄）
- 小陈发布后的数据和复盘

## 📋 时间总览

| 阶段 | 内容 | 耗时 |
|------|------|------|
| 阶段 1 | 资源整合 | 60 分钟 |
| 阶段 2 | 创建 Skill | 60 分钟 |
| 阶段 3 | 配置 xiaohongshu-mcp | 60 分钟 |
| 阶段 4 | 发布 + 运营 | 30-60 分钟 |
| **总计** | — | **3.5-4 小时**（首次） |

后续每篇新 Skill 发布：**1-2 小时**。

## 阶段 1：资源整合（60 分钟）

### Step 1：收集资料（10 分钟）

小陈打开她的工作文件夹，把所有跟「竞品周报」相关的资料都放进一个新文件夹：

```
~/Desktop/技能发布素材/
├── 我的方法笔记/
│   ├── 30min竞品周报-流程.md      # 她自己写的工作流程
│   └── 竞品分析常用字段.md         # 她整理的标准字段表
├── prompt 收藏/
│   ├── 我用得最多的周报 prompt.md
│   └── 网上看到的对比表 prompt.md
├── 历史报告/
│   ├── 2026-06-W1竞品周报.md
│   ├── 2026-06-W2竞品周报.md
│   └── 2026-06-W3竞品周报.md
├── 截图/
│   ├── 优秀对比表示例.jpg
│   └── 我做的对比表截图.png
└── 别人的参考/
    └── 别人发的小红书Skill笔记截图.png
```

### Step 2：让 Codex 提炼（30 分钟）

**Codex Prompt**：

```
我准备把「30 分钟竞品周报」方法打包成 Skill 发布。

读取这个文件夹的所有 .md/.txt/.docx 文件，提炼出结构化方法论。

按以下章节输出 Markdown：

## 1. 方法名称
## 2. 适用场景（3-5 个具体场景）
## 3. 不适用场景（3 个边界）
## 4. 输入要求（含文件夹结构示例）
## 5. 完整步骤（5-8 步，每步说工具和预期输出）
## 6. 完整 Prompt 模板（可复制）
## 7. 常见坑（5+ 个，配解决方案）

文件名：method-30min-competitor-weekly-report-v1.md
保存到当前文件夹根目录。
```

**Codex 输出**：一份 `method-30min-competitor-weekly-report-v1.md` 文件。

### Step 3：小陈人工润色（20 分钟）

她打开 Codex 输出的文件，做了这些事：

✅ **补充了 Codex 没写的内容**：
- 加了「团队角色分工」（谁负责收集资料、谁负责 review）
- 加了「小红书版特殊调整」（为了发布做的简化）
- 加了「失败案例」（哪次跑失败了、为什么）

✅ **改写不准确的地方**：
- Codex 把 Step 2 写成「读所有资料」，她改成「先读 1 家验证格式，再批量读」
- Codex 列的「常见坑」太空洞，她改成具体例子

✅ **调整风格**：
- 把学术化措辞改成口语化
- 加了她个人风格（一句开场白）

## 阶段 2：创建 Skill（60 分钟）

### Step 4：让 Codex 把方法论转成 SKILL.md（10 分钟）

**Codex Prompt**：

```
读取 method-30min-competitor-weekly-report-v1.md，
转成符合 Codex Skill 标准的 SKILL.md。

要求：
1. 包含 7 个章节：frontmatter / 使用场景 / 不适用场景 / 输入要求 / 完整步骤 / 完整 Prompt / 注意事项
2. Skill 命名：30min-competitor-weekly-report（kebab-case）
3. 总长度 2000-3000 字
4. Prompt 要完整可粘贴，不要片段
5. 常见坑至少 5 条

输出文件：SKILL.md（保存在当前文件夹）
```

**Codex 输出**：`SKILL.md` 文件，结构跟 [3. 创建 Skill](03-创建skill.md) 模板一致。

### Step 5：小陈二次润色 + 测试（50 分钟）

她做了几件事：

#### 5.1 完善 Prompt 部分（10 分钟）

Codex 生成的 Prompt 还差点意思，她手动改：

**Codex 写的**：
```
读取文件夹里的竞品资料，生成周报。
```

**小陈改的**：
```
读取这个文件夹里所有竞品资料（PDF/MD/截图），
按以下结构生成 markdown 周报：

1. 本周概览（3-5 句话总结）
2. 竞品动态对比表（必须包含：核心更新 / 营销动作 / 用户反馈 / 定价变化 4 列）
3. 重点关注（哪个竞品动作最大 + 原因分析）
4. 我们的应对建议（至少 3 条，要可执行）
5. 下周关注点

写作风格：
- 数据说话，避免「显著」「大幅」这种形容词
- 短句为主，每段不超过 3 行
- 用 markdown 表格做对比

文件命名：competitor-weekly-report-YYYYMMDD.md
直接输出，不要让我再追问
```

**她的改进**：
- 明确了「对比表的列」（4 列）
- 明确了「应对建议」要可执行
- 加了写作风格约束
- 加了文件命名规范

#### 5.2 自己测试一遍（20 分钟）

把 Skill 复制到 `~/.codex/skills/`，重启 Codex：

1. 用一个新文件夹（3 家没见过的竞品）
2. 调出 Skill 跑了一遍
3. 看到 Codex 输出的周报质量 OK
4. 做了小调整（cover 页加了她公司 logo）

#### 5.3 让 2 个同事测试（20 分钟）

她把 Skill 发给：
- **同事 A**：市场调研岗，没用过 Codex → 看零基础能不能跑通
- **同事 B**：跟她一样做竞品分析 → 看老手体验

**反馈**：
- A 卡在「资料文件夹放哪」→ 她加了「标准文件夹结构示例」
- B 说「少了一个章节叫『行业趋势』」→ 她加了可选章节
- 两人都说「Prompt 部分很实用，直接复制就能用」

## 阶段 3：配置 xiaongshu-mcp（60 分钟）

### Step 6：安装工具（30 分钟）

按 [4. 发布到小红书](04-发布到小红书.md) 的步骤一步步来：

```bash
# 1. 装 Go
brew install go

# 2. 克隆 + 编译
cd ~/tools
git clone https://github.com/xpzouying/xiaohongshu-mcp.git
cd xiaohongshu-mcp
go build -o xiaohongshu-mcp .

# 3. 登录（扫码）
./xiaohongshu-login
```

她遇到的问题：
- 第一次 Chrome 装不上 → 用 brew 重装搞定
- 扫码后没反应 → 等了 30 秒才好

### Step 7：启动 MCP + 配置 Codex（15 分钟）

```bash
# 启动服务
./xiaohongshu-mcp
```

然后在 Codex 桌面端配置 MCP（按 [4. 发布到小红书](04-发布到小红书.md) Step 5）。

测试：在 Codex 输入「列出你所有可用工具」，看到 xiaohongshu 相关的工具列出来 = 成功。

### Step 8：测试发布一次（15 分钟）

**Codex Prompt**（她用的「工作流 3：先审后发」）：

```

基于内容生成一篇小红书笔记。
```

## 🎯 关键经验总结

小陈做完这一轮总结了几个关键经验：

### 1. Skill 质量 > 数量

她**没急着发**——前期花 3 周打磨 Skill，再发布。

发布后效果好，全靠 Skill 本身扎实。

### 2. 一致性很重要

**每天或每两天更新一篇**，算法才认你。

她后来有一周断更（去出差），流量明显跌。

### 3. 评论区是宝藏

**每一条评论都认真回复**，算法会推你更多。

她有 3 个付费客户都是从评论区来的。

### 4. 不要纯靠自动化

虽然有 xiaohongshu-mcp，但她**90% 的内容是手动准备**，只把最后的发布动作自动化。

自动化是省最后一步，不是省内容创作。

### 5. 合规是底线

她每篇都标「AI 辅助生成」，**没出过任何合规问题**。

## 🚀 你可以怎么开始

如果你想跟小陈一样做：

1. **先选一个你最熟的方法**（建议：周报、数据处理、调研这类高频场景）
2. **花 1 周打磨**（不要急着发）
3. **找个同事测试** 3 遍
4. **第一次发布用「先审后发」工作流**
5. **持续运营 30 天**看效果

**3 个月后，你也能有自己的 Skill 作品集**。
