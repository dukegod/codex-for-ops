# 会议纪要自动整理 Skill

## 使用场景

- 产品评审会
- 周会 / 双周会
- 跨部门协调会
- 客户访谈纪要
- 一对一定期沟通（如 1:1）

## 不适用场景

- ❌ 完全没有转写稿的会议（Codex 不能凭空生成）
- ❌ 高度机密的会议（见 [数据安全](../../../04-安全红线/01-数据安全.md)）
- ❌ 需要逐字记录的会议（Codex 是总结，不是逐字稿）
- ❌ 需要法律效力的会议记录

## 输入要求

### 必需资料

会议转写稿（txt/md 格式），从以下工具导出：

| 工具 | 导出方法 |
|------|--------|
| **飞书妙记** | 打开会议 → 右上角「...」→「导出」→「文本」 |
| **腾讯会议** | 会议结束 → 邮件里的链接 → 「会议纪要」→「导出」 |
| **钉钉** | 会议详情 → 「会议记录」→「导出」 |
| **Zoom** | 会议结束 → 云录制 → 「文字记录」→「下载」 |
| **通义听悟** | 会议结束 → 「下载」→ 选「文本格式」 |

### 文件夹结构

```
meeting-input/
├── 2026-06-30-产品评审会.txt
├── 2026-06-30-运营周会.txt
└── 2026-07-01-客户访谈-客户A.txt
```

### 可选资料

- 议程（让 Codex 知道原本要讨论什么）
- 上次会议纪要（用于追踪 Action Item 完成情况）
- 参会人名单（用于标注负责人）

## 完整步骤

### Step 1：导出转写稿

开完会后，第一时间把转写稿导出（趁还没忘）。

### Step 2：新建 Codex 任务

1. 打开 Codex 桌面端
2. + New Task
3. 选放转写稿的文件夹
4. 安全模式：🟡 自动编辑（推荐）或 🟢 建议模式（第一次用）
5. 粘贴下面的「完整 Prompt」
6. 点 Start Task

### Step 3：等 Codex 跑

约 5-15 分钟，Codex 会读转写稿并生成结构化纪要。

### Step 4：审阅 + 同步

- 核对 Action Item 的负责人和截止时间
- 在飞书/钉钉里建对应任务
- 把纪要发给参会人确认

## 完整 Prompt

```
读取这个文件夹里所有的会议转写稿（.txt/.md），
为每份转写稿生成结构化的会议纪要。

每份纪要包含以下结构：

# [会议名称] - [日期]

## 会议元信息
- 时间：[从转写稿提取]
- 参会人：[从转写稿提取]
- 会议类型：[评审/讨论/同步/其他]

## 议题 1：[议题名]
### 讨论要点
- 要点 1
- 要点 2
### 决定事项
- 决定 A
### Action Item
- [ ] [任务描述] - @[负责人] - [截止日期]
- [ ] [任务描述] - @[负责人] - [截止日期]

## 议题 2：[议题名]
...

## 待跟进事项汇总
所有 Action Item 的清单，按负责人分组。

写作要求：
- 议题分段要明确，不能把多个议题混在一起
- Action Item 格式：任务描述 + 负责人 + 截止日期
- 关键讨论要保留原文措辞（避免曲解）
- 不要凭空添加转写稿里没有的内容

文件命名：meeting-summary-<原文件名>.md
保存到当前文件夹根目录。
```

## 注意事项

### 🚨 准确性

- 负责人姓名必须从转写稿里识别，**不要凭空猜**
- 截止日期必须明确（如果转写稿没提，标「待定」）
- 关键决策必须保留原文措辞

### 🚨 隐私

- 涉及薪酬、人事、敏感商业信息的会议**不要用 Codex**
- 见 [数据安全](../../../04-安全红线/01-数据安全.md)

### ⚠️ 转写稿质量

- 转写稿质量差（口音重、噪音大）→ Codex 输出也差
- 解决：用 Otter / 飞书妙记 等专业工具录音
- 多发言人会议：让 Codex 标注「发言人 A」「发言人 B」

### ⚠️ 常见坑

1. **负责人识别错**：Codex 把「那个谁」当成具体名字
   - 解决：人工 review 一次 Action Item
2. **议题分段错**：Codex 把多个议题混在一起
   - 解决：转写稿质量好 + prompt 里强调「议题分段要明确」
3. **Action Item 漏**：转写稿里提到但 Codex 没提取
   - 解决：让 Codex 输出后人工 grep 关键词（决定/完成/负责/下周）
4. **截止日期模糊**：Codex 写「尽快」「尽快安排」
   - 解决：prompt 里要求「截止日期必须是具体日期」
5. **会议名混乱**：所有会议都叫「会议纪要」
   - 解决：保留原文件名 + 加日期前缀

## 进阶技巧

### 技巧 1：让 Codex 自动建任务

在飞书/钉钉里建任务，比手动快：

```
读取刚才生成的 meeting-summary-2026-06-30-产品评审会.md，
帮我在飞书任务里创建对应的 Action Item：

- 任务 1：完成 XX 模块开发
- 负责人：小李
- 截止：2026-07-08
...

调用 feishu-mcp 的 create_task 工具
```

### 技巧 2：跨会议追踪

把本周所有会议纪要放进同一文件夹，让 Codex 汇总：

```
读取这个文件夹里所有的 meeting-summary-*.md，
按负责人汇总所有未完成的 Action Item：

- @小李：5 项
  - XX 模块开发（截止 7-08）
  - ...
- @小红：2 项
  - ...
```

### 技巧 3：对比上次会议

如果文件夹里有上次会议纪要：

```
读取这个文件夹里所有的 meeting-summary-*.md，
对比两次会议的 Action Item 完成情况：

上次 @小李 有 5 项 Action Item：
1. XX（截止 6-25）
2. YY（截止 6-28）
...

本次会议里 @小李 报告了哪些完成？哪些延期？
```
