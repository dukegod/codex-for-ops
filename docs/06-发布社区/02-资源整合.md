# 2. 资源整合：从散乱到结构化

> 第一步：把你脑子里的方法、桌上的笔记、硬盘里的 prompt 草稿，整理成可发布的素材

## 🎬 场景故事

小陈决定要发布一个 Skill。她打开电脑找资料，发现：

```
~/Documents/运营/
├── 周报草稿/
│   ├── 6月第1周.md
│   ├── 6月第2周-初稿.md
│   └── 6月第2周-终稿.md
├── prompt收藏/
│   ├── 看到的好prompt.md
│   └── 网上存的模板.md
├── 笔记截图/
│   ├── IMG_001.jpg
│   └── ...
├── 会议录音/
│   └── 2026-05-产品评审.m4a
└── 想法草稿/
    └── 微信聊天截图.png
```

**资料散乱，没法直接变成 Skill**。

**这章就是帮她把这一堆东西整合成一份「结构化方法论」**。

## 🎯 你将学到

- 资源整合的 3 步流程
- 怎么用 Codex 自动整理
- 一份完整可复制的 prompt
- 整合完应该长什么样

## 📋 整合的 3 步流程

```
┌──────────────────────────────────────────────────┐
│  Step 1: 资料归类（10 分钟）                      │
│  把散落的资料按主题分类                            │
└──────────────────┬───────────────────────────────┘
                   ↓
┌──────────────────────────────────────────────────┐
│  Step 2: Codex 提炼（30 分钟）                    │
│  让 Codex 读资料 → 输出结构化方法论               │
└──────────────────┬───────────────────────────────┘
                   ↓
┌──────────────────────────────────────────────────┐
│  Step 3: 人工润色（20 分钟）                      │
│  你审一遍 Codex 输出，补上你的判断                 │
└──────────────────────────────────────────────────┘
```

总共约 60 分钟，做完你就有了一份「结构化方法论」，可以进入下一步 [创建 Skill](03-创建skill.md)。

## 🚀 Step 1：资料归类（10 分钟）

### 找资料

把你的所有「工作产出」放一个文件夹，比如：

```
~/Desktop/技能发布素材/
├── 我的工作笔记/
│   ├── 2026-Q2-竞品分析.md
│   ├── 2026-Q2-运营周报模板.md
│   └── 6月-活动复盘.md
├── prompt 收藏/
│   ├── 我常用的 prompt.md
│   └── 网上看到的好 prompt.md
├── 截图和图片/
│   ├── 优秀周报示例.png
│   └── 对比表样式.jpg
└── 别人的参考/
    └── 别人的 SKILL.md 范例.md
```

### 归类原则

按这个 4 桶分类法：

| 桶 | 放什么 | 例子 |
|----|------|------|
| **方法论** | 你的工作流程、思考框架 | 「30 分钟搞定竞品周报」的步骤 |
| **模板** | 可以直接复用的 prompt / 文档模板 | 周报 prompt、活动复盘 prompt |
| **案例** | 你做过的具体例子 | 上个月做的某次竞品分析报告 |
| **参考** | 别人的优秀范例 | 别人发的 SKILL.md、看到的优秀小红书笔记 |

**这一步不用追求完美**，大致归类就行。

## 🚀 Step 2：Codex 提炼（30 分钟）

### 创建 Codex 任务

打开 Codex 桌面端：
1. **+ New Task**
2. 选刚才整理的「技能发布素材」文件夹
3. 安全模式建议选 **🟢 建议模式**（第一次跑，先稳一点）
4. 输入下面的 prompt

### 完整 prompt（直接复制）

```
我准备把工作方法打包成 Skill 发布到小红书。

读取这个文件夹里所有的 .md / .txt / .docx 文件（图片先不管），
帮我提炼出一份「结构化方法论」。

要求按以下 7 个章节输出（Markdown 格式）：

## 1. 方法名称
- 给这个方法起一个简洁的名字
- 一句话说明它是干嘛的

## 2. 适用场景
- 哪些情况下会用这个方法？
- 3-5 个真实使用场景

## 3. 不适用场景
- 哪些情况不要用这个方法？

## 4. 输入要求
- 用这个方法前，需要准备什么资料？
- 资料的格式要求（Excel/PDF/md 等）

## 5. 完整步骤
- 拆成 5-8 个步骤
- 每步说清楚：
  - 做什么
  - 用什么工具
  - 预期输出

## 6. 完整 Prompt 模板
- 把方法里用到的所有 prompt 都列出来
- 完整可复制，不是片段

## 7. 常见坑
- 至少列 5 个新手会犯的错误
- 每个错误配解决方案

## 输出要求
- Markdown 格式
- 文件名：method-<方法名>-v1.md
- 保存在当前文件夹根目录
- 完整输出，不要让我追问
```

### 让 Codex 跑

点 Start Task。Codex 会读你文件夹里所有文件，然后输出 `method-<方法名>-v1.md`。

**大约 10-20 分钟**，取决于资料量。

### 中途观察

Codex 跑的时候，注意看：

- **它在读哪些文件**（左侧文件树）—— 如果它没读到关键文件，可能 prompt 没说清楚
- **它的思考过程**（右侧对话）—— 看它怎么理解的、有没有理解错
- **可以追加指令**：比如「等等，再加一个章节叫『方法局限性』」

## 🚀 Step 3：人工润色（20 分钟）

Codex 输出后，**必须人工审一遍**。Codex 会漏掉一些东西。

### 必审清单

打开 `method-<方法名>-v1.md`，按这个清单过一遍：

#### ✅ 内容质量
- [ ] **方法名称**好记、有传播力？（不要太学术）
- [ ] **适用场景**够具体？（不要「适用于各种场景」这种空话）
- [ ] **不适用场景**列了？（划清边界很重要）
- [ ] **步骤**逻辑通顺？（Codex 可能把顺序排错）
- [ ] **Prompt 模板**真的能用？（自己跑一遍试试）

#### ✅ 你的判断
- [ ] **Codex 没写但你知道的背景**——手动补上
- [ ] **Codex 写错的地方**——改对
- [ ] **Codex 没说的人话**——改通俗点
- [ ] **你的个人风格/经验**——加进去（这部分 Codex 替代不了你）

#### ✅ 发布适配
- [ ] **能讲 5 分钟的小红书视频/图文**？（不能太复杂）
- [ ] **截图能配哪些步骤**？（标记出来）
- [ ] **读者能跟着做**？（不要假定读者有专业知识）

### 调优示例

Codex 写的：
```markdown
## 适用场景
适用于数据分析和报告生成的场景。
```

你改成：
```markdown
## 适用场景
- 周一周五早上，用 Codex 汇总本周的销售/活动/用户数据
- 月底做月度复盘，需要把分散的 Excel 整合成一份完整报告
- 季度汇报，要把 Q1/Q2/Q3 的数据整合成一份趋势报告
- 给老板做临时汇报，需要快速出一份数据简报
- 新人入职培训，让他们理解怎么用 Codex 处理数据
```

**你的真实经验 > Codex 的通用输出**。

## 🎯 整合的常见错误

### ❌ 错误 1：资料放得太多

文件夹里有 50 多个文档，Codex 读不完 + 容易混乱。

**解法**：只放**跟这个方法相关**的资料，其他归档到别处。

### ❌ 错误 2：完全不审 Codex 输出

Codex 输出什么就直接用——这种很容易把错误的发布出去。

**解法**：**永远人工审一遍**。这是安全红线。

### ❌ 错误 3：方法论写得太抽象

写出来像「先分析、再总结、最后输出」这种废话。

**解法**：每一步都要**具体到工具、具体到 prompt**。

### ❌ 错误 4：把内部数据写进方法论

比如「我们公司销售额 XX 万、用户 XX 万」——这种绝对不能发。

**解法**：方法论里只用**通用示例**或**完全虚构**的数字。

## 💡 小贴士：怎么找到「值得发布的」方法

不是所有方法都值得发布。问自己 3 个问题：

1. **「这方法我自己用了多久？」** —— 至少 3 个月，否则不够成熟
2. **「这方法别人能用吗？」** —— 不能只在你们公司、行业、岗位用
3. **「这方法能省多少时间？」** —— 至少省 30% 才值得分享

3 个都答「是」，才值得做 Skill。
