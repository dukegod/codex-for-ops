# 5. 从 0 搭建个人知识库

> 端到端实战：基于你现有的 6 区 vault 升级

## 🎬 这章是给谁看的

你已经在用 Obsidian（6 区 vault），有 SCHEMA/QUICKSTART/log 三件套，所以这章**不是从零教你**——而是讲怎么把现有 vault **升级到「LLM + Wiki + Codex」** 体系。

## 🎯 你将学到

- 你现有 6 区 vault 的现状评估
- 升级方案（保留优点 + 增加 LLM 能力）
- 完整的 7 步升级流程
- 一个真实可用的 purpose.md 模板
- 升级后的日常使用方式

## 📋 你现有 vault 的现状分析

根据你的配置：

```
你的 Vault/
├── inbox/         ← 临时收集
├── todo/          ← 待办事项
├── journal/       ← 日记/复盘
├── concepts/      ← 概念/知识
├── archive/       ← 归档
├── templates/     ← 模板
```

**已经很扎实了**——这比 90% 的 Obsidian 用户都做得好。

**但是**（这是要升级的部分）：
- ❌ 缺少 LLM 自动化消化能力
- ❌ 缺少双向链接的自动建议
- ❌ 缺少知识图谱可视化
- ❌ 没有跟 Codex 整合

## 🚀 7 步升级流程

### Step 1：评估现有 vault（1 小时）

先看你的 vault 里现在有多少笔记：

```bash
find ~/Documents/你的vault -name "*.md" | wc -l
```

假设你有 500 篇笔记，按这个分类：

| 类型 | 数量 | 处理方式 |
|------|------|--------|
| **concepts/ 里的概念笔记** | X | 这些就是你的 Wiki 基础，**不要动** |
| **journal/ 里的日记** | Y | 保留原样，**不加双向链接**（日记是个人的） |
| **inbox/ 里的临时** | Z | 用 Codex 消化成 Wiki |
| **todo/ 里的待办** | W | 保留原样，**不进 Wiki**（任务不是知识） |
| **archive/ 里的归档** | V | 不处理，除非你想 |

**重要判断**：concepts/ 里的笔记是你的知识资产核心，**绝对不要让 Codex 自动改**。它们是你手动维护的精华。

### Step 2：装 llm-wiki-skill（10 分钟）

按 [第 2 章](02-llm-wiki-skill安装与使用.md) 装。

完成后你会得到：
- `~/.codex/skills/llm-wiki/` —— 装在 Codex 里
- 可以用 `/llm-wiki-*` 命令

### Step 3：装 Claudian 插件（15 分钟）

按 [第 4 章 · 方式 4](04-obsidian与codex的整合.md) 装。

配置：
- AI 后端选 **Codex**
- 登录你的 ChatGPT 账号
- 把 Vault 路径告诉 Claudian

### Step 4：升级 concepts/ 目录结构（30 分钟）

现在你的 `concepts/` 是一堆平铺或浅层分类的笔记。升级成 k神风格的 Wiki 结构：

```
concepts/
├── _system/                  # 系统文件（不参与 Codex 操作）
│   ├── SCHEMA.md             # 你的 Schema 定义
│   ├── QUICKSTART.md
│   └── log.md
├── _wiki/                    # Codex 维护的 Wiki 区
│   ├── entities/             # 实体页（人物、概念、工具）
│   ├── topics/               # 主题页（跨实体综合）
│   ├── sources/              # 素材摘要
│   ├── synthesis/            # 综合分析
│   └── _graph.html           # 自动生成的知识图谱
├── _index.md                 # 总索引（Codex 维护）
└── （你原有的笔记，按主题分类）
```

**关键决策**：
- 你原有的概念笔记 **保留**，**不要让 Codex 自动改**
- Codex 只负责 `_wiki/` 目录
- 双向链接**手动维护**（你 King 维护）+ Codex 自动建议

### Step 5：写一份 purpose.md（30 分钟）

在 `concepts/_system/` 下新建 `purpose.md`：

```markdown
# 我的个人知识库目的与方向

## 核心身份
我是 [你的名字]，[职业/角色]，主要做 [业务领域]。

## 我想沉淀什么

### 主题 1：互联网运营方法论
- 用户增长：AARRR 漏斗、留存模型、增长案例
- 内容运营：选题策略、爆款拆解
- 活动运营：活动设计、ROI 分析
- 数据分析：指标体系、报表搭建

### 主题 2：[你的专业领域]
- ...

### 主题 3：AI 工具与工作流
- Codex / Claude Code / 其他 AI 工具
- Prompt 工程
- Skills / Plugins 设计
- AI + 工作流整合

### 主题 4：[个人兴趣]
- ...

## 我不想沉淀什么
- ❌ 一次性的工作任务（不沉淀为知识）
- ❌ 客户的内部数据（合规）
- ❌ 没经过自己思考的转载

## 知识库使用原则
1. **概念笔记**：我自己写，Codex 不自动改
2. **新素材消化**：通过 Codex 自动化，但人工 review
3. **每周 review**：至少 1 次
4. **每月整理**：归档过期内容

## 关联角色
- 我：King，负责内容创作
- Codex：main，负责系统维护 + 素材消化 + Wiki 整理
```

### Step 6：配置 Codex 让它知道你的 vault（10 分钟）

在 `~/.codex/config.toml` 里加：

```toml
[projects.my-knowledge-base]
vault_path = "~/Documents/你的vault/concepts"
purpose_file = "~/Documents/你的vault/concepts/_system/purpose.md"
enable_wiki_compilation = true
```

或者更简单：每次新建任务时选 `concepts/` 文件夹。

### Step 7：第一次跑通（30 分钟）

#### 7.1 选一篇素材测试

选一篇你最近想消化的文章（公众号 / 网页 / PDF）。

#### 7.2 让 Codex 消化

在 Codex 里：

```
用 llm-wiki 消化这篇文章：[URL]

要求：
1. 提取的概念只生成 _wiki/entities/ 下的新页面
2. 不要改 concepts/ 里我现有的笔记
3. 加 [[双向链接]] 时：
   - 如果链接到 _wiki/entities/ 里的页面 → 直接加
   - 如果链接到 concepts/ 里我现有的笔记 → 用 [[笔记名]] 格式
4. 摘要里说明哪些信息需要人工核实
```

#### 7.3 人工审阅

打开 Codex 生成的 `_wiki/entities/xxx.md`，检查：
- 内容是否准确（跟原文对照）
- 双向链接是否合理
- 置信度标签是否合适

#### 7.4 加到总索引

打开 `concepts/_index.md`，在对应主题下加链接：

```markdown
# 知识库总索引

## 互联网运营方法论
### 用户增长
- [[AARRR 漏斗]]
- [[留存模型]]
- [[增长案例 - Dropbox]]
### 内容运营
- ...

## AI 工具与工作流
- [[Codex 入门]]
- [[llm-wiki-skill 使用]]
- （新消化的：[[刚生成的概念]]）
```

#### 7.5 测试 Obsidian 里的双向链接

打开 Obsidian，确认：
- 双向链接能正常显示
- Claudian 插件能识别新生成的 Wiki 页面
- 图谱视图能看到新增的节点

**第一次跑通了！**

## 🎯 升级后的日常使用方式

### 每天（10-15 分钟）

**场景 A：在 Obsidian 里随手记**

- 看到好文章 → 用 Claudian 快速写一段摘要 → 存到 `concepts/` 或 `inbox/`
- 不想当天整理 → 丢 `inbox/` 后面再消化

**场景 B：用 Codex 处理 inbox**

每天晚上或周末，打开 Codex：

```
用 llm-wiki 处理 inbox/ 里我最近 3 天放进去的内容：

要求：
1. 每篇单独消化
2. 提取的概念去 _wiki/entities/
3. 已存在概念就更新对应页面
4. 处理完的 inbox 文件归档到 archive/
```

### 每周（30-60 分钟）

**周日晚上 review**：

```
用 llm-wiki 做一次周度综合分析：

主题：本月消化的所有素材

要求：
1. 找出反复出现的核心概念（出现 ≥ 3 次的）
2. 生成一份对比分析（保存到 _wiki/synthesis/）
3. 找出我 concepts/ 里有但还没在 _wiki/ 体现的概念
4. 给我 5 条「这周可以做的实践」

然后重新生成 _graph.html
```

### 每月（2 小时）

**月末整理**：

```
用 llm-wiki 做月度知识库健康检查：

要求：
1. 找出孤立页面（没有 [[双向链接]] 进出的）
2. 找出断链（指向不存在的页面）
3. 找出过期内容（标注了"待核实"超过 30 天的）
4. 给我一份清理清单
```

然后花 1-2 小时人工清理。

## ⚠️ 升级过程中的坑

### 坑 1：让 Codex 改你现有的笔记

**症状**：你精心写的概念笔记被 Codex 改坏了

**预防**：
- 明确告诉 Codex：「只改 `_wiki/` 下的文件，不要动 `concepts/` 里其他笔记」
- 在 purpose.md 里强调

### 坑 2：双向链接混乱

**症状**：太多链接，看不清重点

**预防**：
- 每个新概念最多链接 3-5 个相关页面
- 重要链接人工加，一般链接 Codex 自动加

### 坑 3：图谱太密

**症状**：500+ 节点挤在一起，看不清

**预防**：
- 用 k神的「社区地图」功能，按主题分簇
- 在 Obsidian 里用 `localgraph` 而不是 `globalgraph`

### 坑 4：升级太快

**症状**：一次把所有笔记消化完，结果全乱了

**预防**：
- 一次只消化 5-10 篇
- 每周 review 后再消化下一批
