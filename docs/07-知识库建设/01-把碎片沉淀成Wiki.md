# 1. 把碎片沉淀成 Wiki：Codex + Obsidian 的飞轮

> 你看到的、读过的、聊过的——怎么从「在收藏夹吃灰」变成「工作中随时能调出来」

## 🎬 场景故事

小李每年看 100 多篇文章、收藏 200 多个 GitHub 仓库、订 20 多个 newsletter。但每次想用——

- 上周看到的好资料，这周想找，**找不到了**
- 收藏了等于看过？**再也没点开过**
- 知道某个概念，但说不出**它跟 XX 概念什么关系**
- 学过的知识只能「在用的时候才想起来」

**这章就是来解决这个的**：用 Codex 把碎片自动消化成 Obsidian 里的 Wiki，让你的工作产出**可复用**。

## 🌀 一个飞轮

```
碎片（微信、网页、读书、对话）
   ↓ 随手收
Obsidian inbox/   ← 不整理,先囤着
   ↓ 周末批量 1 次
Codex 消化(llm-wiki-skill)   ← 30 分钟,自动化
   ↓
双向链接 Wiki (_wiki/)   ← 概念化、可检索
   ↓ 工作中复用
写方案时查到、跟人讲时能引述   ← 知识变成能力
   ↓
有动力继续维护   ↑ 回到第一步
```

**核心目标**：让 Codex 当消化引擎，Obsidian 当载体，把你每天看到的碎片**自动**变成能反复调用的知识资产。

## 🎯 为什么需要这个体系

1. **知识库 ≠ 笔记软件**：笔记软件是工具，知识库是「你思考的载体」
2. **AI + Wiki 的核心是「被编译一次」**：知识被结构化整理一次，后续每次查询就不用从原始信息重新推导
3. **Obsidian 是载体,不是限制**：选什么笔记软件不重要，「wiki 化、双向链接、持续维护」的思路才重要
4. **Codex 是消化引擎**：把碎片信息变成结构化 Wiki 的过程，靠 Codex 自动化

## 🚀 端到端:从 0 到 7 步

### Step 1:评估你现有的 vault（5 分钟）

假设你已经有 Obsidian vault(类似这种 6 区结构):

```
你的 Vault/
├── inbox/         ← 临时收集
├── todo/          ← 待办
├── journal/       ← 日记
├── concepts/      ← 概念/知识(这是核心)
├── archive/       ← 归档
└── templates/     ← 模板
```

**已经很扎实了**——这比 90% 的 Obsidian 用户都做得好。
**但缺 3 个能力**:LLM 自动化消化、双向链接自动建议、跟 Codex 整合。下面 6 步补齐。

### Step 2:装 llm-wiki-skill(10 分钟)

这个 Skill 装在 Codex 里,负责「把 1 篇素材消化成 1 个 Wiki 页面」。

安装方式(简化):
```bash
# 从 dukegod 仓库拉(具体地址以官方为准)
git clone https://github.com/sdyckjq-lab/llm-wiki-skill.git ~/.codex/skills/llm-wiki
```

装完后,Codex 里能用 `/llm-wiki-*` 系列命令。

### Step 3:装 Claudian 插件(15 分钟)

Claudian 是 Obsidian 里的 AI 插件,支持 Codex 作为后端。

- 在 Obsidian 设置 → 第三方插件 → 浏览 → 搜 `Claudian` → 安装
- 配置 AI 后端选 **Codex**,登录你的 ChatGPT 账号
- 把 vault 路径告诉 Claudian

装完后,在 Obsidian 里能用 AI 直接读/写 vault。

### Step 4:升级 concepts/ 目录结构(30 分钟)

现在你的 `concepts/` 是平铺或浅层分类的笔记。升级成 Wiki 结构:

```
concepts/
├── _system/           ← 你手动维护(King)
│   ├── SCHEMA.md      ← 已有
│   ├── QUICKSTART.md  ← 已有
│   ├── log.md         ← 已有
│   └── purpose.md     ← 新加(Step 5)
├── _wiki/             ← Codex 维护(AI)
│   ├── entities/      ← 实体页(人物、概念、工具)
│   ├── topics/        ← 主题页(跨实体综合)
│   ├── sources/       ← 素材摘要
│   └── synthesis/     ← 综合分析
├── _index.md          ← 总索引(Codex 维护)
└── (你原有的笔记)     ← 不要让 Codex 改!
```

**关键决策**:
- 你原有的概念笔记**保留**,**不要让 Codex 自动改**(它们是你的精华)
- Codex 只负责 `_wiki/` 目录
- 双向链接**手动维护 + Codex 自动建议**

### Step 5:写一份 purpose.md(30 分钟)

在 `concepts/_system/` 下新建 `purpose.md`:

```markdown
# 我的个人知识库目的与方向

## 核心身份
我是 [你的名字],[职业/角色],主要做 [业务领域]。

## 我想沉淀什么

### 主题 1:[如 互联网运营方法论]
- 用户增长:AARRR 漏斗、留存模型
- 内容运营:选题策略、爆款拆解
- 活动运营:活动设计、ROI 分析
- 数据分析:指标体系、报表搭建

### 主题 2:[你的专业领域]
- ...

### 主题 3:AI 工具与工作流
- Codex / Claude Code / 其他 AI 工具
- Prompt 工程、Skills / Plugins 设计
- AI + 工作流整合

### 主题 4:[个人兴趣]
- ...

## 我不想沉淀什么
- ❌ 一次性的工作任务
- ❌ 客户内部数据(合规)
- ❌ 没经过自己思考的转载

## 知识库使用原则
1. **概念笔记**:我自己写,Codex 不自动改
2. **新素材消化**:Codex 自动化,但人工 review
3. **每周 review**:至少 1 次
4. **每月整理**:归档过期内容

## 关联角色
- 我 (King):负责内容创作
- Codex (main):负责素材消化 + Wiki 整理
```

### Step 6:第一次跑通(30 分钟)

1. **选 1 篇素材测试**(公众号文章 / 网页 / PDF)
2. **让 Codex 消化**——在 Codex 里:
   ```
   用 llm-wiki 消化这篇文章:[URL]

   要求:
   1. 提取的概念只生成 _wiki/entities/ 下的新页面
   2. 不要改 concepts/ 里我现有的笔记
   3. 加 [[双向链接]] 时:
      - 链接到 _wiki/entities/ 的页面 → 直接加
      - 链接到 concepts/ 里我现有的笔记 → 用 [[笔记名]]
   4. 摘要里说明哪些信息需要人工核实
   ```
3. **人工审阅**——打开 `_wiki/entities/xxx.md`,检查内容准确性
4. **加到总索引**——打开 `concepts/_index.md`,在对应主题下加链接
5. **测试 Obsidian 双向链接**——打开图谱视图,确认新节点

**第一次跑通了!** 后面就是重复。

## 🗓️ 日常怎么养(3 种节奏选 1)

| 节奏 | 适合谁 | 工作量 |
|------|------|------|
| **A. 每天 10 分钟 + 周末 30 分钟** | 喜欢日常维护 | 高 |
| **B. 每天 0 分钟 + 周末 1 小时** | 不想天天整理 | 中 |
| **C. 每天 0 分钟 + 月末 2 小时** | 只想周末/月度整理 | 低 |

**选一个,不要混用**。推荐从 **C 开始**(最低门槛),跑顺了再升级到 B。

### 3 个 Codex 工作流(自动化日常维护)

1. **每日 inbox 消化**(跑节奏 A/B):扫 `inbox/`,消化新文件,归档已处理
2. **每周综合分析**:找出本周核心概念、生成 `_wiki/synthesis/weekly-*.md`、更新图谱
3. **月度健康检查**:找孤立页面、断链、过期内容,生成清理清单

把这 3 个做成 Codex Skill,日常维护就自动化了。

## 🎯 怎么判断「值得保留」

**✅ 值得**:
- 3 个月内你会再查的(「AARRR 漏斗」「Codex MCP 配置」)
- 概念性内容(「什么是 RAG」「如何做用户分层」)
- 方法论(「30 分钟竞品周报法」)
- 个人洞察(「我对 XX 的思考」)
- 跨主题的桥梁

**❌ 可以丢**:
- 一次性资料(XX 会议 PPT)
- 过时的资讯(2024 年某新闻)
- 没自己思考的转载
- 跟 purpose.md 不符的

## ⚠️ 4 个常见病

| 病 | 症状 | 处方 |
|---|------|------|
| **完美主义** | 花 2 周调结构,3 天写笔记 | 结构是演化出来的,先随便建,跑 3 个月再调 |
| **囤积症** | 每天消化 10 篇,Wiki 1000+ 页但没回头看过 | 每天最多 3 篇;每周强制 review 旧的 |
| **强迫症** | 每篇笔记都加 5+ 个双向链接 | 最多 3 个 [[]],重要的手动加 |
| **资料依赖** | 以为消化了就是学会了 | 消化 ≠ 学会,真正学会要「用」——用到工作里、跟人讲、写出来 |

## 📈 6 个月长成什么样

- **6 个月后**:100-200 篇 Wiki,6 区 vault 完全跟 llm-wiki 整合,每周 review 30 分钟搞定
- **1 年后**:300-500 篇,开始有「知识涌现」——概念之间产生你没想到的关联
- **3 年后**:1000+ 篇,Wiki 是你**个人思考的镜像**——别人读你的 Wiki 能感受到你的思维模式

## ⚠️ 别期待太多

- ❌ **不会一夜成为大牛**——知识库的价值在「3-5 年」这个尺度
- ❌ **不会自动产出洞察**——工具再强,思考还是你的事
- ❌ **不会替代学习**——知识库是「已经学过的」沉淀,不是「学习本身」
- ✅ **会让你的工作产出可复用**——这是最大的价值
