# 1. 什么是 LLM + Wiki 知识库（k神方法论）

> Karpathy 提出的"LLM 编译信息"思路 + k神的具体落地

## 🎬 场景故事

小王每年看 100 多篇文章、收藏 200 多个 GitHub 仓库、加 50 多个微信群。他发现：

```
- 上周看到的好资料，这周想找，找不到了
- 收藏了等于看过？再也没点开过
- 知道某个概念，但说不出"它跟 XX 概念什么关系"
- 学过的知识只能"在用的时候才想起来"
```

**这是典型的"信息囤积 ≠ 知识"问题**。

## 💡 Karpathy 的核心洞察：「LLM as Compiler」

**Andrej Karpathy**（前特斯拉 AI 总监、OpenAI 创始成员）在 2025 年提出一个观点：

> **"知识被 LLM 编译一次，持续维护，而不是每次查询都从原始文档重新推导。"**

翻译成人话：

```
传统方式（每次重新推导）：

  每次问问题 → LLM 读 N 篇文章 → 重新总结 → 回答你
              （慢、不一致、消耗 token 多）

知识库方式（编译一次，持续维护）：

  LLM 一次性读 N 篇文章 → 编译成结构化 Wiki
       ↓
  每次问问题 → 直接查 Wiki → 回答你
              （快、稳定、token 消耗少）
```

**关键洞察**：

| 维度 | 传统方式 | 知识库方式 |
|------|--------|--------|
| 速度 | 每次重新推导，慢 | 查 Wiki，快 |
| 一致性 | 每次结果可能不一样 | Wiki 是稳定的 |
| Token 消耗 | 每次都读原文 | 只读 Wiki 摘要 |
| 信息关联 | 孤立的 | 双向链接，跨主题关联 |
| 长期价值 | 单次回答 | Wiki 持续累积 |

## 🎯 k神（llm-wiki-skill）是什么

**GitHub 仓库**：[sdyckjq-lab/llm-wiki-skill](https://github.com/sdyckjq-lab/llm-wiki-skill)

**k神 = 国内开发者基于 Karpathy 思路做的开源 Skill**，让 Codex / Claude Code / OpenClaw / Hermes 都能用。

**它的核心能力**：

### 1. 一键初始化知识库

```
你：「帮我初始化一个知识库」

Codex/k神：
  ✅ 自动创建目录结构
  ✅ 生成 purpose.md（你的研究方向）
  ✅ 生成模板（实体页、主题页、摘要页）
  ✅ 生成 index.md（索引页）
```

### 2. 一键消化素材

```
你：「帮我消化这篇文章：[链接/PDF/MD]」

Codex/k神：
  ✅ 提取关键概念（实体）
  ✅ 提炼核心观点（主题）
  ✅ 生成摘要页
  ✅ 自动添加 [[双向链接]]
  ✅ 标注置信度（EXTRACTED / INFERRED / AMBIGUOUS / UNVERIFIED）
```

### 3. 自动生成知识图谱

**这是 k神的招牌功能** —— 把你的 Wiki 编译成一个**自包含的 HTML 知识图谱**：

- 🎨 **数字山水风格**：东方美学的图谱视觉
- 🔍 **三栏布局**：左侧列表、中间图谱、右侧摘要
- 🌐 **离线运行**：双击 HTML 即可在浏览器看
- 🗺️ **社区地图**：自动识别主题社区
- 📍 **小地图定位**：快速找到节点

```
你的 Wiki（几十到几百页）
   ↓ 编译
数字山水知识图谱.html
   ↓ 浏览器打开
可交互、可探索、可发现关联的可视化界面
```

### 4. 置信度标注

k神给每条信息打标签：

| 标签 | 含义 | 示例 |
|------|------|------|
| **EXTRACTED** | 从原文直接提取 | 「这是文档第 3 段说的」 |
| **INFERRED** | LLM 推断的 | 「根据上下文推测」 |
| **AMBIGUOUS** | 有歧义的 | 「可能有两种解释」 |
| **UNVERIFIED** | 还没核实 | 「需要查证」 |

**这个标注非常重要**——让你知道哪些信息可信、哪些需要复核。

### 5. 智能缓存

- 用 SHA256 去重（同一篇文档不会被处理两次）
- 写入即更新（修改原文，Wiki 自动同步）
- 自愈安全网（弱模型也不会漏缓存）

## 🤔 为什么这个方法适合个人知识库

### 传统笔记方法的 3 个坑

**坑 1：手动整理成本高**

```
手动流程：
  读文章 → 自己提炼 → 自己写笔记 → 自己加标签 → 自己关联
  （每篇 30 分钟，10 篇就要 5 小时）
```

**k神流程**：
```
自动化流程：
  喂给 Codex → 自动提取概念/主题/摘要/链接
  （每篇 5 分钟，主要花在审阅上）
```

**坑 2：整理了就等于学过了**

```
实际：你整理了 50 篇笔记，但 6 个月后一篇也想不起来
```

**k神流程**：
```
实际：知识图谱帮你「发现」意外关联，比如：
  - 你读过的 A 文章和 B 文章其实是同一作者
  - 你以为独立的 X 概念和 Y 概念其实是同一回事
  - 某篇笔记跟 5 年前读的另一篇意外呼应
```

**坑 3：笔记散落在各处**

```
实际：微信收藏 + GitHub star + 浏览器书签 + Notion 笔记 + 印象笔记
```

**k神流程**：
```
实际：所有素材进 raw/ → k神消化 → 结构化 Wiki
     一个入口、一种结构、一致呈现
```

## 📋 k神方法论的 5 个核心原则

### 原则 1：信息分层

```
原始素材（raw/）    → 不可变，只读
       ↓
素材摘要（sources/）→ 原文要点
       ↓
实体页（entities/）  → 概念/人物/工具的定义
       ↓
主题页（topics/）    → 跨实体的综合主题
       ↓
综合分析（synthesis/）→ 跨主题的深度分析
```

**这是 Karpathy 的"编译"分层**——每层都比上一层更抽象、更结构化。

### 原则 2：双向链接

任何概念出现，自动加 `[[wiki-link]]`，让知识图谱自动生成关联。

**例子**：

```markdown
# GPT-5

GPT-5 是 OpenAI 发布的旗舰模型 [[OpenAI]]，
在 [[推理能力]] 上有显著提升，
相比 [[GPT-4]] 在 [[多模态]] 任务上有明显进步。
```

这 4 个 `[[]]` 链接，自动把 4 个相关页面串起来。

### 原则 3：持续维护

- 知识库不是一次性建好就完事
- 每次读到新内容 → 消化 → 增量更新 Wiki
- 每周 review 一次（看有没有错、漏、过期）

### 原则 4：可视化导航

知识图谱是「让大脑换个角度看知识」的工具——你能看到**结构**而不是单篇笔记。

### 原则 5：人工审阅

**AI 整理的每一条信息，人工必须 review**：
- 置信度标签辅助判断
- 关键引用必须溯源
- 推断信息要标清楚

## 🎯 k神跟传统 PKM 方法对比

| 维度 | 传统 PKM | k神方法论 |
|------|---------|----------|
| **整理方式** | 手动 | LLM 辅助 |
| **耗时（每篇）** | 30 分钟 | 5 分钟 |
| **关联方式** | 手动加 [[]] | 自动建议 + 手动确认 |
| **可视化** | 没有 | 数字山水图谱 |
| **检索** | 关键字搜索 | 图谱探索 + 关键字 |
| **置信度** | 没有 | 4 级标签 |
| **适合规模** | 100 篇以内 | 100-10000 篇 |
| **学习曲线** | 中等 | 较高（要理解分层） |

## ⚠️ k神方法论的局限

1. **不擅长处理矛盾信息** —— LLM 可能把矛盾的来源整合到一起，需要人工识别
2. **图谱可能过于复杂** —— 笔记多了之后图谱很密，反而看不清重点
3. **依赖 LLM 质量** —— 弱模型整理出来的 Wiki 质量差，需要 GPT-5 / Claude Opus 级别
4. **不是"一键建立第二大脑"** —— 它加速了整理，但思考还是你的事
5. **中文支持** —— k神原生支持中文，但图谱视觉对中文更友好还需要调整
