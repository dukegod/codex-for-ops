## 🚀 安装步骤（5 分钟）

### Step 1：打开 Codex

启动 Codex 桌面端，确认登录正常。

### Step 2：新建任务，让 Codex 自己装

1. 点 **+ New Task**
2. 选**一个临时文件夹**（任意空白文件夹就行）
3. 安全模式建议选 **🟢 建议模式**
4. 输入下面的 prompt：

```
帮我安装 llm-wiki-skill，让我的 Codex 具备「一键建立知识库」的能力。

仓库地址：https://github.com/sdyckjq-lab/llm-wiki-skill

按照官方 README 的 install.sh 流程走：
1. 克隆仓库到 /tmp/llm-wiki-skill
2. 运行 bash install.sh --platform codex
3. 验证安装成功

完成后告诉我：
- 装在哪里（默认 ~/.codex/skills/llm-wiki）
- 怎么调用（应该有个 /llm-wiki-* 命令）
- 怎么测试一次最小初始化
```

5. 点 Start Task

### Step 3：等 Codex 装

Codex 会自己执行：
```bash
git clone https://github.com/sdyckjq-lab/llm-wiki-skill.git /tmp/llm-wiki-skill
cd /tmp/llm-wiki-skill
bash install.sh --platform codex
```

**约 2-5 分钟**，取决于网络。

### Step 4：验证安装

装完后，在 Codex 输入：

```
列出你的所有 skills
```

应该看到：

```
✅ commit
✅ llm-wiki (新装的)
...
```

看到 `llm-wiki` = 装好了 ✅

### Step 5：可选的扩展安装

如果你要消化 YouTube 视频或微信公众号文章，需要装可选依赖：

```bash
bash install.sh --platform codex --with-optional-adapters
```

**默认安装只包含核心功能**（PDF/Markdown/TXT/HTML）。可选的是：

| 适配器 | 用途 |
|--------|------|
| 网页提取 | 任意 URL |
| X / Twitter | X 帖子 |
| 微信公众号 | 公众号文章 |
| YouTube | YouTube 字幕 |
| 知乎 | 知乎回答 |

## 🎯 第一次使用：初始化知识库

### Step 1：建一个空文件夹

在某个安全的位置（建议云盘 / NAS）建一个空文件夹：

```bash
mkdir -p ~/Documents/my-knowledge-base
```

**不要放在桌面、下载文件夹这种容易乱的地方**。

### Step 2：让 Codex 初始化

在 Codex 里新建任务，选刚才的文件夹，输入：

```
帮我用 llm-wiki 初始化这个文件夹作为我的个人知识库。

要求：
1. 提示我输入「研究方向 / purpose」（我想沉淀什么内容）
2. 根据我的回答自动创建：
   - purpose.md
   - 目录结构（raw/、wiki/、sources/ 等）
   - 模板文件
   - index.md
   - log.md
3. 完成后告诉我下一步怎么「消化第一篇素材」
```

### Step 3：回答 purpose 提问

Codex 会问你：「你想沉淀什么内容？」

参考回答（举几个例子）：

```
# 例子 1：互联网运营
我想沉淀互联网运营相关的内容，包括：
- 用户增长方法论
- 活动运营案例
- 数据分析技能
- 行业研究报告
- 常用工具和工作流

# 例子 2：AI 工程师
我想沉淀 AI 工程相关的内容，包括：
- LLM 模型原理
- Agent 开发框架
- RAG 系统实践
- 主流工具对比
- 自己项目的踩坑记录

# 例子 3：产品经理
我想沉淀产品相关的内容，包括：
- 需求分析方法
- 用户研究方法
- 产品设计原则
- 行业竞品观察
- 自己的产品决策记录
```

### Step 4：验证初始化

初始化完成后，你的文件夹长这样：

```
my-knowledge-base/
├── raw/                  # 原始素材
│   ├── articles/
│   ├── pdfs/
│   └── notes/
├── wiki/                 # 结构化 Wiki
│   ├── entities/         # 实体页
│   ├── topics/           # 主题页
│   ├── sources/          # 素材摘要
│   ├── comparisons/      # 对比分析
│   ├── synthesis/        # 综合分析
│   ├── sessions/         # 对话结晶化
│   └── queries/          # 保存的查询
├── purpose.md            # 你的研究方向
├── index.md              # 索引
├── log.md                # 操作日志
├── .wiki-schema.md       # 配置
└── .wiki-cache.json      # 缓存
```

**这就是你的个人知识库骨架了**。

## 🎯 消化第一篇素材

### 场景：消化一篇技术文章

假设你看到一篇公众号文章，URL 是 `https://mp.weixin.qq.com/s/xxx`

在 Codex 输入：

```
用 llm-wiki 帮我消化这篇文章：
https://mp.weixin.qq.com/s/xxx

要求：
1. 自动提取核心概念（生成实体页）
2. 提炼文章主题（生成主题页）
3. 写一份素材摘要（保存到 sources/）
4. 自动加 [[双向链接]] 到 Wiki 里已存在的相关页面
5. 给每条信息打置信度标签
6. 摘要末尾说明哪些信息需要我人工核实
```

### Codex 会做的事

1. **抓取文章内容**（用网页提取适配器）
2. **去重检查**（如果处理过，直接调缓存）
3. **两步式整理**：
   - 先分析文章结构、提取概念、识别主题
   - 再生成 Wiki 页面
4. **写入 Wiki 文件**：
   - `sources/<文章标题>.md` —— 素材摘要
   - `entities/<概念>.md` —— 实体页（如果是新概念）
   - `topics/<主题>.md` —— 主题页（如果是新主题）
   - 自动加 `[[wiki-link]]` 到相关已存在页面
5. **更新索引**：
   - 在 `index.md` 加链接
   - 在 `log.md` 加记录

**耗时**：约 3-10 分钟，取决于文章长度。

### 中途审阅

Codex 跑的时候你可以：
- **看它在读什么**（左侧文件树）
- **看它在写什么**（右侧对话）
- **追加指令**：比如「这篇文章重点放在营销上，技术部分简短处理」
- **暂停修改**：发现 Codex 理解错了就停下来纠正

### 完成后的人工审阅

打开生成的 Wiki 页面，**至少检查这 3 件事**：

1. **置信度高的内容**（EXTRACTED）：跟原文对照一下，看有没有曲解
2. **推断的内容**（INFERRED）：是否符合你的理解
3. **新的 [[双向链接]]**：是不是你想要的关联

## 🎯 日常使用流程

### 每周消化节奏（推荐）

```
周一上午（30 分钟）：
  - 消化上周收藏的 3-5 篇文章 / 报告 / 笔记
  - 让 Codex 自动整理

周三晚上（15 分钟）：
  - review 上周消化的内容
  - 补充自己的判断和洞察
  - 修正 Codex 整理错的地方

周五下午（30 分钟）：
  - 让 Codex 跑一次「综合分析」
  - 找出本周消化内容里的关联
  - 生成新主题页或对比页
```

### 让 Codex 跑综合分析

```
用 llm-wiki 帮我做一次「综合分析」：

主题：过去 2 周消化过的所有关于「用户增长」的内容

要求：
1. 找出这些内容里共同的核心概念
2. 找出观点冲突的地方（如果有）
3. 生成一份「对比分析」页面（保存到 comparisons/）
4. 生成一份「综合洞察」页面（保存到 synthesis/）
5. 给我 5 条可以用于实践的「行动建议」
```

### 让 Codex 更新知识图谱

```
用 llm-wiki 重新编译我的知识图谱，包括所有最新的 wiki 内容。
```

Codex 会重新扫描整个 Wiki，生成新的 `knowledge-graph.html`。

**双击 HTML 即可在浏览器打开**，看你的知识库全景图。

## 🎯 进阶用法

### 用法 1：把对话结晶化

你在 Codex 里跟 AI 聊了很久，得到一些有价值的内容。

```
帮我把刚才这段对话结晶化成 Wiki：

[粘贴对话内容]

要求：
1. 提取核心概念 → 实体页
2. 提炼观点 → 主题页
3. 生成对话摘要 → sessions/<对话主题>.md
4. 加 [[双向链接]] 到相关页面
```

### 用法 2：跨笔记检索

```
用 llm-wiki 帮我搜索：

问题：「GPT-5 在多模态能力上比 GPT-4 强在哪？」

要求：
1. 在我的 wiki/ 里搜索相关内容
2. 整理成一份带引用的回答（每个观点后加 [[来源]]）
3. 如果找到矛盾的观点，标出来
4. 保存到 queries/ 目录
```

### 用法 3：批量消化

```
用 llm-wiki 批量消化这个文件夹的所有素材：
~/Downloads/reading-materials/

要求：
1. 每个文件单独消化
2. 去重检查（已处理过的跳过）
3. 每消化 5 篇停下来给我个进度汇报
4. 全部完成后给个总览报告
```

## ⚠️ 常见坑和排查

### ❌ 坑 1：消化质量差

**症状**：摘要空洞、链接乱加、推断太多

**原因**：
- 模型太弱（GPT-5.4-mini 不如 GPT-5.4）
- 原文质量差（很短的、没有结构的）
- prompt 没约束

**解决**：
- 重要素材用 `model_reasoning_effort = "high"`
- 在 prompt 里强调「宁可少而准，不要多而空」
- 消化完人工 review

### ❌ 坑 2：双向链接爆炸

**症状**：一篇文档加了 50 个 `[[]]` 链接，看不清重点

**原因**：LLM 试图把所有相关词都链接

**解决**：在 prompt 里约束「只链接真正重要的概念（≤5 个），其他忽略」

### ❌ 坑 3：缓存没生效

**症状**：同一篇文章处理了两次

**原因**：原文被轻微修改过（SHA256 变了）

**解决**：用 `.wiki-cache.json` 排查；如果要强制重新处理，可以 `rm .wiki-cache.json` 后重跑

### ❌ 坑 4：图谱太密

**症状**：笔记多了之后图谱看不清

**解决**：k神有「社区地图」功能，自动识别主题社区，进入社区后只显示该社区的图谱

### ❌ 坑 5：跟不上更新

**症状**：llm-wiki-skill 更新了新功能，你还在用旧版

**解决**：
```bash
# 进仓库目录
cd /tmp/llm-wiki-skill
git pull
bash install.sh --platform codex --upgrade
```

或者在 Codex 用 `/llm-wiki-upgrade` 命令（如果装了的话）。
