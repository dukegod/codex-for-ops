# 6. 知识库的日常维护与进化

> 知识库不是一次性建好的，是持续养出来的

## 🎬 场景故事

小陈照着 [第 5 章](05-从0搭建个人知识库.md) 搭好了个人知识库。

第一个月很兴奋：每天消化 3-5 篇素材，Wiki 涨到 100+ 页面。

第二个月热情减半：偶尔消化一下。

第三个月几乎不动了：素材堆在 `inbox/`，Wiki 没更新。

**半年后，他打开 Obsidian 看着那个 Wiki，感觉：「我又做了一个笔记软件坟墓」**。

**这章就是帮你避开这个结局**。

## 🎯 你将学到

- 知识库的「生命周期」
- 怎么设置可持续的日常节奏
- 怎么判断哪些内容值得保留
- 怎么让知识库「活起来」（而不是坟墓）

## 📋 知识库的 4 个阶段

### 阶段 1：搭建期（第 1 个月）

**特征**：
- 兴奋，每天都想整理
- 装各种插件、调各种配置
- 消化大量历史素材

**风险**：热情过头，容易过度设计。

**建议**：
- 限制每种配置只试 1 周
- 不要装超过 5 个插件
- 第 1 个月不要追求完美结构

### 阶段 2：蜜月期（第 2-3 个月）

**特征**：
- 每天/每周有节奏地消化
- 开始发现双向链接的价值
- 偶尔能查到之前的笔记

**风险**：养成「每天必须整理」的压力。

**建议**：
- 找到适合自己的节奏（每天 10 分钟 vs 每周 1 小时）
- 不要追求 100% 整理（70% 就够了）

### 阶段 3：平淡期（第 4-6 个月）⚠️

**特征**：
- 热情下降，新内容消化变少
- 旧内容开始过期
- 偶尔打开 Obsidian，但没动力整理

**风险**：**90% 的人在这阶段放弃**。

**建议**：
- 降低维护成本（每周 1 次，每次 30 分钟）
- 用 Codex 自动化消化
- 把知识库跟工作流挂钩（不是「为了整理而整理」）

### 阶段 4：成熟期（6 个月后）

**特征**：
- 已经习惯，每天/每周自然维护
- 真正在用知识库辅助工作
- Wiki 内容稳定增长

**进入条件**：
- 你至少 3 次在工作中查到之前的 Wiki
- 你不再纠结结构（结构自然演化）
- 你不再追新插件（够用就行）

## 🎯 可持续的日常节奏

### 推荐节奏 A：每天 10 分钟 + 周末 30 分钟

**每天（10 分钟）**：
- 早上：扫一遍 `inbox/`，有价值的丢进去
- 晚上：用 Codex 消化今天的 `inbox`（可以批量）

**周末（30 分钟）**：
- review 一周消化的内容
- 加自己的判断（Codex 整理完，King 审阅）
- 修正双向链接

### 推荐节奏 B：每天 0 分钟 + 周末 1 小时

**每天**：
- 看到好东西往 `inbox/` 一扔（不整理）

**周末（1 小时）**：
- 30 分钟：让 Codex 批量消化本周 inbox
- 30 分钟：人工 review + 加判断

### 推荐节奏 C：每天 0 分钟 + 月末 2 小时

**适合「不想天天整理」的人**。

**月末（2 小时）**：
- 1 小时：让 Codex 消化整月 inbox
- 1 小时：review + 修正 + 综合分析

**三种节奏选一个**，**不要混用**。

## 🎯 Codex 自动化清单

把日常维护任务做成 Codex 的工作流：

### 工作流 1：每日 inbox 消化

```toml
# ~/.codex/skills/daily-inbox/SKILL.md
---
name: daily-inbox-digest
description: 每天消化 inbox/ 里新增的素材
---

# 每日 inbox 消化

## 使用方式
点 /skills 找到 daily-inbox-digest → 运行

## 任务流程

1. 扫描 inbox/ 目录
2. 跳过 24 小时内已处理过的文件
3. 对每个新文件：
   - 用 llm-wiki 消化
   - 提取概念 → _wiki/entities/
   - 摘要 → _wiki/sources/
   - 自动加 [[双向链接]]
4. 处理完的文件移到 archive/
5. 更新 _index.md
6. 重新生成 _graph.html

## 完整 Prompt

[粘贴你的标准 prompt]
```

### 工作流 2：每周综合分析

```toml
# ~/.codex/skills/weekly-synthesis/SKILL.md
---
name: weekly-synthesis
description: 每周综合分析，找出本周消化内容里的关联
---

# 每周综合分析

## 任务流程

1. 找出本周新增的 _wiki/ 页面
2. 找反复出现的核心概念
3. 生成 _wiki/synthesis/weekly-YYYY-WW.md
4. 重新生成 _graph.html
5. 输出一份「本周知识图谱变化报告」
```

### 工作流 3：月度健康检查

```toml
# ~/.codex/skills/monthly-health/SKILL.md
---
name: monthly-health-check
description: 月末知识库健康检查
---

# 月度健康检查

## 任务流程

1. 找出孤立页面（没有双向链接进出的）
2. 找出断链（指向不存在页面的）
3. 找出过期内容（标注"待核实"超过 30 天的）
4. 找出 90 天没修改的概念页（可能需要更新）
5. 输出一份「健康检查报告」
```

把这 3 个 Skill 配到 Codex 后，**日常维护就自动化了**。

## 🎯 怎么判断「值得保留」

### ✅ 值得保留

| 标准 | 例子 |
|------|------|
| **3 个月内你会再查的** | 「AARRR 漏斗模型」「Codex MCP 配置」 |
| **概念性内容** | 「什么是 RAG」「如何做用户分层」 |
| **方法论** | 「30 分钟竞品周报法」「活动复盘模板」 |
| **个人洞察** | 「我对 XX 的思考」「XX 的 3 个反直觉发现」 |
| **跨主题的桥梁** | 连接两个领域的笔记 |

### ❌ 可以丢弃

| 标准 | 例子 |
|------|------|
| **一次性的资料** | 「XX 会议 PPT」 |
| **过时的资讯** | 「2024 年某新闻」 |
| **没自己思考的转载** | 直接复制粘贴的文章 |
| **太具体、太细节** | 「XX 产品的某个按钮的文案」 |
| **跟 purpose.md 不符的** | 如果你 purpose 没写，就不沉淀 |

## 🎯 怎么让知识库「活起来」

### 方法 1：跟工作流挂钩

**没挂钩**：知识库是「为了整理而整理」，很快废弃
**挂钩后**：知识库是「工作的一部分」，自然维护

**怎么挂钩**：

| 工作场景 | 用知识库的环节 |
|--------|--------|
| 写周报 | 查 Wiki 里「XX 项目进展」的笔记 |
| 做决策 | 查 Wiki 里「XX 类比」的笔记 |
| 写方案 | 用 Wiki 里沉淀的方法论 |
| 新人入职 | 把 Wiki 链接发给新人 |

### 方法 2：每月做一次「跨主题综合」

每月挑一个主题，让 Codex 跑一次综合分析：

```
用 llm-wiki 做一次跨主题综合：

主题：我最近 3 个月所有关于「用户增长」的笔记

要求：
1. 提取出 5 个最核心的概念
2. 找出这 3 个月我的思考变化（认知升级）
3. 给出 3 个「下个月可以实践」的洞察
4. 保存到 _wiki/synthesis/cross-topic-2026-06.md
```

这种「跨时间 + 跨主题」的回顾，是知识库的最大价值。

### 方法 3：每季度更新一次 purpose.md

每 3 个月 review 你的 purpose.md，问自己：

- 「我现在还在研究这些主题吗？」
- 「有没有新的主题应该加进来？」
- 「有没有主题应该移除？」

**purpose.md 是知识库的指南针**——它变了，知识库的方向也要跟着调。

### 方法 4：跟同行/朋友分享

把 Wiki 的一部分（比如方法论）分享给同行/朋友：
- 收到反馈 → 触发你继续维护
- 看到别人用 → 让你有成就感
- 别人指出错 → 帮你修正

如果分享敏感内容，可以**脱敏后分享**，只分享方法论框架。

## ⚠️ 知识库的常见病

### 病 1：完美主义

**症状**：花 2 周调结构，3 天写笔记

**处方**：结构不是设计出来的，是演化出来的。先随便建，跑 3 个月再调。

### 病 2：囤积症

**症状**：每天消化 10 篇，Wiki 涨到 1000+ 页面，但从来没回头看过

**处方**：
- 每天最多消化 3 篇
- 每周强制 review（不是看新内容，是看旧的）
- 90 天没动过的页面打上「待整理」标签

### 病 3：强迫症

**症状**：每篇笔记都要加 5+ 个双向链接，否则不放过

**处方**：
- 一篇笔记最多 3 个 [[]] 链接
- 重要的手动加，普通的让 Codex 自动加
- 链接不是越多越好，是越准越好

### 病 4：资料依赖

**症状**：以为消化了就是学过了，再也不打开原文

**处方**：
- 消化 ≠ 学会，消化只是「沉淀」
- 真正学会需要「用」（用到工作里、跟人讲、写出来）
- 知识库是辅助记忆，不是替代学习

## 🎯 长期演化的方向

### 6 个月后

- 你应该有 **100-200 篇** Wiki 页面
- 你的 6 区 vault 完全跟 llm-wiki 整合
- 你每周 review 一次，30 分钟搞定

### 1 年后

- 你应该有 **300-500 篇** Wiki 页面
- 你的 Wiki 真正开始有「知识涌现」——概念之间产生你没想到的关联
- 你在工作中至少 5 次从 Wiki 里找到答案

### 3 年后

- 你应该有 **1000+ 篇** Wiki 页面
- 你的 Wiki 是你**个人思考的镜像**——别人读你的 Wiki 能感受到你的思维模式
- 知识库从「记录」变成「思考伙伴」

## 🎯 给团队的建议（如果你想推给团队）

如果你想把个人知识库建设方法推给团队：

### 阶段 1：个人先跑通（3 个月）

你自己先用起来，**别上来就推团队**。

### 阶段 2：1-2 个同事一起试（1 个月）

找 1-2 个愿意尝试的同事，每周分享一次你的发现。

### 阶段 3：内部分享会（1 次）

整理一份「个人知识库建设实践」分享给团队。

### 阶段 4：建立团队 Wiki 规范（按需）

如果团队想统一：
- 团队 Wiki 仓库（Git 管理）
- 团队 purpose.md
- 团队 Codex 配置规范

**不要强推**——知识库是个人选择。
