# 批量处理任务

> 让 Codex 替你处理文件夹里那 200 张照片、50 个 PDF、100 个文档的重命名 / 转换 / 提取。

## 🎬 场景故事

周六下午，市场组的小赵接到一个紧急任务：上周末办了 3 场线下活动，主办方要全部照片原图，并且要求「按日期-活动名-序号」命名，比如 `20260628-亲子嘉年华-001.jpg`。

她打开相机文件夹一看——**412 张照片**，原始文件名全是 `IMG_3847.jpg`、`IMG_3848.jpg`……还有 30 张是别的活动的混进来了。

如果手动改：412 × 改 3 段文字 = 至少 2 小时，还容易改错。

她打开 Codex，把文件夹指给它，**6 分钟搞定**。

## 🎯 你将学到

- 怎么让 Codex 扫描整个文件夹、识别文件规律、制定批量处理规则
- 重命名、格式转换、内容提取、文件分类 4 类最常见批量任务的 prompt 模板
- 进阶玩法：把常用批量任务打包成 Skills（可复用工作流），下次一行 prompt 就能跑

时间：第一次 20 分钟，熟练后每次 5-8 分钟。

## 📋 前置准备

- ✅ 已安装 Codex 桌面端并登录
- ✅ 一个明确的「输入文件夹」和一个「输出文件夹」（千万别混在一起，Codex 跑起来后混一起很难撤销）
- ✅ 安全模式建议选 **Workspace**，但跑大批量前先在小文件夹里测试一次
- ✅ 重要文件提前备份（虽然 Codex 用 worktree 隔离不会动原文件，但养成备份习惯）

> 💡 **小贴士**：Codex 默认在沙箱里跑，**不会直接动你原文件夹**。但保险起见，先复制 5-10 个样本到一个测试文件夹跑通流程，再跑全量。

## 🚀 操作步骤

### Step 1：把小文件夹指给 Codex

桌面建 `~/Desktop/批量测试/`，把样本文件复制进去。

> 👀 **这里你会看到**：
>
> ```
> ~/Desktop/批量测试/
> ├── IMG_3847.jpg
> ├── IMG_3848.jpg
> ├── IMG_3849.jpg
> └── ...（共 8 张样本）
> ```

打开 Codex → 新建任务 → 把 `批量测试` 文件夹指给 Codex。

### Step 2：先用一句 prompt 让 Codex 摸清家底

```
请扫描当前文件夹，告诉我：1) 有多少个文件；2) 都是什么类型；3) 文件名有没有规律（比如都叫 IMG_xxxx.jpg）；4) 最早和最晚的修改时间。不要修改任何文件。
```

Codex 会返回：8 个文件，全是 jpg，命名是 IMG_xxxx.jpg 格式，修改时间集中在 2026-06-28 到 2026-06-29。

### Step 3：把任务规则完整告诉 Codex

粘贴下面这段 prompt 模板（已经填好了小赵的活动照片场景）：

```
我对当前文件夹的图片做批量重命名，要求：

【命名规则】
- 格式：YYYYMMDD-活动名-序号(3位).jpg
- 日期：根据文件修改时间取（YYYYMMDD）
- 活动名：本次活动叫「亲子嘉年华」
- 序号：从 001 开始，按修改时间升序，依次递增
- 示例：20260628-亲子嘉年华-001.jpg

【执行步骤】
1. 先把所有文件的当前文件名 + 修改时间 + 新文件名列成一个「对照表」（输出为 markdown，让我确认）
2. 等我确认后再执行重命名
3. 重命名后输出一份「执行日志」，记录每个文件的旧名 → 新名
4. 不要移动文件、不要删除文件、不要修改文件内容

【运行方式】
用 Python 的 os 和 pathlib 在沙箱里跑。
```

Codex 会先生成对照表让你看，没问题你说「继续」，它才会真的改名。

### Step 4：跑完人工抽查

抽查 5-10 个文件，看命名是否符合预期。重点看：

- 日期是不是按修改时间取的（不是文件名）
- 序号是不是连号
- 中文有没有乱码

## 📝 完整 Prompt 模板

### 模板 A：批量重命名（按规则 + 序号）

**适用场景**：文件命名混乱，需要按某种规则统一重命名。

**完整 prompt**：

```
对当前文件夹的所有文件做批量重命名：

【命名规则】
- 格式：{日期}_{活动名}_{原扩展名}
- 日期：YYYYMMDD，按文件修改时间
- 活动名：[填入你的活动名]
- 序号：3 位，从 001 开始

【执行要求】
1. 先生成「对照表」（markdown 格式，包含旧文件名、修改时间、新文件名），等我确认
2. 我说「继续」后执行重命名
3. 输出「执行日志」
4. 用 Python（os + pathlib）跑，不要用 shell 的 mv 命令（避免编码问题）
5. 如果新文件名已存在，跳过并在日志里写「冲突」

【注意】
- 不修改文件内容
- 不移动文件
- 不递归处理子文件夹
```

**预期输出**：一份对照表（等你确认）→ 一份执行日志（重命名后）。

### 模板 B：格式转换（docx ↔ pdf、xlsx → csv、图片格式）

**适用场景**：几十上百个文件需要从一种格式转成另一种格式。

**完整 prompt**：

```
把当前文件夹所有 .docx 文件转换为 .pdf，输出到 ~/Desktop/pdf输出/。

【转换要求】
1. 保持原排版（包括图片、表格、页眉页脚）
2. 输出文件名和原文件名一致（只改扩展名）
3. 中文不要乱码
4. 用 docx2pdf 或者 LibreOffice 命令行（macOS 用 soffice）转换

【执行流程】
1. 先列出会被转换的所有文件（包含原文件名 + 大小），让我确认
2. 我说「继续」后执行转换
3. 输出「转换日志」，记录成功/失败的文件
4. 失败的文件保留原 docx 在原位置，不要删除

【如果失败】
常见失败原因：1) 文件被 Word 占用；2) 字体缺失；3) 图片格式特殊。
```

**预期输出**：N 个 PDF 文件 + 1 份转换日志。

### 模板 C：内容提取（从 N 个 PDF 汇总成 Excel）

**适用场景**：从一堆同结构 PDF（比如合同、发票、报告）里提取关键信息，汇总成一张 Excel。

**完整 prompt**：

```
当前文件夹里有 30 份合同 PDF（都是同一模板），请提取以下字段，汇总成一份 Excel：

【要提取的字段】
- 合同编号
- 甲方公司名
- 乙方公司名
- 合同金额（元）
- 签订日期
- 合同期限（起 - 止）
- 付款方式

【输出】
- 保存为 ~/Desktop/合同汇总.xlsx
- 每个 PDF 对应一行
- 增加一列「来源文件名」
- 用 pdfplumber 或 PyPDF2 在沙箱里跑
- 提取不到的字段写「未识别」，不要留空
- 输出完成后给我一份「字段识别率」报告：每个字段有多少份能识别到

【注意】
- 不要修改原 PDF
- 如果某个 PDF 是扫描件（没文字层），先在日志里标记「需 OCR」，不要瞎猜内容
```

**预期输出**：一份合同汇总 Excel + 一份字段识别率报告。

### 模板 D：文件分类（按扩展名 / 按内容关键词）

**适用场景**：把杂乱的文件夹按某种规则自动分类到子文件夹。

**完整 prompt**：

```
对当前文件夹做自动分类，规则：

【分类规则】
- 按扩展名分到子文件夹：
  - .jpg / .png / .jpeg → 图片/
  - .pdf / .docx / .doc → 文档/
  - .xlsx / .csv → 表格/
  - .mp4 / .mov → 视频/
  - 其他 → 其他/

【执行要求】
1. 移动（不是复制）文件到对应子文件夹
2. 先生成「移动预览表」，等我确认
3. 子文件夹如果不存在自动创建
4. 输出「移动日志」
5. 不要递归处理（只动当前层）
```

**预期输出**：分类后的子文件夹结构 + 移动日志。

## ⚠️ 常见坑

### 坑 1：文件数量太大，一次预览刷屏

**症状**：1000 个文件，对照表全是字，根本看不过来。

**解决**：在 prompt 里加「对照表只展示前 20 行 + 末尾 5 行，中间用『... 省略 975 行 ...』代替」，或者「按文件类型分组统计数量，不用每行列出来」。

### 坑 2：误操作难撤销

**原因**：批量改名后想撤回，但已经覆盖了一些同名文件。

**解决**：
- Codex 在沙箱里跑，**不会直接动原文件夹的文件**（它会把结果输出到你指定的另一个文件夹）。所以养成习惯：输入和输出分两个文件夹。
- 真要原地改名，提前把整个文件夹复制一份到 `~/Desktop/原文件备份_20260630/`。

### 坑 3：中文文件名乱码

**症状**：macOS 改完名挺好，Windows 打开一看全是 `?`。

**解决**：在 prompt 里写「文件名保留中文，使用 UTF-8 编码」，并指定 Python 脚本用 `pathlib.Path` 而不是字符串拼接。

### 坑 4：PDF 转换后排版乱了

**原因**：用了「在线转换」或者某些 PDF 库不支持复杂排版。

**解决**：用 LibreOffice 命令行（macOS 自带），或者在 prompt 里指定 `docx2pdf` + `Microsoft Word`（如果装了）。

### 坑 5：Codex 把不该动的子文件夹也处理了

**解决**：在 prompt 里明确写「只处理当前层，不递归处理子文件夹」。
