# 表格分析

> 让 Codex 替你读懂数据、找出异常、得出结论——不只是算 SUM，是真的出洞察。

## 🎬 场景故事

小陈是用户增长组的运营，每周要写一份「上周用户活跃周报」。

她面对一堆数据：DAU、WAU、留存、漏斗、付费转化……

以前她是这样工作的：

1. 打开 Excel，拖公式算这周 DAU
2. 拖公式算上周 DAU
3. 手算环比
4. 把数字粘到 PPT 上
5. **最头疼的环节**：对着数字写「洞察」——为什么这周涨了？哪个渠道贡献最大？要不要做点什么？

第 5 步通常要憋 1-2 小时，因为要从数字里「看出故事」。

现在她把 CSV 扔给 Codex，**8 分钟拿到一份带洞察的初稿**——Codex 会告诉她「DAU 上涨主要来自新用户拉新活动，但次日留存下降了 5 个百分点，建议排查活动质量」。

## 🎯 你将学到

- 怎么让 Codex 跑描述统计（均值/中位数/分布/同比环比）
- 怎么让 Codex 出**洞察**而不是只出数字（这一章的重点）
- 4 类最常见的数据分析 prompt 模板（销售周报 / 用户活跃 / 活动复盘 / 异常检测）

时间：第一次 20 分钟，熟练后每次 5-8 分钟。

## 📋 前置准备

- ✅ 已安装 Codex 桌面端
- ✅ 一份数据文件（CSV 或 Excel），最好带表头
- ✅ **强烈建议**：单独写一个 `字段说明.md`，列出每列的含义、单位、统计口径。这是出好洞察的关键——Codex 不知道你业务里的「DAU」是去重还是不去重
- ✅ 一个输出文件夹（比如 `~/Desktop/分析结果/`）

> ⚠️ **重要**：喂给 Codex 的数据先脱敏。把用户 ID、手机号、身份证等敏感字段替换成「用户001」「用户002」这种代号（详见[数据安全](../04-安全红线/01-数据安全.md)）。

## 🚀 操作步骤

### Step 1：把数据和字段说明一起放进工作文件夹

```
~/Desktop/分析任务/
├── data.csv               ← 原始数据
└── 字段说明.md            ← 业务解释
```

`字段说明.md` 写大概这样：

```markdown
# 数据字段说明

## 基础维度
- user_id: 用户唯一标识（已脱敏为 USER_001 格式）
- register_date: 注册日期
- channel: 注册渠道（organic / ads / referral / event）

## 活跃维度
- dau: 当天是否活跃（1/0）
- session_count: 当天会话次数
- avg_duration: 平均停留时长（秒）

## 付费维度
- is_paid: 是否付费用户（1/0）
- pay_amount: 付费金额（元）
- pay_date: 付费日期

## 统计口径
- DAU = 当天 dau=1 的去重用户数
- 留存 = 第 N 天回访用户数 / 第 0 天新增用户数
- 付费率 = 付费用户数 / 总用户数
```

### Step 2：先用一句 prompt 让 Codex 摸清数据

```
请先读 data.csv 和字段说明.md，告诉我：1) 一共多少行多少列；2) 各列的数据类型和缺失值情况；3) DAU、付费率这两个核心指标的口径我理解得对不对。不做分析，只做数据体检。
```

Codex 会回复一份「数据体检报告」，比如：

> - 共 52,341 行 × 12 列
> - pay_amount 列有 3.2% 缺失值，建议处理
> - 你说的「DAU」我理解是「当日 dau=1 的去重用户数」，对吗？

如果它对你业务口径的理解有偏差，**现在纠正它**，后面分析才不会跑偏。

### Step 3：下达正式分析任务

粘贴下面这个 prompt 模板（按你的场景改）：

```
基于 data.csv 和字段说明.md，给我一份「上周用户活跃周报」分析：

【基础统计】
1. 上周（2026-06-23 ~ 2026-06-29）总 DAU、WAU、新增用户数
2. 和上上周（2026-06-16 ~ 2026-06-22）对比，计算环比
3. 按 channel 分组，统计每个渠道的 DAU 和新增占比
4. 按 weekday 分组（周一到周日），看哪天活跃最高

【深度分析】
1. 留存分析：上周新增用户，按 day1 / day3 / day7 留存分别多少
2. 漏斗分析：注册 → 7 日内活跃 → 7 日内付费，每一步的转化率
3. 异常检测：找出上周 DAU 突增 / 突降的日期，结合渠道和事件看可能原因

【输出形式】
- 数据表格（markdown 表格）
- 关键洞察（3-5 条 bullet，每条要有数据支撑）
- 行动建议（基于洞察给 2-3 条建议）

【注意】
- 数据里的数字不要瞎编，如果某个指标无法从现有字段算出来，明确写「数据不足，无法判断」
- 洞察要写得像人话，不要堆砌「增长」「赋能」这种空话
- 用 Python（pandas）在沙箱里跑
```

Codex 会先跑脚本，输出原始数字，再基于数字给出洞察。

### Step 4：人工审核洞察

Codex 给的洞察**不要直接抄**，要做 3 件事：

1. **核对数字**：随机挑 2-3 个数字，自己在 Excel 里验算一下
2. **质疑洞察**：Codex 说的「DAU 上涨主要来自新用户拉新活动」——你对照业务日历，确实那天有个活动吗？
3. **补充它看不到的信息**：比如「这次上涨其实是某渠道刷量，我已经知道」——你写进去，比 Codex 瞎猜强

## 📝 完整 Prompt 模板

### 模板 A：销售周报自动生成

**适用场景**：每周/每月生成销售数据周报/月报。

**完整 prompt**：

```
基于 sales_weekly.csv（字段说明见 字段说明.md），生成本周（2026-06-23 ~ 2026-06-29）销售周报。

【必须包含】
1. 销售总额、订单数、客单价，对比上周的环比
2. TOP 10 商品（按销售额），列出商品名、销售额、订单数
3. TOP 5 销售渠道，列出渠道名、销售额、占比
4. 异常点：销售异常低/高的日期、异常退款的订单
5. 3 条关键洞察 + 2 条行动建议

【输出格式】
- 先给 markdown 表格（数据）
- 再给一段「业务解读」（洞察）
- 最后给「下周关注重点」（建议）
- 整份报告控制在 1500 字以内
```

**预期输出**：一份带表格 + 洞察 + 建议的周报初稿。

**调优提示**：
- 想让它关注特定品类 → 在 prompt 里加「重点分析美妆品类，其他品类简要带过」
- 想要更口语化 → 加「请用运营内部交流的语气，不要用咨询报告体」

### 模板 B：用户活跃度分析（DAU / WAU / 留存 / 漏斗）

**适用场景**：分析用户活跃、留存、转化漏斗。

**完整 prompt**：

```
基于 user_active.csv（字段说明见 字段说明.md），做用户活跃度深度分析：

【基础指标】
- DAU、WAU、MAU（本月）
- 日活同比、环比
- DAU/WAU 比（反映用户访问频次）

【留存分析】
- 新增用户的 day1 / day3 / day7 / day30 留存
- 按渠道分组的留存差异
- 留存的 cohort（队列）表格

【漏斗分析】
- 注册 → 首次活跃 → 7 日内付费，每一步转化率
- 不同渠道的漏斗对比

【洞察要求】
- 找出留存最差的 cohort，可能是哪类用户
- 找出漏斗中流失最大的环节，给 2 个可能原因
- 对比上周同期，指出本周最大变化
```

### 模板 C：活动效果复盘

**适用场景**：线上/线下活动结束后的效果分析。

**完整 prompt**：

```
基于 event_data.csv（这是「618 大促」活动期间 2026-06-01 ~ 2026-06-18 的用户行为数据），做活动复盘：

【活动核心指标】
- 活动期总 GMV、订单数、客单价，对比活动前 2 周的涨幅
- 新客占比、老客占比，老客复购率
- 各品类的销售贡献
- ROI（活动 GMV / 活动成本，成本数据见 cost.csv）

【用户行为变化】
- 活动期间 DAU 变化（vs 平时）
- 活动期间的转化率（vs 平时）
- 活动结束后第 7 天、14 天的留存是否有提升

【洞察 + 建议】
- 这次活动最有效的 2 个玩法
- 这次活动最大的 1 个问题
- 下次类似活动的 2 条改进建议
```

### 模板 D：异常数据检测

**适用场景**：监控数据中是否有异常波动、离群值、刷量行为。

**完整 prompt**：

```
基于 daily_metrics.csv，做异常检测分析：

【异常定义】
- 单日指标偏离过去 30 天均值超过 2 个标准差
- 某渠道单日新增突增 5 倍以上
- 同一用户当日 session 超过 50 次（疑似刷量）

【输出】
- 异常日期清单（哪个指标、哪天、偏离多少）
- 异常渠道清单（哪个渠道、哪天）
- 异常用户清单（user_id + 异常行为 + 建议处理方式：标记 / 封禁 / 人工复核）
- 不要直接修改原数据
```

## ⚠️ 常见坑

### 坑 1：Codex 幻觉数字

**症状**：报告里写了「DAU 周环比上涨 12.3%」，但你自己算其实是 8.7%。

**原因**：Codex 在生成洞察时偶尔会「脑补」数字，尤其是它没真正跑代码、直接生成文字的时候。

**解决**：
- 在 prompt 里明确「先跑代码输出真实数字，再基于数字写洞察，不要直接生成结论」
- 关键数字（特别是要对外汇报的）一定要自己再算一遍
- 用 [Codex 的工作区功能](../00-入门/06-安全模式.md) 让它真跑脚本，而不是只生成文字描述

### 坑 2：业务口径理解错误

**症状**：你说「DAU 是去重的」，Codex 算成不去重的，数字差一倍。

**解决**：
- 字段说明.md 里写得越细越好，包括口径定义、单位、统计窗口
- 在 prompt 里明确「DAU 必须去重，每个用户当天只算一次」
- Codex 输出后检查核心指标的口径是不是和你理解的一致

### 坑 3：分析太泛、不聚焦

**症状**：Codex 给你一份 30 页的「全面分析」，啥都有，啥都不深。

**解决**：在 prompt 里明确「本周只关注一个核心问题」，比如「这周新增下滑 15%，请重点分析新增下滑原因」。

### 坑 4：数据敏感字段泄漏

**症状**：原始数据里直接包含手机号、身份证，喂给 Codex 后存在云端。

**解决**：见[数据安全](../04-安全红线/01-数据安全.md) 章，**先脱敏再喂**。

### 坑 5：把 Codex 的「建议」当真理

**症状**：Codex 建议「下个月加大 X 渠道投放」，你真信了，预算投进去血本无归。

**解决**：Codex 的洞察是基于数据的建议，**业务判断要人来下**。把它的输出当「辅助决策」而不是「决策本身」。
