# 项目记忆（AGENTS.md）：让 Codex 一次记住，永远不用再说

> 每次新建任务都要重打「我们公司是做 xx 的」？把它写进 AGENTS.md，Codex 每次自动读。

## 🎬 场景故事

小陈是 SaaS 公司的内容运营。她每天都要用 Codex 写产品文案、用户邮件、活动推送。

每次她都要在 prompt 里重复这些信息：

- 「我们公司叫 ABC，是一家做团队协作工具的 SaaS 公司」
- 「目标用户是中大型企业的 HR 和 IT 管理员」
- 「品牌调性是专业、克制、不卖萌」
- 「禁用词：赋能、抓手、闭环、底层逻辑」
- 「产品名要用中文全称，不要写英文简称」

每天重复输入 5 行背景信息，多花 3 分钟。更麻烦的是——她有时候会忘记写其中某一条，结果生成的文案里冒出来一个「闭环」，被老板打回来。

后来她发现 Codex 桌面端支持读一个叫 **AGENTS.md** 的文件，放在工作文件夹根目录就行。Codex 每次启动任务时会**自动读这个文件**，相当于给 Codex 配了一个「项目说明书」。

现在她再也不用重复打这些背景了。文案风格稳定，新人接手也不用再交接。

## 🎯 你将学到

- 理解 AGENTS.md 是什么、为什么它比「写在备忘录里」强
- 写一份完整可用的 AGENTS.md 的方法
- 一份能直接复制使用的 AGENTS.md 模板
- 按项目 / 按客户分别建 AGENTS.md 的进阶用法
- 哪些东西**不能**写进 AGENTS.md

预计花 20 分钟。写完之后你以后每次新建任务能省 3-5 分钟输入 + 减少 80% 的「忘记交代背景」返工。

## 📋 前置准备

- 已安装并登录 Codex 桌面端
- 想清楚：**你主要用 Codex 做什么类型的任务**？（比如：写文案 / 处理 Excel / 做调研）不同任务类型可能需要不同的 AGENTS.md
- 准备好你的工作文件夹。比如做用户调研的话，工作文件夹是 `~/Documents/用户调研/`
- 准备一份草稿：把你每次都要重复告诉 Codex 的「公司背景 / 品牌调性 / 常用术语」列个清单

## 🚀 操作步骤

### Step 1：理解 AGENTS.md 的位置

AGENTS.md 必须放在**工作文件夹的根目录**。比如你的工作文件夹是 `~/Documents/用户调研/`，那 AGENTS.md 的位置就是：

```
~/Documents/用户调研/
├── AGENTS.md          ← 在这里
├── 本周反馈.xlsx
└── 上周会议.txt
```

Codex 启动任务时，会自动找这个文件读一遍。你不用手动加载。

> 💡 **小贴士**：如果你在不同文件夹做不同的事，可以在**每个文件夹**根目录各放一个 AGENTS.md。Codex 会按当前任务的文件夹自动加载对应的那份。

### Step 2：创建 AGENTS.md 文件

在你的工作文件夹根目录，新建一个名叫 `AGENTS.md` 的纯文本文件（用任何编辑器都行，推荐 VS Code、Typora、或者 macOS 的 TextEdit 纯文本模式）。

文件名**严格用大写**，不要写成 `agents.md` 或者 `Agents.md`。

### Step 3：按模板填充内容

打开文件，按下面这份模板填。完整模板见下一节。

> 👀 **这里你会看到**（模板的章节结构）：
> ```markdown
> # 项目说明：xxx
>
> ## 公司/团队背景
> - 公司是做什么的
> - 我们的产品是什么
> - 目标用户是谁
>
> ## 品牌调性 & 禁用词
> - 我们的文案风格
> - 不能用的词
>
> ## 常用术语表
> - 内部黑话解释
> - 产品名写法约定
>
> ## 输出格式偏好
> - 默认输出格式（Markdown / 表格 / 飞书文档格式）
> - 长度偏好
> ```

每节写 3-10 条就够了，不要写成长篇大论。

### Step 4：在 Codex 里验证它读到了

保存 AGENTS.md 后，打开 Codex 桌面端，新建一个任务，问它：

> 「请用一句话告诉我，我们公司是做什么的，目标用户是谁。」

如果 Codex 答得对，说明 AGENTS.md 被正确加载了。

如果答得不对（答非所问，或者说「我不知道」），检查：

1. AGENTS.md 文件名是不是大写
2. AGENTS.md 是不是在工作文件夹**根目录**（不是子文件夹）
3. AGENTS.md 编码是不是 UTF-8（用编辑器保存时确认）

### Step 5（可选）：按项目 / 客户分别建 AGENTS.md

如果你同时在做几个不同的项目（比如同时服务 A 客户和 B 客户），可以为每个项目建一个独立的工作文件夹 + AGENTS.md：

```
~/Documents/
├── 客户A项目/
│   ├── AGENTS.md        ← 客户 A 的专属背景
│   └── ...
└── 客户B项目/
    ├── AGENTS.md        ← 客户 B 的专属背景
    └── ...
```

Codex 会根据你打开任务的文件夹自动加载对应的 AGENTS.md，互不干扰。

> 💡 **小贴士**：如果你想让组里所有同事都用同一份 AGENTS.md，可以把这文件放进共享文件夹（比如飞书云文档同步下来的本地文件夹），或者直接发到群里让大家复制。

## 📝 完整 AGENTS.md 模板

### 模板：通用运营团队 AGENTS.md

**适用场景**：通用的内容运营 / 用户运营 / 增长岗位。

**完整模板**（直接复制，改成你自己的内容）：

```markdown
# 项目说明：ABC 公司用户增长组

## 一、公司 / 团队背景

我们是 **ABC 公司**（一家做团队协作工具的 SaaS 公司），成立于 2019 年，总部在上海。
我们的核心产品叫 **ABC 协作平台**，主要功能是任务管理、文档协作、日程同步。
目标用户是**中大型企业的 HR 部门和 IT 部门**（公司规模 500-5000 人）。
我们正在拓展海外市场，重点市场是东南亚。

我们组是 **用户增长组**，负责：
- 新用户拉新（SEM、社媒、合作伙伴）
- 老用户活跃（推送、邮件、活动）
- 用户反馈整理 + 转化漏斗分析

## 二、品牌调性 & 禁用词

**品牌调性**：专业、克制、信息密度高。不卖萌，不夸张，不用感叹号。

**禁用词清单**（**绝对不能出现在输出里**）：
- 赋能
- 抓手
- 闭环
- 底层逻辑
- 打通
- 链路
- 全方位
- 一站式
- 保姆级

**推荐用词**：
- 用「帮助」不用「赋能」
- 用「方法」不用「抓手」
- 用「流程」不用「链路」

**人称约定**：
- 称呼用户用「您」（正式场景）或「你」（社区/社媒场景），不要混用
- 自称用「我们」不用「小编」「小编家」

## 三、常用术语表

| 术语 | 含义 | 备注 |
|------|------|------|
| DAU | 日活跃用户数 | 全称 Daily Active Users |
| MAU | 月活跃用户数 | |
| GMV | 总交易额 | Gross Merchandise Volume |
| ABC 协作平台 | 产品正式名 | 不要写「ABC」或「ABC 平台」 |
| HRBP | 人力资源业务伙伴 | 不是 HR 助手 |
| 工单 | 用户反馈的问题单 | 不要写「ticket」 |

## 四、输出格式偏好

- **默认输出格式**：Markdown（标题用 ##，列表用 `-`）
- **数据呈现**：用表格，不用大段文字
- **长度偏好**：
  - 日常文案：300-500 字
  - 周报 / 月报：800 字以内
  - 深度分析报告：可以到 2000 字
- **语言**：简体中文
- **日期格式**：YYYY-MM-DD
- **货币单位**：人民币用「¥」，美元用「USD $」

## 五、参考资料位置

- 公司产品介绍 PPT：`~/Documents/ABC资料/产品介绍.pptx`
- 品牌 VI 手册：`~/Documents/ABC资料/品牌指南.pdf`
- 历史周报归档：`~/Documents/周报归档/`
- 用户反馈原始数据：`~/Documents/用户反馈/`

如果有相关任务，优先读这些文件。
```

**预期效果**：你以后新建任务时，只要 prompt 里写「写一篇公众号推送」，Codex 会自动按上面这份 AGENTS.md 的风格输出——不会冒出禁用词，会用中文产品名，会用表格而不是大段文字，会控制在 300-500 字。

**调优提示**：

- 如果输出还是用了禁用词 → 在 AGENTS.md 的「禁用词清单」下面加一句「如果你用了这些词，我会要求你重写」
- 如果输出太正式 / 太活泼 → 在「品牌调性」里加更具体的描述，比如「参考小米社区的写作风格」
- 如果想做不同风格的输出 → 在 AGENTS.md 里加一个「风格切换」章节，比如「如果要写活动文案，切换到活泼风格；如果要写产品文档，切换到技术风格」

## ⚠️ 常见坑

**坑 1：AGENTS.md 写得太长（5000 字以上），拖累 Codex 速度**
→ 解决：AGENTS.md **总字数控制在 1000-2000 字**。Codex 每次启动任务都会完整读一遍这个文件，所以它越短，加载越快。真正详细的资料放在「参考资料位置」里指明路径，让 Codex 按需去读，不要全塞进 AGENTS.md。

**坑 2：把客户隐私数据、未公开财务数据、内部敏感文档写进 AGENTS.md**
→ 解决：AGENTS.md 是**明文存储**的纯文本文件，不会自动加密。不要在 AGENTS.md 里写：
- 客户合同金额、未公开的财务数字
- 客户的身份证号、银行卡号、手机号
- 未公开的产品 roadmap、未发布的版本信息

这些信息应该单独加密存储，参考 [数据安全](../04-安全红线/01-数据安全.md) 章节。AGENTS.md 只放「公开的、大家都知道的背景」。

**坑 3：AGENTS.md 改了之后，Codex 还是用旧版**
→ 解决：Codex **每次启动新任务时**才重新读 AGENTS.md。如果你在任务进行中改了 AGENTS.md，需要**新建一个任务**才会生效。在原任务里改是没用的。

**坑 4：好几个项目用同一份 AGENTS.md，结果风格串了**
→ 解决：每个项目（每个工作文件夹）建独立的 AGENTS.md。如果项目之间风格类似，可以把通用部分抽出来命名为 `AGENTS_common.md`，各项目的 AGENTS.md 在开头写「先读 AGENTS_common.md」。

**坑 5：写得很抽象（「品牌调性是专业的」），Codex 不知道具体怎么做**
→ 解决：抽象描述 + 具体例子。比如不要只写「品牌调性是专业克制的」，要写「品牌调性是专业克制的。例如：『3 分钟设置好你的第一个任务』可以，但『手把手教你 3 分钟搞定！超级简单！』不可以」。
