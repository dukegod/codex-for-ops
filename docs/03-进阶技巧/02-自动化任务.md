# 自动化任务：让 Codex 定时跑

> 周末不用惦记周一早 9 点的周报——让 Codex 自己到点跑。

## 🎬 场景故事

小王是用户运营组的组长。组里每周一早会要汇报上周数据，他周日晚上都要加班把周报赶出来。

「为什么这事不能周一早上来做？」他想过，但周一早上 9 点要开会，他没时间。

后来他发现 Codex 桌面端有个 **自动化任务（Automation）** 功能：把 Skill 关联到一个「定时触发器」，设定「每周一早 8 点」自动跑。跑完结果直接发到组里的飞书群。

从此他周日晚上不用再加班。周一早 8:30 醒来，飞书群里已经有周报初稿等着他 review。

## 🎯 你将学到

- 理解 Codex 桌面端的自动化任务是怎么工作的
- 把 Skills 绑定到定时触发器的完整流程
- 3 个常见自动化场景的配置（周报、月度汇总、自动备份）
- 自动化失败时怎么收到通知，以及怎么控制 token 消耗

预计花 30 分钟。配好之后你每天 / 每周能省下 30 分钟到 2 小时不等。

## 📋 前置准备

- 已经会创建 Skill（如果还没看过，先看上一章 [Skills](01-skills.md)）
- 已安装 Codex 桌面端 2026 年 2 月以后的版本（macOS）或 3 月以后的版本（Windows）
- 想清楚：**你那个每周 / 每月都要做的任务**，跑的时间点应该是什么？
- 准备好「任务失败时的通知渠道」：飞书群机器人 webhook、邮箱、或者 Codex 桌面端通知

## 🚀 操作步骤

### Step 1：打开自动化面板

> 👀 **这里你会看到**：
> 1. Codex 桌面端左侧栏「≡」展开
> 2. 找到「Automations」（图标是 ⏰ 闹钟）
> 3. 点击进入，顶部有「+ New Automation」按钮

如果你的 Codex 桌面端是最新版但没看到这个菜单，说明组织管理员没开放 Automation 权限。联系你们的 IT / Codex 管理员开通。

### Step 2：选择触发方式

点击「+ New Automation」后，你会看到 3 种触发方式：

> 👀 **这里你会看到**（3 个选项卡片）：
> ```
> ┌─────────────────┬─────────────────┬─────────────────┐
> │ ⏰ Schedule      │ 📁 Folder Watch  │ 🔗 Webhook      │
> │ 定时触发         │ 文件夹变化触发   │ 外部系统调用触发 │
> │                  │                 │                 │
> │ 每周一早 9 点    │ 文件夹新增文件时 │ 飞书机器人推送时 │
> │ 每月 1 号        │ 自动跑          │ 自动跑          │
> └─────────────────┴─────────────────┴─────────────────┘
> ```

运营最常用的是 **Schedule（定时触发）**。点这个卡片进入下一步。

> 💡 **小贴士**：Folder Watch 适合「有人往共享文件夹丢新文件就自动处理」的场景，比如销售部每天往文件夹丢客户访谈录音，自动转文字 + 摘要。Webhook 适合「外部系统触发」，比如飞书审批通过后自动跑某个 Skill。本章主要讲 Schedule。

### Step 3：配置 cron 表达式（或者用可视化选择）

> 👀 **这里你会看到**（两种配置模式可切换）：
>
> **可视化模式**（推荐新手用）：
> ```
> 频率：  [● 每周]  [○ 每天]  [○ 每月]  [○ 自定义]
> 星期：  [✓ 周一]  [ 周二]  [ 周三]  [ 周四]  ...
> 时间：  [09:00]
> 时区：  [Asia/Shanghai]
> ```
>
> **高级模式**（点「Advanced」展开）：
> ```
> Cron: [0 9 * * 1]
> ```
> 这表示「每周一早 9 点」。

可视化模式够用了。如果你的需求很复杂（比如「每个工作日的下午 5 点，但跳过法定节假日」），用高级模式写 cron 表达式。

> 💡 **小贴士**：cron 表达式不熟没关系，5 个字段从左到右是「分 时 日 月 周」。`*` 表示任意。`0 9 * * 1` = 每周一 9:00 整。`0 17 * * 1-5` = 周一到周五 17:00。

### Step 4：选择要运行的 Skill

页面会列出你创建过的所有 Skill。从下拉菜单选一个，比如「周报生成器」。

> 👀 **这里你会看到**：
> ```
> 运行 Skill：  [周报生成器          ▼]
>                ↓
>                （选完后会显示这个 Skill 的输入/输出配置预览）
> ```

如果你的 Skill 已经设好了输入文件夹和输出位置，这里会自动带过来，不用再填。

### Step 5：设置通知方式

自动化任务跑完后，结果怎么送到你手里？

> 👀 **这里你会看到**（可多选）：
> ```
> ☐ Codex 桌面端通知（系统通知栏）
> ☐ 飞书群消息（需要先绑定 webhook）
> ☐ 邮件（需要先绑定邮箱）
> ☐ 不通知，自己去 Codex 里看
> ```

建议至少勾一个。运营最实用的是「飞书群消息」——跑完自动推到组群里，大家都能看到。

绑定飞书 webhook 的方法：在 Codex 的 Settings → Integrations → Feishu，点「+ Add」，把你的飞书机器人 webhook 地址粘进去（找你们飞书群管理员要）。绑定成功后这里就能勾选了。

### Step 6：测试 + 启用

保存后，先点一下「Test Run」测试一下：

- 确认 Skill 能正常跑完
- 确认通知能收到
- 确认输出位置对

测试没问题后，把状态从「Paused」拨到「Active」（启用）。

到时间 Codex 就会自动跑。

> 💡 **小贴士**：第一次配置自动化的运营，建议先选「比真实时间晚 5 分钟」的时间点测试。比如现在是 14:32，你设个 14:37 跑一次，看飞书群能不能在 14:38 收到通知。确认 OK 后再改成正式的时间。

## 📝 完整自动化配置模板

### 模板 1：每周一早 9 点生成上周销售周报

**适用场景**：销售组每周一早会需要上周数据汇总。

**配置**：

- **触发方式**：Schedule / 每周 / 周一 / 09:00 / Asia/Shanghai
- **运行 Skill**：`周报生成器`（见上一章模板 1）
- **输入文件夹**：`~/Documents/周报素材/`（每周日晚上值班的人把资料丢进去）
- **通知方式**：飞书群「销售-数据播报」群
- **失败通知**：勾选「失败时单独发一条告警到管理员」

**操作要点**：

> 👀 **这里你会看到**（配置 JSON 预览，可选）：
> ```json
> {
>   "name": "周一销售周报",
>   "trigger": "cron",
>   "schedule": "0 9 * * 1",
>   "timezone": "Asia/Shanghai",
>   "skill": "周报生成器",
>   "notify_on_success": ["feishu:销售-数据播报"],
>   "notify_on_failure": ["feishu:管理员私信"]
> }
> ```

### 模板 2：每月 1 号汇总上月所有活动数据

**适用场景**：月初给老板发月度运营报告。

**配置**：

- **触发方式**：Schedule / 每月 / 1 号 / 10:00 / Asia/Shanghai
- **运行 Skill**：`月度活动汇总`（需要你自己建一个，类似「周报生成器」但汇总周期是月）
- **输入文件夹**：`~/Documents/活动数据/`（所有活动数据按月归档）
- **输出位置**：`~/Documents/月报输出/月报_YYYY-MM.md`
- **通知方式**：邮件发给老板 + Codex 桌面端通知

**调优提示**：

- 月报往往字数多、图表多，建议 prompt 里加「请同时生成 3 个 Mermaid 图表（参与人数趋势 / GMV 趋势 / 各活动对比）」
- 月报对准确性要求高，加一句「所有数字必须与 Excel 原始数据核对，禁止编造」

### 模板 3：每天下班前自动备份当天更新的资料文件夹

**适用场景**：运营的共享文件夹每天有人更新，需要每天自动打包备份。

**配置**：

- **触发方式**：Schedule / 每天 / 18:00
- **运行 Skill**：`文件夹备份器`（特殊 Skill，作用是把文件夹打包成 zip 存到备份盘）
- **输入文件夹**：`~/Documents/共享资料/`
- **输出位置**：`~/Backups/共享资料_YYYY-MM-DD.zip`
- **通知方式**：Codex 桌面端通知 + 失败时发邮件

**示例 prompt（这个 Skill 的 prompt 比较特殊）**：

```
读取 ~/Documents/共享资料/ 文件夹下今天（最近 24 小时）修改过的所有文件。

1. 把这些文件打包成 zip，文件名格式：共享资料_YYYY-MM-DD.zip
2. 存到 ~/Backups/ 目录
3. 如果 zip 文件大小超过 100MB，发邮件警告（说明文件过多）
4. 删除 30 天前的旧备份（节省空间）

完成后输出一句话总结：今天备份了几个文件、总大小多少。
```

## ⚠️ 常见坑

**坑 1：自动化任务失败了没人知道，等周一发现周报没出**
→ 解决：通知方式里**一定勾上失败告警**。最好分开通知——成功发到组群，失败发到你个人（比如飞书私信或者邮件）。永远不要让失败静默。

**坑 2：自动化跑得太多，token（API 调用量）消耗爆表**
→ 解决：在 Settings → Usage 里能看到每个自动化任务的 token 消耗。优化方法：
- 输入文件夹不要放无关文件（Codex 会读所有文件，每个文件都算 token）
- 复杂的 Skill 拆成两步：先用一个 Skill 筛资料，再用一个 Skill 生成报告
- 周报这种固定模板，加一句「输出控制在 600 字以内」减少输出 token

**坑 3：定时任务到了但电脑没开机，任务就跳过了**
→ 解决：Codex 桌面端的自动化任务需要客户端在线。如果你周一可能不在工位，把 Codex 设置成「开机自启 + 保持后台运行」（macOS 在「系统设置 → 通用 → 登录项」里加 Codex；Windows 在「设置 → 应用 → 启动」里加）。更稳妥的做法是把自动化任务绑定到一台固定的、长期开机的办公电脑上。

**坑 4：夏令时 / 时区切换后，任务跑的时间变了**
→ 解决：cron 表达式一定要配时区（不要用系统默认）。在 Settings → General → Timezone 里确认你的时区是 `Asia/Shanghai`。如果你的团队分布在多个时区，用 UTC 时间配 cron（北京时间 9 点 = UTC 1 点，即 `0 1 * * 1`）。

**坑 5：自动化跑出来的周报老板看了不满意，说「和上周格式不一样」**
→ 解决：把 prompt 写得更死。比如周报模板里直接写死表格的列名、固定的章节顺序。越死板越稳定。可变的内容用占位符（如「{{本周时间范围}}」），结构本身写死。
