# Skills：把常用任务打包成可复用工作流

> 每周都在重复输入同一段 prompt？把它录成 Skill，下次一键就跑。

## 🎬 场景故事

小李是用户增长组的运营。每周一上午，他要做三件事：

1. 把上周的用户反馈 Excel 整理成摘要
2. 从飞书妙记导出上周所有会议，整理成周报素材
3. 把上周的活动数据生成一张趋势图

这三件事他每周都要做，每次都要重新输入一大段 prompt，复制粘贴、调整参数、等结果——光输入就要花 20 分钟。

有一天他发现 Codex 桌面端有个叫 **Skills**（技能）的功能：把「prompt + 输入文件夹 + 输出格式」打包成一个按钮，下次只要点一下就自动跑完。

从此他的周一早上多出了 20 分钟，可以去喝杯咖啡。

## 🎯 你将学到

- 理解 Skills 是什么，为什么它比「保存 prompt 到备忘录」强
- 把现有重复任务打包成 Skill 的完整流程
- 3 个运营高频场景的 Skill 模板（周报、活动复盘、竞品监控）
- 把 Skill 共享给团队成员的方法

预计花 25 分钟。看完你就能把自己最常做的那个任务变成一键按钮。

## 📋 前置准备

- 已安装并登录 Codex 桌面端（macOS 或 Windows 均可）
- 已经做过至少 1 次「完整任务」（读过资料、输出过结果的那种）
- 想清楚一件事：**你最近 3 个月里，哪一个任务重复做了至少 5 次**？把它挑出来当今天的练习对象
- 准备好这个任务对应的资料文件夹路径（比如 `~/Documents/周报素材/`）

## 🚀 操作步骤

### Step 1：打开 Skills 面板

> 👀 **这里你会看到**：
> 1. Codex 桌面端左侧栏点击「≡」展开菜单
> 2. 在菜单里找到「Skills」（图标是 ⚡️ 闪电）
> 3. 点击进入 Skills 面板，顶部有一个「+ New Skill」按钮

如果你看不到「Skills」菜单，说明你的版本还没更新到最新版——去 [OpenAI Codex 官网](https://openai.com/codex/) 下载最新版。

### Step 2：录制你的第一个 Skill

点击「+ New Skill」后，你会看到一个表单：

> 👀 **这里你会看到**（表单字段）：
> - **Skill 名称**（必填）：给这个 Skill 起个名字
> - **描述**（选填）：一句话说清楚它干什么
> - **触发 prompt**（必填）：就是那段你每次都要复制粘贴的 prompt
> - **输入文件夹**（选填）：自动挂载的资料路径
> - **输出位置**（选填）：结果默认存到哪里
> - **触发方式**（必选）：手动按钮 / 快捷键 / 定时

先填名称。比如：「周报生成器」。

然后把那段你每次都要复制粘贴的 prompt 完整贴进「触发 prompt」框里。

> 💡 **小贴士**：prompt 里如果有占位符（比如「读取 {{本周}} 的数据」），直接写中文说明就行，比如「读取最近 7 天的数据」。Codex 每次执行时会自动按当前时间替换。

### Step 2.5：如果流程很难描述，就录给 Codex 看

有些任务不是一句 prompt 能说清楚的。比如「登录某个后台 → 点到报表页 → 选择上周时间 → 下载 Excel → 改文件名 → 放进固定文件夹」。这种流程更适合用 **Record & Replay**（录制与重放）：你在 Mac 上实际操作一遍，Codex 观察这段流程，再把它整理成一个可复用 Skill。

适合录制的流程有三个特点：

- 步骤稳定：每次按钮位置、页面路径、输出格式差不多
- 输入会变：这次下载 7 月数据，下次下载 8 月数据
- 用文字描述麻烦：你自己做一遍只要 3 分钟，写 prompt 却要写半页

操作时，在 Skills 面板里打开「+」菜单，选择「Record a skill」。录制前先告诉 Codex 你的目标和哪些参数以后会变，比如「日期范围每次不同」「文件名按月份命名」。录完后让 Codex 把生成的 Skill 再整理一遍，重点检查：触发条件、输入参数、成功标志、失败时怎么处理。

> 💡 **小贴士**：录制时不要带入真实密码、客户名单、未公开报表。需要登录的系统，提前登录好再开始录制；需要演示数据，用测试账号或脱敏文件。

### Step 3：设置输入文件夹和输出位置

在「输入文件夹」里填你每次都要喂给 Codex 的资料路径。比如：

```
~/Documents/周报素材/
```

Codex 每次执行这个 Skill 时，会自动读取这个文件夹里的所有文件，不用你每次再手动选一次。

「输出位置」可以填：

- `~/Documents/周报输出/`：保存成 Markdown 文件
- 「直接显示在对话框」：不存文件，看完即丢
- 「发送到飞书群」（需要先在 Settings 里绑定飞书机器人）

### Step 4：测试你的 Skill

保存后，回到 Skills 面板，点击这个 Skill 右侧的「▶ Run」按钮（一个三角形播放图标）。

Codex 会按照你录制的 prompt 完整跑一遍。你检查一下：

- ✅ 输入文件夹对不对
- ✅ prompt 是否被完整执行
- ✅ 输出位置是否符合预期

如果哪里不对，点「✏️ Edit」直接修改 prompt，不用删了重建。

### Step 5：把它共享给团队（可选）

如果你想让组里其他人也能用这个 Skill：

> 👀 **这里你会看到**：
> 1. 在 Skill 详情页右上角找到「Share」按钮
> 2. 选择「Publish to Team Library」（发布到团队库）
> 3. 选择目标团队 / 群组
> 4. 点击「Publish」

发布后，团队成员的 Skills 面板里会自动出现这个 Skill，他们也能一键用。

> 💡 **小贴士**：团队 Skill 是「只读共享」——别人能用但不能改你的原版。如果他们想基于你的版本做调整，可以点「Fork」（复制一份到自己的空间里改）。

## 📝 完整 Skill 模板

### 模板 1：周报生成 Skill

**适用场景**：每周一自动整理上周的用户反馈、运营数据、会议纪要，生成周报初稿。

**Skill 配置**：

- **名称**：`周报生成器`
- **输入文件夹**：`~/Documents/周报素材/`（里面放 Excel 数据 + 妙记导出的 txt）
- **输出位置**：`~/Documents/周报输出/周报_YYYY-MM-DD.md`

**触发 prompt**（完整可复制）：

```
你是一名用户增长组的运营助理。

请读取「~/Documents/周报素材/」文件夹里的所有文件：
- *.xlsx 或 *.csv：本周的用户反馈数据 / 运营数据
- *.txt：本周的飞书妙记导出文本

按以下结构生成一份周报：

# 本周周报（日期范围：{{最近 7 天}}）

## 一、数据概览
- 新增用户数、活跃用户数、转化率（用表格）
- 与上周对比，标注涨跌幅

## 二、用户反馈摘要
- 列出 Top 5 高频反馈问题
- 每条问题附上 1-2 个原始用户原话（保持口语化，不要润色）

## 三、会议要点
- 从妙记文本里提取本周开过的会议
- 每个会议 1 句话总结 + 待办事项列表

## 四、下周重点
- 基于本周数据，建议下周关注 3 个方向

要求：
- 语言简洁，避免空泛黑话
- 数据用表格呈现，不要写成大段文字
- 输出 Markdown 格式，方便直接粘贴到飞书文档
```

**预期输出**：一份 500-800 字的 Markdown 周报，包含表格和数据对比。

**调优提示**：
- 如果输出太长 → 在 prompt 里加「总字数控制在 600 字以内」
- 如果想加图表 → 加一句「数据概览部分用 Mermaid 折线图呈现 4 周趋势」

### 模板 2：活动复盘 Skill

**适用场景**：每次活动结束后，整理活动数据 + 参与反馈，生成复盘报告。

**Skill 配置**：

- **名称**：`活动复盘生成器`
- **输入文件夹**：`~/Documents/活动复盘/活动名_日期/`
- **输出位置**：直接显示在对话框（复盘报告需要当场讨论修改）

**触发 prompt**（完整可复制）：

```
你是一名市场运营，负责撰写活动复盘报告。

读取「~/Documents/活动复盘/活动名_日期/」文件夹里的所有资料，按以下结构生成复盘：

# 活动复盘：[活动名称]

## 一、活动概览
- 活动目标
- 实际参与人数 vs 目标人数（达成率）
- 活动时间 / 渠道 / 主推产品

## 二、数据表现
| 指标 | 目标 | 实际 | 达成率 |
|------|------|------|--------|
| 参与人数 | ... | ... | ...% |
| 转化人数 | ... | ... | ...% |
| GMV | ... | ... | ...% |

## 三、用户反馈亮点
- Top 3 正向反馈（附原始用户原话）
- Top 3 负向反馈（附原始用户原话）

## 四、踩坑记录
- 这次活动踩了哪些坑？每个坑给出改进建议

## 五、可复用的经验
- 哪些做法下次活动可以继续用？

要求：
- 数据说话，不要用「效果很好」「反响热烈」这种空话
- 踩坑部分要诚实，不回避问题
```

**调优提示**：
- 如果活动类型不同（线上 vs 线下）→ 复制这个 Skill 改名为「线上活动复盘」「线下活动复盘」分别保存
- 如果想加截图 → 在 prompt 里说「在合适位置插入图片占位符：[图片：xxx]」

### 模板 3：竞品监控 Skill

**适用场景**：每周监控 3-5 家竞品的官网更新、公众号发文，生成对比周报。

**Skill 配置**：

- **名称**：`竞品监控周报`
- **输入文件夹**：`~/Documents/竞品监控/`
- **输出位置**：`~/Documents/竞品周报/竞品周报_YYYY-MM-DD.md`

**触发 prompt**（完整可复制）：

```
你是竞品分析助理。

读取「~/Documents/竞品监控/」文件夹里的资料：
- 竞品A_本周更新.md：竞品 A 的官网更新、公众号发文截图 OCR
- 竞品B_本周更新.md：竞品 B 同上
- 竞品C_本周更新.md：竞品 C 同上

按以下结构生成竞品监控周报：

# 竞品监控周报（{{最近 7 天}}）

## 一、竞品动态一览

| 竞品 | 产品更新 | 营销动作 | 定价变化 |
|------|----------|----------|----------|
| A    | xxx      | xxx      | xxx      |
| B    | xxx      | xxx      | xxx      |
| C    | xxx      | xxx      | xxx      |

## 二、重点关注
- 竞品 X 做了 Y 动作，对我们的潜在影响是...

## 三、值得借鉴
- 竞品 X 的 Z 做法，建议我们评估是否跟进

## 四、警示信号
- 竞品 X 正在做 Y，可能在抢我们的某块市场

要求：
- 每条结论都要附资料来源（哪个文件、哪一段）
- 不要编造没在资料里出现的信息
```

**调优提示**：
- 监控竞品数量变化 → 修改 prompt 里的「竞品 A/B/C」列表
- 想监控的频率变高 → 把 Skill 关联到「自动化任务」（见下一章）

## ⚠️ 常见坑

**坑 1：Skill 越攒越多，后来自己都找不到**
→ 解决：每做 5 个 Skill 就回头整理一次。命名加前缀分类，比如「周报-销售周报」「周报-用户周报」「活动-线上」「活动-线下」。Skills 面板支持搜索，输入关键词秒定位。

**坑 2：两个 Skill 触发条件冲突，按快捷键时不知道跑哪个**
→ 解决：快捷键不要复用。如果非要复用，改成手动点击触发。定时触发的 Skill 一定要给一个明确的名字带时间标识（比如「周一早9点-销售周报」），避免和别的 Skill 撞时间。

**坑 3：共享给团队的 Skill，别人改了 prompt 我不知道**
→ 解决：团队 Skill 一旦发布就是「锁定版」，别人改了会创建 Fork，不会污染你的原版。但如果你想监控大家的使用情况，在 Skill 详情页看「Usage Stats」（使用统计），能看到谁在用、用了多少次。

**坑 4：Skill 里硬编码了路径，换台电脑就用不了**
→ 解决：路径用 `~/Documents/xxx/` 这种「波浪号开头」的写法，不要写绝对路径 `/Users/张三/Documents/xxx/`。波浪号会自动展开成当前用户的 home 目录。
