# 9. 多源信息归总模式：把行业趋势股票头条热点自动归类

> 每天扫 200 条信息，分类整理花 2 小时？扔给 Codex，按 4 类自动归总成简报。

## 🎬 场景故事

小张是某投资机构的行业分析师。她每天要扫的信息源包括：

- **行情类**：Wind / 同花顺推送的公告、研报、新闻
- **监管类**：证监会、央行、行业监管文件
- **财经媒体**：财新、华尔街见闻、彭博中文
- **社交媒体**：雪球热帖、X 推文、微博热搜

每天 200+ 条信息进来，她要：
1. 一条条点开看
2. 判断这条属于"行业趋势 / 具体股票 / 头条 / 热点"哪一类
3. 提炼摘要
4. 分类归档

**每天整理 2 小时，剩下时间才做正经分析**。

直到她发现 Codex 可以**批量接收 + 自动归类**——她每天的活从"扫 200 条"变成"校对 1 份 30 条的简报"。

整理时间从 2 小时 → 20 分钟。

## 🎯 你将学到

- 什么是「多源信息归总」——把零散信息按 4 个主题维度自动归类
- 4 类信息的判断标准：行业趋势 / 具体股票 / 头条信息 / 热点
- 一个完整可用的「每日信息简报」案例
- 跟 Wind、财新、雪球、推特等信源的集成方法
- 进阶用法：定时跑 / /goal 持续跟踪 / 跟个人分析规范结合

预计 30 分钟。搭好以后**每天省 1.5 小时**。

## 📋 前置准备

- **必读**：先看完 [1. Skills](../03-进阶技巧/01-skills.md)、[3. 项目记忆](../03-进阶技巧/03-项目记忆.md) 和 [8. 分析规范模式](../03-进阶技巧/08-分析规范模式-把个人方法论做成Skill.md) 三章——本篇是组合应用，不重复讲基础
- 已安装 Codex 桌面端 2026 GA 版
- 准备一个工作目录：`~/brief/`
- 准备一批原始信息（10-30 条），格式不限：链接 / 截图 / 文字 / 微信转发的文章

## 🚀 三步搭建法

### Step 1：纸面梳理（5 分钟）—— 你的 4 类信息是什么

在 Obsidian / 备忘录里回答 3 个问题：

| 问题 | 示例回答 |
|-----|--------|
| 我日常处理的信息有**哪 4 类**？ | 行业趋势 / 具体股票 / 头条信息 / 热点 |
| **每类的判断特征**是什么？ | "赛道/政策"=趋势；"代码/股票名/财报"=股票；"突发/重大"=头条；"爆款/热搜/KOL"=热点 |
| **每条信息要保留什么字段**？ | 标题 + 1 句摘要 + 来源 + 时间 |

### Step 2：写 AGENTS.md（5 分钟）—— 沉淀归类规则

在 `~/brief/` 根目录建 `AGENTS.md`：

```markdown
# 多源信息归总规范

## 4 类信息及判断特征

### 1. 行业趋势（宏观 + 中观）
- **特征**：含"行业 / 赛道 / 政策 / 监管 / 周期 / 技术演进"等词
- **典型来源**：行业协会、监管文件、券商研报、宏观数据
- **保留字段**：行业名 + 关键变化 + 影响判断

### 2. 具体股票（个股动态）
- **特征**：含"股票代码 / 公司名 / 财报 / 公告 / 业绩预告"
- **典型来源**：上市公司公告、交易所、Wind 公告流
- **保留字段**：股票代码 + 公司名 + 事件类型（财报 / 公告 / 异常波动）+ 关键数字

### 3. 头条信息（重大事件）
- **特征**：含"突发 / 重大 / 官方 / 监管 / 影响全市场"
- **典型来源**：财新、彭博、央行 / 证监会 / 工信部 公告
- **保留字段**：事件 + 影响范围 + 紧急程度

### 4. 热点（社交 / 舆论）
- **特征**：含"爆款 / 热搜 / 高互动 / KOL / 讨论 / 出圈"
- **典型来源**：雪球热帖、X 推文、微博热搜、知乎热榜
- **保留字段**：话题 + 讨论度 + 代表观点

## 输出格式（严格 4 段）
## 行业趋势
- **【行业】标题**（来源 / 时间）
  1 句摘要

## 具体股票
- **【代码 公司】事件**（来源 / 时间）
  1 句摘要

## 头条信息
- **【紧急度 ★★★】事件**（来源 / 时间）
  1 句摘要

## 热点
- **【话题】讨论焦点**（来源 / 时间 / 互动量）
  1 句摘要

## 禁止
- 不属于这 4 类的信息 → 放进"杂项"段，不强行分类
- 同一事件多源时只保留最权威的 1 条
- 客户/上市公司未公开的内部消息不归档
- 社交媒体未经证实的内容标注"未证实"
```

Codex 每次打开 `~/brief/` 会自动读这份规则。

### Step 3：封装成 Skill（2 分钟）—— 一键调用

在 Codex 对话里输入 `/`，选 **+ New Skill**：

```yaml
name: 信息简报
description: 把零散信息按 4 类自动归总成每日简报
trigger: /newsroom
inputs:
  - 信息源（粘贴文本 / 文件路径 / 文件夹路径）
steps:
  - 读取当前 AGENTS.md 的 4 类规则
  - 解析输入的每条信息
  - 按 4 类归类，输出严格 4 段
  - 同一事件多源只保留最权威 1 条
  - 不属于 4 类的放进"杂项"
```

```
/newsroom inbox/2026-08-06-raw.md
```

## 进阶玩法

**① 定时跑 / /goal 持续跟踪**

把 `/newsroom` 升级成每日定时任务：

```
/goal 每天 18:00 跑 /newsroom

输入：~/brief/inbox/ 当天所有 .md 文件
输出：~/brief/briefing/YYYY-MM-DD.md
跑完在飞书给我发个摘要：今日 X 条趋势 / Y 条股票 / Z 条头条 / W 条热点
```

这样你**完全不用手动触发**，每天 18:30 打开飞书就看到简报。

**② 跟分析规范模式结合（08 章）**

跑完 `/newsroom` 后，自动用你的**个人分析规范**做深度分析：

```
/newsroom inbox/2026-08-06-raw.md
分析：读 briefing/2026-08-06.md，按 3 视角 + 3 行动 框架给一份投资建议
```

等于把 09 章和 08 章串起来用：09 做"信息归集"，08 做"决策分析"。

**③ 跟 Inbox 模式结合**

把抓来的原始信息先用 Inbox 模式分一次（粗分），再用 `/newsroom` 精分到 4 类——两层过滤更准。

**④ 按主题拆分 Skill**

不同主题用不同 Skill：

- `/newsroom-tech`（科技股版）：4 类里更细的子分类
- `/newsroom-macro`（宏观版）：重点是政策 + 数据
- `/newsroom-crypto`（加密货币版）：热点权重更高

每个 Skill 一份独立 AGENTS.md，规则不串台。

## ⚠️ 常见坑

**坑 1：信息源格式混乱，Codex 解析失败**
- 症状：微信转发的文章含乱码 / 截图 OCR 错误
- 解决：先用 Inbox 模式粗整理一次（提取纯文本），再喂给 `/newsroom`

**坑 2：Codex 把同一事件归到多类**
- 症状："证监会新规"既出现在"行业趋势"也出现在"头条"
- 解决：AGENTS.md 加规则「同一事件只保留最权威 1 条，优先放"头条"」

**坑 3：股票代码识别错误**
- 症状：把"300750"认成别的股票
- 解决：AGENTS.md 明确「股票代码 6 位数字 = A 股；HK 开头 = 港股；美股用字母」

**坑 4：未公开信息被归档**
- 症状：客户内部消息、上市公司未披露的研报判断被收录到简报
- 解决：AGENTS.md 加「只归档公开信息；标"未证实"的内容不进入决策池」

**坑 5：社交媒体谣言被当事实**
- 症状：把 X 上的"听说 XX 公司要被收购"当真
- 解决：AGENTS.md 强制「社交媒体类必须标"未证实"，并写明信源」

**坑 6：4 类规则太死，覆盖不全**
- 症状：很多信息找不到对应类别
- 解决：保留"杂项"段作为兜底，定期复盘"杂项"里有哪些该独立成新类
