# 8. 分析规范模式：把个人方法论做成 Codex Skill

> 你脑子里有一套「我分析问题的方式」，但每次让 Codex 跑都要重说一遍？把它写进 AGENTS.md + Skill，永久生效。

## 🎬 场景故事

小周是某 SaaS 公司的市场调研负责人。她做竞品分析有一套自己打磨了 3 年的方法论：

> "**3 视角 + 3 行动**"——每个竞品必须从用户、商业、技术三个视角看一遍，末尾给老板 3 条可落地的建议。**只关注最近 3 个月的动态，500-800 字封顶，不堆功能列表。"

但每次她让 Codex 帮忙做这事，问题都出在同一个地方：

- 有时候 Codex 输出 2000 字
- 有时候 Codex 罗列 20 个功能特性
- 有时候 Codex 写"综合来看，Cursor 是一款优秀的产品"这种空话
- 她每次都要在 prompt 里重打一遍方法论，还要事后改 3 遍

**她意识到问题不在 Codex，在她没把方法论交给 Codex**。

## 🎯 你将学到

- 什么是「分析规范模式」——一种把"个人方法论"沉淀成 Codex 规则的组合拳
- 三步搭建法：纸面梳理 → AGENTS.md 沉淀 → 封装 Skill
- 一个完整可用的「竞品分析」实战案例
- 3 个调优技巧，让 Codex 越用越准
- 多个分析类型怎么拆分（不要一个 Skill 通吃）

预计 30 分钟。搭好以后你每次做这类任务**省 5-10 分钟 + 减少 80% 返工**。

## 📋 前置准备

- **必读**：先看完 [1. Skills](../03-进阶技巧/01-skills.md) 和 [3. 项目记忆（AGENTS.md）](../03-进阶技巧/03-项目记忆.md) 这两章——本篇不重复讲基础
- 已安装 Codex 桌面端 2026 GA 版
- 准备一个测试目录：`~/test-analysis/`
- 准备一份竞品资料（PDF / 截图 / 链接都行，5-10 个文件足够）

## 🚀 三步搭建法

### Step 1：纸面梳理（5 分钟）—— 你的规范是什么

在 Obsidian / 备忘录里回答 5 个问题，**别直接上 Codex，先用纸面写清楚**：

| 问题 | 示例回答 |
|-----|--------|
| 我做这类分析的角色是？ | "市场调研负责人，给老板做判断" |
| 必看的几个角度？ | 用户 / 商业 / 技术 |
| 产出的长度 / 格式？ | 500-800 字、3 段 + 3 条建议 |
| 啥不能写？ | 不堆数据 / 不写空话 / 不超 800 字 |
| 我自己最爱用的判断框架？ | 差异化机会 + 威胁点 + 不值得打的点 |

> 💡 **小贴士**：这一步是整套方法的灵魂。如果你写不清楚，Codex 也不可能跑得清楚。**先在纸面打磨 3 次再往下走**。

### Step 2：写 AGENTS.md（5 分钟）—— 沉淀项目级规则

在测试目录 `~/test-analysis/` 根目录建 `AGENTS.md`，把 Step 1 的回答整理成机器能读的格式：

```markdown
# 竞品分析专用规范

## 你的角色
你是资深竞品分析师，熟悉 SaaS / 前端工具赛道，给市场负责人做决策支持。

## 分析框架（缺一不可）
1. **用户视角**：竞品解决了谁的什么问题，体验好不好
2. **商业视角**：定价、目标客户、增长策略、护城河
3. **技术视角**：技术栈、性能、特色功能、技术债

## 产出规范
- 长度：500-800 字
- 格式：1 段结论 + 3 个视角各 1 段 + 末尾 3 条行动建议
- 风格：给老板看的，少用术语
- 时效：只关注最近 3 个月动态
- 必须包含：差异化机会 + 威胁点 + 不值得打的点

## 禁止
- 不罗列功能列表
- 不写"综合来看 / 综上所述"这种空话
- 不超过 800 字
- 不用"赋能 / 闭环 / 抓手 / 底层逻辑"等黑话
- 不引用未提供的数据来源
```

Codex 每次打开这个目录会自动读这份规则——不用每次提醒。

### Step 3：封装成 Skill（2 分钟）—— 一键调用

在 Codex 对话里输入 `/`，选 **+ New Skill**：

```yaml
name: 竞品分析
description: 按 [3 视角 + 3 建议] 框架分析单个竞品，给老板看的简报
trigger: /competitor
inputs:
  - 竞品名（如 Cursor / Figma / Linear）
steps:
  - 读取当前 AGENTS.md 的"竞品分析专用规范"
  - 从"竞品资料/{竞品名}/"目录读取所有材料
  - 按 3 视角框架分析
  - 输出 500-800 字简报
  - 末尾给 3 条具体行动建议
```

## 实战演示

把竞品资料放到 `~/test-analysis/竞品资料/Cursor/` 下，然后在 Codex 桌面端开这个目录，直接：

```
/competitor Cursor
```

Codex 会自动完成 5 件事：读 AGENTS.md → 读资料 → 按 3 视角分析 → 输出 800 字简报 → 给 3 条建议。**整个过程你不用再说任何规则**。

## 3 个调优技巧

**① 跑几轮，规范才能稳**

第一次跑完你会发现"哎它没遵守 X 规则"。在对话里直接说：

> "刚才输出 850 字了，超过规范了；下次严格 800 字以内"

Codex 这次会话内会立刻改。**要永久生效，必须改 AGENTS.md**——会话内的反馈不写到文件里就丢了。

**② 把反面教材也写进规范**

跑出来不好的部分直接贴到 AGENTS.md 当 ❌ 示例，比单写规则管用 10 倍：

```markdown
## 反面教材（不要这样写）
- ❌ "Cursor 整体表现优秀，各方面都很出色" —— 这是空话
- ❌ "支持 50+ 编程语言，提供智能补全功能" —— 这是功能罗列
- ❌ "综合来看，Cursor 是值得关注的竞品" —— 这是空结论
```

**③ 一个分析类型一个 Skill，不要通吃**

| Skill | 触发 | 适用场景 |
|------|------|---------|
| `/competitor` | 竞品深挖 | 单个竞品详细分析 |
| `/market-trend` | 行业趋势 | 赛道风向、宏观判断 |
| `/user-research` | 用户反馈汇总 | 多份反馈提炼洞察 |
| `/retro` | 项目复盘 | 项目结束后的总结 |

每个 Skill 配一份独立 AGENTS.md，**规范不串台**。

## ⚠️ 常见坑

**坑 1：规范写得太抽象**
- 症状：Codex 看了规范但不知道具体怎么做
- 解决：规则必须**可判断**——"500-800 字" ✅，"简洁精炼" ❌

**坑 2：规则堆太多，Codex 记不住**
- 症状：规范写到 200 行，Codex 反而挑着遵守
- 解决：**控制在 100 行以内**，复杂的拆成多个 Skill

**坑 3：从不更新规范**
- 症状：3 个月前写的规范跟现在的业务已经不匹配
- 解决：每次跑完任务花 1 分钟看输出，**有偏差就立刻改 AGENTS.md**

**坑 4：把客户隐私写进规范**
- 症状：客户真实数据进了 AGENTS.md，可能被 Codex 上传到云端
- 解决：见 [1. 数据安全](../04-安全红线/01-数据安全.md)，AGENTS.md 里只放**方法论**，不放**真实数据**

**坑 5：期待"一次配好永久生效"**
- 症状：搭完就不管了，半个月后发现 Codex 输出越来越离谱
- 解决：规范是**活文档**，每 2 周复盘一次
