# Sites：把运营成果做成内部工具

> 不只是生成一份报告，还能把报告变成团队可以访问、筛选、更新的小网页。

## 🎬 场景故事

小陈负责活动运营。每次大促结束，她都会整理报名表、渠道数据、用户反馈，再写一份复盘报告发到群里。问题是，报告发出去当天大家会看，过两周再想查「某个渠道当时表现怎么样」就很难找。

后来她让 Codex 用 **Sites** 做了一个活动复盘看板：左边按活动筛选，右边展示报名人数、转化率、反馈摘要和复盘结论。老板看结果不用翻文档，同事补充信息也不用改一堆表格。

这类东西不用当成「官网」。对运营来说，Sites 更像一个能分享的内部小工具。

## 🎯 你将学到

- 判断哪些运营成果适合做成 Site
- 用 Codex 把表格、报告、资料夹变成可访问的小网页
- 写一段完整 prompt，让 Codex 生成活动复盘看板
- 发布前检查权限、数据和敏感信息

预计花 25 分钟。适合已经会让 Codex 整理资料、生成报告的同学。

## 📋 前置准备

- 已安装并登录 Codex 桌面端，或能访问 ChatGPT Work
- 准备一份结构化资料，比如 Excel、CSV、Markdown 报告、活动复盘文档
- 想清楚这个 Site 给谁看：只给自己、给团队、还是给整个公司
- 确认资料里没有客户手机号、身份证号、合同金额等敏感信息

## 🚀 操作步骤

### Step 1：先判断要不要做成 Site

不是所有内容都值得做成网页。下面这些适合：

- 需要反复查看：活动复盘库、竞品监控台、项目进度看板
- 需要筛选对比：不同渠道、不同活动、不同时间段的数据
- 需要多人访问：老板、项目组、跨部门同事都要看
- 需要持续更新：每周或每月追加新数据

不适合的内容：

- 一次性汇报，发完就结束
- 涉及敏感数据，权限还没理清
- 只是 300 字摘要，飞书消息就能讲清楚

### Step 2：把资料放到一个清楚的文件夹

建议为每个 Site 单独建一个资料夹，比如：

```
~/Documents/运营Sites/活动复盘看板/
```

里面可以放：

- `活动数据.xlsx`：报名、到场、转化、渠道数据
- `用户反馈.csv`：问卷或社群反馈
- `复盘结论.md`：你已经写好的文字结论
- `字段说明.md`：告诉 Codex 每一列是什么意思

> 💡 **小贴士**：字段说明很有用。比如「渠道成本」到底是含税还是不含税，「转化用户」是下单还是留资，提前写清楚，Codex 做出来的看板会稳很多。

### Step 3：让 Codex 生成 Site

在 Codex 或 ChatGPT Work 里新建任务，选择这个资料夹，然后直接说明你要一个内部工具，而不是一份报告。

你可以这样写：

```
请读取当前文件夹里的活动数据、用户反馈和复盘结论，帮我生成一个活动复盘看板 Site。

使用对象：活动运营组和增长负责人。

核心功能：
1. 左侧可以按活动名称、渠道、月份筛选
2. 顶部展示核心指标：报名人数、到场人数、转化人数、转化率、渠道成本
3. 中间用表格展示每场活动的表现，并标出高于平均值和低于平均值的活动
4. 右侧展示用户反馈摘要，按正向反馈、负向反馈、待改进建议分组
5. 每场活动点开后，可以看到复盘结论和下次行动建议

要求：
- 页面给运营同事日常查看，不要做成营销落地页
- 信息密度高一点，方便横向对比
- 不展示任何手机号、邮箱、客户姓名等个人信息
- 先生成预览，不要直接公开发布
```

### Step 4：检查预览，不急着发布

Site 生成后，先看三件事：

- **数据是否对**：随机抽 3 行表格，对照原始 Excel 看数字有没有错
- **权限是否窄**：先设置成只有自己或指定同事可访问
- **内容是否干净**：搜索手机号、邮箱、客户名、内部价格等敏感信息

如果需要改，直接对 Codex 说：

```
请调整这个 Site：
1. 隐藏「客户姓名」和「手机号」两列
2. 把渠道筛选放到页面顶部
3. 增加一个「只看转化率低于平均值的活动」筛选
4. 发布前继续保持仅我可见
```

### Step 5：保存版本，再决定要不要部署

Sites 通常有「保存版本」和「部署」两个动作。保存版本像是存一个候选稿，部署才是让别人通过链接访问。

给团队看之前，先让 Codex 保存一个版本，并把访问范围设窄：

```
请保存当前 Site 版本，但先不要公开发布。
保存后告诉我：
1. 当前版本包含哪些页面和功能
2. 访问权限是什么
3. 还有哪些数据安全风险需要我人工确认
```

确认没问题后，再改成团队可访问。

## 📝 完整 Prompt 模板

**适用场景**：把活动复盘、竞品监控、项目进度表做成内部看板。

**完整 prompt**：

```
请基于当前文件夹资料，生成一个给运营团队使用的内部 Site。

使用对象：[写清楚谁会看，比如活动运营组、增长负责人、客服主管]
核心目标：[写清楚这个 Site 要解决什么问题]
资料来源：[列出文件名和每个文件的用途]

页面功能：
1. 支持按 [字段 A]、[字段 B]、[时间范围] 筛选
2. 顶部展示 [3-5 个核心指标]
3. 主区域展示明细表，支持排序和搜索
4. 详情区域展示结论、风险和下一步行动
5. 如果发现数据缺失，请在页面里标记「待补充」，不要自行编造

权限与安全：
- 先生成预览，不要公开发布
- 不展示个人手机号、邮箱、身份证号、客户姓名
- 如果需要展示敏感字段，先向我确认

风格要求：
- 像内部工作台，不要像营销落地页
- 信息清楚、方便扫读、适合每天打开看
```

**预期输出**：一个可预览的内部看板 Site，以及一份发布前检查清单。

## ⚠️ 常见坑

**坑 1：把 Site 当官网做，页面很漂亮但不好用**
→ 解决：运营内部工具要重视筛选、表格、搜索、指标卡。不要让 Codex 做大标题、大海报、大段宣传文案。

**坑 2：一生成就公开分享**
→ 解决：先只给自己看。检查数据、权限和敏感字段后，再开放给团队。

**坑 3：数据更新后，看板还是旧的**
→ 解决：把资料文件夹、更新频率和更新责任人写清楚。如果每周都要更新，可以结合 [自动化任务](02-自动化任务.md) 定期刷新资料。

**坑 4：团队不知道这个 Site 该怎么看**
→ 解决：在页面顶部放一个很短的说明，比如「用于查看 2026 年活动复盘表现，数据每周一更新」。说明要短，不要写成长篇教程。
