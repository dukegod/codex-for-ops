# 异常处理：Codex 翻车了怎么办

> 这一章给你一份「Codex 翻车速查表」。卡死、跑偏、编造数据、误删文件——5 种常见异常，每种都有标准应对流程（SOP）。

## 🎬 场景故事

小张让 Codex 「帮我分析这周的 8 份竞品周报，生成对比表」。20 分钟后 Codex 返回了一个看起来很专业的对比表。但小张抽查发现：

- 表里有一家公司「周活用户 500 万」，原始周报里根本没这个数字
- 有一家公司的「上线时间」是 2024 年，但实际是 2026 年
- 对比表里多了一家「竞品 D」，原始资料里完全没出现过

Codex 把「看起来合理」的东西编造了出来。这就是典型的 AI 幻觉（Hallucination，即 AI 一本正经地胡说八道）。

**如果小张直接把这个表发给老板，就出事了。**

## 🎯 你将学到

- 5 种 Codex 常见异常的应对 SOP
- 怎么从「Codex 翻车」里快速恢复
- 怎么建立自己的「Codex 翻车速查表」

## 📋 前置准备

- 已经用过 Codex 几次
- 手边有一个跑飞了的任务可以练手

## 🚨 异常类型 1：Codex 卡住不动 / 一直转圈

**表现**：进度条停在某个位置不动了，或者输入框一直显示「thinking...」超过 10 分钟。

**应对 SOP**：

### Step 1：先等 5 分钟

Codex 处理大文件或复杂任务时，可能需要更长时间。先别急着重启。

### Step 2：取消当前任务

点界面上的「Cancel」（取消）按钮，或按 `Esc` 键。

### Step 3：简化 prompt 重试

原 prompt 可能太复杂。把任务拆成 2-3 个小任务：

- ❌ 「帮我分析 8 份周报生成对比表」
- ✅ 「先帮我提取这 8 份周报的关键数字，存成 CSV」→ 再来 → 「对比这个 CSV 生成表格」

### Step 4：检查文件大小

如果单文件 >100MB，先拆分。Codex 处理大文件效率会下降。

### Step 5：检查网络

Codex 默认需要联网。如果公司网络不好，连接会断。提示「rate limit」就是这种问题。

---

## 🚨 异常类型 2：生成内容跟预期完全不符

**表现**：你让 Codex 「总结用户反馈的痛点」，它返回了一份「产品功能介绍」。

**应对 SOP**：

### Step 1：用「约束式 prompt」让 Codex 重做

不要简单地说「再试一次」，要给具体约束。

### Step 2：明确告诉 Codex 「不要做什么」

大多数跑偏是因为 Codex 不知道边界。

### Step 3：检查输入文件

有时候不是 Codex 的问题，是你喂的资料里就有无关内容。

### Step 4：换一个任务重新开始

如果重试两次还是跑偏，建议放弃当前任务，重新建一个。

---

## 🚨 异常类型 3：生成内容有事实错误（幻觉）

**表现**：Codex 给的数字、人名、日期在原始资料里找不到。

**应对 SOP**：

### Step 1：永远人工核实关键数字

**这是最重要的一条**。Codex 编造的内容看起来非常合理，但经常是错的。

### Step 2：要求 Codex 标注数据来源

用下面的「数据溯源 prompt」让它告诉你每个数字是从哪里来的。

### Step 3：让 Codex 只引用、不发挥

明确告诉它「只能引用原文，不要自己总结」。

### Step 4：交叉验证

关键数字至少核对 2 个来源（比如原始文件 + 别的同事）。

---

## 🚨 异常类型 4：token 用得太快（5 小时额度用完）

**Token** 可以理解为 AI 处理文字的「计费单位」，每个字、每次 AI 思考都要消耗 token。ChatGPT Plus 每 5 小时有一个额度窗口。

**表现**：提示「You've reached your limit」「Rate limit exceeded」。

**应对 SOP**：

### Step 1：看右上角显示的恢复时间

Codex 桌面端会显示「额度在 XX:XX 重置」。

### Step 2：判断是临时额度还是套餐上限

- 「5 小时窗口用完」→ 等到下个 5 小时窗口
- 「月度额度用完」→ 升级套餐或等下个月

### Step 3：优化 prompt 减少 token 消耗

- 别一次性让 Codex 处理 50 个文件
- 大文件先预处理（提取关键部分）
- 避免让 Codex「重新做一遍」

### Step 4：用本地模型处理简单任务

如果公司有 Codex 本地模型部署，可以处理简单任务，不消耗云端额度。

---

## 🚨 异常类型 5：Codex 误删 / 误改文件

**表现**：你发现 Codex 改了一个不该改的文件，或者删了一个不该删的文件。

**应对 SOP**：

### Step 1：立即停止 Codex

点「Cancel」或关闭 Codex 桌面端。

### Step 2：用 worktree 隔离机制恢复

Codex 桌面端的 Auto-Edit 模式默认用 worktree（工作树，就是 Git 的一个隔离副本机制）。如果你用 Git 管理文件：

```
cd 你的项目目录
git status            # 看哪些文件被改了
git checkout -- 文件名  # 撤销单个文件
git stash             # 撤销所有改动
```

### Step 3：如果你没用 Git

- **Mac**：打开「Time Machine」（系统自带的时光机备份），回到任务前的版本
- **Windows**：右键文件 → 「以前的版本」
- **都没有**：看看 Codex 客户端的「Files Changed」（文件改动）面板，有时可以一键还原

### Step 4：分析原因，避免下次再犯

- 是 prompt 写得不明确？
- 是权限给得太大？
- 是没仔细看 diff 就点了「批准」？

## 📝 模板：约束式重做 prompt

**适用场景**：Codex 跑偏了，你想让它重做但要加约束。

**完整 prompt**：

```
重新做刚才的任务，但这次请严格遵守以下约束：

1. 只关注 [X 主题]，不要涉及 [Y 主题]
2. 输出格式必须是 [表格/Markdown/JSON]
3. 不要超过 [X 字 / X 行]
4. 所有数字必须从原文件引用，不要自己推断
5. 如果某项信息原文件里没有，写「无」不要编造

任务：[把原始任务描述复制过来]
```

**预期输出**：一个更聚焦、更可控的结果。

---

## 📝 模板：数据溯源 prompt

**适用场景**：你想知道 Codex 给的某个数字是从哪里来的。

**完整 prompt**：

```
你刚才的输出里，「XXX」这个数据是从哪里来的？

请告诉我：
1. 这个数据出现在原文件的哪一页 / 哪一行
2. 原文件的原文是怎么写的（直接引用）
3. 如果你无法定位到原文件，请明确告诉我「这是我推断的，不是原文件数据」
```

**预期输出**：精确的引用位置 + 原文，或者 Codex 承认这是它编的。

---

## 📝 模板：只引用、不发挥 prompt

**适用场景**：你只想让 Codex 整理资料，不想让它自由发挥。

**完整 prompt**：

```
请只做以下事情，不要做任何额外的分析或建议：

1. 把所有文件里出现的「关键数字」提取出来（用户数、营收、增长率等）
2. 按文件分组，每个数字标注来自哪个文件
3. 如果某个数字在不同文件里冲突，列出冲突

不要：
- 不要做趋势分析
- 不要给建议
- 不要补充原文件没有的信息
```

**预期输出**：一份纯提取的清单，没有 AI 的「发挥」。

## 📋 进阶：建一个 Codex 翻车速查表

建议你建一个 `~/Desktop/Codex翻车记录.md` 文件，每次遇到异常就记一行：

```
| 日期 | 异常类型 | 原因 | 解决方式 | 耗时 |
|------|---------|------|---------|------|
| 2026-06-15 | 跑偏 | prompt 没说要排除 X | 加了约束重做 | 10 分钟 |
| 2026-06-20 | 卡死 | 单文件 200MB | 拆成 3 个文件 | 5 分钟 |
```

记 10 条以上你就会发现：80% 的翻车都是同一类原因。

把这个速查表贴在工位上，新同事也能参考。

## ⚠️ 常见坑

- **坑 1**：反复重试同一个失败的 prompt → 解决：先简化 prompt，再换思路
- **坑 2**：相信 Codex 编造的「数据来源」 → 解决：永远自己去原文件核对
- **坑 3**：任务跑飞了还继续等，怕「浪费已花的 token」 → 解决：及时止损，token 沉没成本（已经花出去、收不回来的成本）不要再投入
- **坑 4**：误删文件后第一反应是责怪 Codex → 解决：用 git/Time Machine 恢复，然后复盘 prompt
- **坑 5**：网络不好时 Codex 反复重试，烧掉大量 token → 解决：网络差时先暂停 Codex 任务
