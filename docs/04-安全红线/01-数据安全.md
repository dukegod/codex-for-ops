# 数据安全：什么能给 Codex、什么不能

> 这一章帮你守住一条最重要的红线：哪些数据能喂给 Codex，哪些必须先脱敏，哪些绝对不能碰。

## 🎬 场景故事

小王是用户运营组的同事。某天她想分析一批客户投诉数据，就直接把客服系统导出的 Excel 丢进 Codex 桌面端，文件里包含 3000 条记录，每条都有客户的真实姓名、手机号、身份证后六位和家庭住址。Codex 帮她跑出了一份漂亮的分析报告——但问题来了：

- 这份 Excel 被上传到了 OpenAI 的服务端
- 数据穿过了国境，可能触发了《个人信息保护法》的跨境传输条款
- 有同事把这份分析结果截图发到了客户群里，里面的真实手机号没打码

第二天，法务找上门了。**不是 Codex 的错，是小王不该把原始客户数据直接喂进去。**

## 🎯 你将学到

- 哪些数据是绝对红线，绝对不能喂给 Codex
- 哪些数据要先脱敏再喂
- 怎么用一条 prompt 让 Codex 帮你自动脱敏
- 不同法规对运营工作的基本要求

## 📋 前置准备

- 一个 ChatGPT Plus 或 Pro 账号
- 你手头可能有敏感数据的那个文件夹

## 🚨 绝对不能喂的数据清单

下面这些数据，**任何情况下都不要直接喂给 Codex**。哪怕你只是让 AI 帮你看一眼也不行。

### 1. 客户个人隐私

- 身份证号、护照号、港澳台通行证
- 手机号、银行卡号、CVV（卡背面三位数）
- 家庭住址、工作单位、户籍信息
- 医疗记录、健康状况、病历
- 14 岁以下未成年人的任何信息

### 2. 未公开的财务数据

- 公司真实营收、成本、毛利、净利润
- 员工薪资、奖金、股权激励
- 投资人名单、融资条款、估值
- 任何带「内部」「未审计」标记的财报

### 3. 未发布的产品信息

- 产品 roadmap（路线图）
- 内部代号、未发布的功能细节
- A/B 测试的实验数据和结论
- 还在内测的版本号、灰度策略

### 4. 公司内部敏感文件

- 合同（特别是带对方公司公章的扫描件）
- 并购、融资、上市相关文件
- 人事变动、裁员、晋升名单
- 法律纠纷、诉讼、仲裁材料
- 内部安全漏洞、应急响应预案

### 5. 用户原始数据

- 含 PII（个人身份信息）字段的数据库导出
- 客服聊天记录、用户私信原文
- 用户上传的身份证照片、人脸数据

> 💡 **小贴士**：判断标准很简单——「如果这份数据泄露到网上，公司会被处罚吗？」如果会，就不要喂。

## ⚠️ 可以喂但必须先脱敏的数据

下面这些数据**本身有用**，但你必须先处理掉敏感字段再喂。

| 数据类型 | 脱敏方法 | 示例 |
|---------|---------|------|
| 客户姓名 | 替换成「客户 A」「客户 B」 | 张三 → 客户 A |
| 手机号 | 中间四位打码 | 13812345678 → 138\*\*\*\*5678 |
| 邮箱 | 用统一占位符 | zhangsan@xx.com → user@example.com |
| 身份证 | 只保留地区码 + 出生年 | 110101199001011234 → 110101\*\*\*\*\*\*\*\*1234 |
| 内部代号 | 替换成公开名 | 「星火计划」 → 「新产品 A」 |
| 地址 | 精确到城市 | 北京市朝阳区xx路1号 → 北京市朝阳区 |
| 金额 | 用相对值 | 1380 万 → 「千万级」 |

## ✅ 安全的资料类型

这些资料**可以直接喂**，不用担心：

- 公开的竞品官网、产品介绍、招股书
- 已经脱敏的统计数据、聚合报表
- 公司对外发布的新闻稿、官方介绍
- 公开的行业研究报告、券商研报
- 公开的招聘信息、财报摘要

## 🚀 操作步骤：让 Codex 帮你自动脱敏

### Step 1：先把原始文件放进一个独立文件夹

新建一个文件夹，比如 `~/Desktop/待脱敏/`，把所有敏感文件丢进去。不要让 Codex 直接读这个文件夹。

### Step 2：用脱敏 prompt 让 Codex 处理

打开 Codex 桌面端，「+ New Task」，只授权这个文件夹，然后粘贴下面的 prompt。

### Step 3：人工检查脱敏结果

Codex 可能漏掉一些边缘情况（比如「家庭电话」字段它可能没识别）。**这一步永远要人来做。**

### Step 4：把脱敏后的文件喂给真正的分析任务

脱敏后的文件可以放心用了。

## 📝 模板：通用数据脱敏 prompt

**适用场景**：你手头有一份含敏感信息的文件，想让 Codex 帮你自动脱敏，再生成新文件。

**完整 prompt**：

```
请你读取我授权文件夹里的所有文件，做以下处理：

1. 把所有客户的姓名、手机号、身份证号、邮箱、家庭住址全部脱敏
   - 姓名 → 客户 A、客户 B、客户 C（按出现顺序）
   - 手机号 → 中间四位打码（138****5678）
   - 身份证号 → 只保留前 6 位 + 后 4 位
   - 邮箱 → 替换成 user001@example.com 这种格式
   - 地址 → 精确到省级

2. 把所有金额字段处理成区间
   - 1 万以下 → 「小额」
   - 1-10 万 → 「中额」
   - 10 万以上 → 「大额」

3. 输出一个 Excel 文件叫「脱敏后数据.xlsx」，原文件不要动

处理完后告诉我：脱敏了多少条记录，哪些字段你无法识别需要我手动处理。
```

**预期输出**：一个新的 Excel 文件 + 一份脱敏摘要。

**调优提示**：
- 如果有新的敏感字段没识别 → 在 prompt 里补充「请额外处理 xxx 字段」
- 如果脱敏规则不符合公司规范 → 改成你们公司合规部门给的规则
- 如果数据量太大（>10 万行）→ 分批处理，每次 1 万行

## 📜 合规提醒（不需要记，心里有数就行）

| 法规 | 适用场景 | 你要做什么 |
|------|---------|----------|
| 《个人信息保护法》（中国） | 涉及中国公民信息 | 不跨境传输原始 PII |
| GDPR（欧盟） | 涉及欧盟用户 | 用户有「被遗忘权」，别存原始数据 |
| PCI DSS | 涉及银行卡 | 永远不要存 CVV，连脱敏都不行 |
| 《数据安全法》 | 重要数据出境 | 100 万人以上 PII 出境要申报 |

> 💡 **不要被吓到**：运营日常工作只要做到「不喂原始 PII」「重要决策人工复核」两条，基本不会出事。

## ⚠️ 常见坑

- **坑 1**：截图给 Codex 看，里面带客户信息 → 解决：截图前先打码
- **坑 2**：让 Codex 读一个 .sql 备份文件，里面有几万条用户数据 → 解决：先导出脱敏版
- **坑 3**：同事发来的「脱敏数据」其实没脱敏 → 解决：自己再检查一遍，别相信别人的脱敏
- **坑 4**：用 Codex 处理完敏感数据后，聊天记录里还能搜到原文 → 解决：任务结束后在 Codex 客户端里删掉任务
